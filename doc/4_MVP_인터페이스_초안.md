# MVP 인터페이스 설계 초안

> 기준 문서: [MVP 명세](1_MVP_명세.md)
>
> 상태: 검토용 제안 · 2026-09-17
>
> 모바일 중심의 화면 구성을 가정한 초안이다. 화면 배치와 표현 방식은 확정된 결정이 아니며, 기존 MVP의 기능과 동작 규칙을 따른다.

## 1. 구성 방향

채팅방을 중심으로 **AI 도움 → 합의 → 실천**으로 이어지는 인터페이스를 구성한다. 주요 화면 3개와 필요할 때 열리는 패널 3개로 나누어, 대화 도중 화면 이동을 줄인다.

| 구분 | 인터페이스 | 주요 내용 |
| --- | --- | --- |
| 화면 | 시작·초대 | 표시 이름, 방 만들기, 코드 입장, 링크 공유, 상대 입장 대기 |
| 화면 | 대국방 | 실시간 채팅, 메시지 작성, AI·협상 진입, 진행 상태 |
| 패널 | 고스트 코치 | 초안 분석, 감정 추정, 추천 문장 선택, 최종 전송 |
| 패널 | 형세 파악 | 대화 상태, 과열도, 사실과 추정, 다음 행동 |
| 패널 | 무승부 협상 | 조건·기한 작성, 수락, 조건 수정 후 재제안 |
| 화면 | 미션 보드 | 개인·공동 미션, 완료 요청, 상대 확인 |

## 2. 시작·초대 화면

### 기본 구성

- 표시 이름 입력
- `대국방 만들기` 버튼
- 6자리 초대 코드 입력과 `입장하기` 버튼

### 방 생성 후

- 초대 코드와 초대 링크 복사 버튼을 표시한다.
- 상대가 들어오기 전에는 `상대 입장 대기 중` 상태를 표시한다.
- 상대가 들어오면 `상대가 입장했습니다`와 `대국방 들어가기` 버튼을 표시한다.

### 초대받은 사용자

- 초대 링크로 접속하면 코드 재입력 없이 표시 이름을 입력해 입장하도록 제안한다.
- 이미 두 명이 입장한 방에는 추가 입장을 허용하지 않는다.
- 사용자당 진행 중인 대국은 한 개만 지원한다.

## 3. 대국방

일반 메신저처럼 메시지를 읽고 작성하기 쉬운 구성을 사용한다. 대국의 분위기는 기능 이름과 상태 표현에 담는다.

```text
┌─────────────────────────────┐
│ 나 · 상대          미션 보기 │
├─────────────────────────────┤
│ 무승부 제안 도착   [내용 보기]│ ← 진행 중일 때
├─────────────────────────────┤
│ 상대: 왜 연락을 안 했어?     │
│                             │
│       나: 많이 서운했겠네.   │
│                             │
├─────────────────────────────┤
│ [형세 파악]   [무승부 제안]  │
│ 메시지를 입력하세요… [확인] │
└─────────────────────────────┘
```

### 주요 요소

- 상단: 참여자 이름, 상대 입장 상태, 미션 보드 진입
- 상태 영역: 진행 중인 무승부 제안 고정 표시, 미션 요약
- 본문: 시간순으로 표시되는 실시간 메시지
- 하단: `형세 파악`, `무승부 제안`, 메시지 작성창, `확인`

### 필수 전송 흐름

```text
초안 작성 → 확인 → 고스트 코치 → 원문 또는 추천 메시지 선택 → 전송
```

`확인`은 항상 고스트 코치를 연다. 코치 결과를 거치지 않고 바로 전송하는 경로는 제공하지 않는다. 메시지와 협상 상태는 두 사용자의 화면에 일관되게 반영되어야 한다.

## 4. 고스트 코치 패널

메시지 작성 직후 화면 아래에서 올라오는 패널로 제안한다. 채팅 맥락을 유지하면서 문장을 검토하도록 한다.

### 표시 순서

1. 내가 쓴 원문
2. 이 수의 위험
3. 숨은 감정 — `AI의 추정` 표시
4. 선택 입력: `내가 진짜 원하는 것`
5. 추천 문장 2~3개 — 선택 가능한 카드
6. `원문 전송`과 `선택한 추천 메시지 전송`

### 표현 예시

- 이 수의 위험: “상대가 비난으로 받아들일 수 있어요.”
- 숨은 감정 · AI의 추정: “기다리는 동안 서운했던 것 같아요.”
- 추천 문장: “연락이 없어서 서운했어. 다음에는 늦어지면 한마디 해줄 수 있을까?”

### 상태와 동작

- 분석 중에는 로딩 상태를 표시한다.
- 감정·의도 해석에는 모두 `AI의 추정`을 붙인다.
- 추천 문장은 관찰, 감정, 요청을 포함한다.
- 폭력·협박·통제·자해 위험 표현이 감지되면 일반 추천을 멈추고 안전 안내를 먼저 표시한다.
- 패널을 닫으면 전송하지 않고 작성 중인 초안을 유지하는 동작을 제안한다.

## 5. 형세 파악 패널

누가 옳은지 평가하기보다, 현재 대화 상태를 이해하고 다음 행동을 고르게 한다.

### 주요 요소

- 현재 형세: `난타전`, `교착`, `회복 가능` 등
- 대화 지속 가능성
- 감정 과열도
- 확인된 사실
- 추정된 의도 — `AI의 추정` 표시
- 짧은 해설
- `대화로 돌아가기`와 `무승부 제안` 버튼

### 표현 제안

- 과열도는 수치 기준이 정해져 있지 않으므로 `낮음·보통·높음`처럼 표현한다.
- 사실과 AI의 추정을 별도 영역으로 구분한다.
- 누가 잘못했는지 점수나 승패로 판정하지 않는다.

## 6. 무승부 협상 패널

같은 제안의 조건과 기한을 두 사람이 확인하고 합의하도록 한다. 사용자 역할과 협상 상태에 따라 행동 버튼을 다르게 표시한다.

| 상황 | 표시 내용과 행동 |
| --- | --- |
| 제안 작성 | 조건 추가·수정, 기한 `오늘/내일`, `제안 보내기` |
| 상대 응답 대기 | 보낸 조건·기한, `상대 응답 기다리는 중` |
| 제안 받음 | 받은 조건·기한, `수락`, `조건 수정해서 제안`, `계속 대국` |
| 합의 완료 | 최종 합의 조건, `미션 보기` |

### 동작 규칙

- 조건은 0개 이상 작성할 수 있다.
- 카운터오퍼에서는 기존 조건을 유지하거나 추가·수정해 다시 제안한다.
- 양쪽이 같은 조건에 합의하기 전에는 미션을 생성하지 않는다.
- `계속 대국`을 선택하면 해당 제안을 종료하고 대화로 돌아간다.
- 조건에는 수행자가 명확히 보여야 한다. 예를 들어 “내가 밥 사기”를 확인 화면에서는 “상원님이 밥 사기”처럼 표시하도록 제안한다.

## 7. 미션 보드

`내 미션`, `상대 미션`, `공동 퀘스트`로 구분해 수행 책임과 다음 행동을 명확히 한다.

### 미션 카드

- 할 일
- 수행자 또는 참여자
- 기한: 오늘 또는 내일
- 진행 상태와 상대 확인 상태
- 현재 사용자에게 가능한 행동

### 유형별 동작

| 유형 | 완료 흐름 |
| --- | --- |
| 내 개인 미션 | `완료 요청` → 상대 확인 대기 → 상대 확인 후 완료 |
| 상대 개인 미션 | 상대의 완료 요청 확인 → `확인 완료` 또는 `다시 요청` |
| 공동 퀘스트 | 두 사람의 완료 여부를 각각 표시 → 양쪽 모두 완료 처리하면 완료 |

`다시 요청`된 개인 미션은 진행 중 상태로 돌아간다. 명세에 포함된 `미션 포기`도 제공한다. 수행자가 완료를 요청한 상태와 상대가 확인한 최종 완료 상태는 시각적으로 구분한다.

기본 완료 방식은 텍스트 처리와 상대 확인이다. 사진 인증은 선택 데모 기능이며 필수 흐름에 넣지 않는다.

## 8. 전체 사용자 흐름

```text
표시 이름 입력
→ 방 생성 및 초대 / 링크·코드로 입장
→ 두 사용자 연결
→ 대국방에서 초안 작성
→ 고스트 코치 확인 및 메시지 전송
→ 형세 파악
→ 무승부 제안
→ 상대의 수락 또는 카운터오퍼
→ 같은 조건에 합의
→ 개인 미션·공동 퀘스트 생성
→ 수행 완료 및 상대 확인
```

형세 파악은 필요할 때 요청할 수 있으며, 무승부 제안은 대국방에서도 바로 시작할 수 있다.

## 9. 구체화 우선순위와 검토 사항

### 우선순위 제안

1. **대국방과 고스트 코치:** 모든 메시지가 거치는 핵심 경험을 먼저 구체화한다.
2. **무승부 협상과 미션 보드:** 제안·합의·완료 상태와 사용자별 행동을 구체화한다.
3. **시작·초대와 형세 파악:** 연결 경험과 분석 결과 표현을 구체화한다.

### 구현 전 확인할 사항

- 고스트 코치 초안·분석 결과의 상대방 공개 범위
- AI 분석 실패 및 안전 안내 이후에 허용할 전송 동작
- 조건 없이 합의했을 때의 완료 화면과 미션 생성 여부
- 카운터오퍼에서 조건을 수정해도 원래 수행 책임을 명확히 유지하는 방법
- 미션 포기 권한과 공동 퀘스트 포기 시 상태 처리

위 항목은 명세만으로 세부 동작이 확정되지 않아 별도 확인이 필요하다. 이 초안에서는 기능 범위나 정책을 새로 확정하지 않는다.
