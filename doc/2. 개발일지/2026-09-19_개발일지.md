# 2026-09-19 개발 일지

## 한눈에 보기

- 오늘의 목표: 하네스가 문서 맥락과 데이터 의존성에 따라 일관된 순서로 판단하도록 보완한다.
- 핵심 결과: 문서 판단 근거를 DAG로 관리하고, 하네스의 목표를 지속 가능한 시스템 개발로 정했다. 확정 결정의 주 기준 위치를 날짜별 의사결정 로그로 이관하고 협업 기록 폴더를 우선순위 순서로 재정렬했다.

## 진행 순서와 결정

### 1. 문서 판단 의존성의 DAG 운영을 도입

- 선택: 제품 방향과 의사결정 로그부터 MVP 명세, 시스템·데이터 정의, 인터페이스 설계, 구현, 검증으로 이어지는 판단 근거를 DAG로 관리한다. 검증보고서와 보완계획은 기존 기준을 역방향으로 변경하지 않는 관찰·제안 노드로 둔다.
- 이유: 하위 산출물이나 제안 보완계획이 상위 정책의 근거가 되어 판단 순서가 순환하거나, 확정되지 않은 제안이 구현 기준으로 적용되는 일을 막기 위해서다.
- 반영 결과: 작업 시작 전 확인 순서, 문서별 확정 권한, 기준 변경 절차, 충돌 해결 우선순위와 완료 점검 항목을 `AGENTS.md`에 추가했다.
- 근거: [의사결정 로그](../1.%20의사결정%20로그/README.md) · [프로젝트 작업 규칙](../../AGENTS.md) · [관련 커밋 `b91991b`](https://github.com/tail1887/hackathon-2person-project/commit/b91991b)

### 2. 지속 가능한 시스템 개발을 위한 구조화 원칙을 도입

- 선택: 하네스의 목표를 단순 문서 정리가 아닌 지속 가능한 시스템 개발로 정하고, 지속 참조 정보의 구조화, 주 기준 문서, 상태·권한 구분, 일회성 기록의 승격 기준을 운영 원칙으로 둔다.
- 이유: 다음 작업자가 필요한 기준·입력·변경 영향을 빠르게 찾고, 새 데이터와 산출물을 같은 구조로 추가하되, 일회성 기록까지 과도하게 관리하는 비용은 피하기 위해서다.
- 반영 결과: `AGENTS.md` 1.1에 목적과 구조화 원칙을 추가했다. 관련 문서는 주 기준 문서의 정책을 복제하지 않고 자기 범위의 영향과 구현 기준을 구체화하도록 정했다.
- 근거: [의사결정 로그](../1.%20의사결정%20로그/README.md) · [프로젝트 작업 규칙 1.1](../../AGENTS.md#11-하네스의-목적과-구조화-원칙) · [관련 커밋 `4f1b922`](https://github.com/tail1887/hackathon-2person-project/commit/4f1b922)

### 3. 날짜별 의사결정 로그와 협업 기록 순서를 재구성

- 선택: 확정 의사결정의 주 기준을 `doc/1. 의사결정 로그/`로 이관하고, 협업 기록 폴더를 스크럼 안건·의사결정 로그·개발일지·검증보고서·보완 계획·인터페이스 설계 순서로 정렬한다.
- 이유: 기획서의 제품 방향과 변경 이력을 분리해 결정을 날짜별로 찾기 쉽게 하고, 기록의 실제 판단 우선순위를 폴더 구조에도 반영하기 위해서다.
- 반영 결과: 기존 결정 47개를 날짜별 로그 4개로 이관하고, 기획서에는 새 주 기준 위치의 안내만 남겼다. 기존 `1`~`4` 협업 폴더를 각각 `2`~`5`로 이동하고 모든 로컬 Markdown 링크를 새 경로로 갱신했다.
- 근거: [2026-09-19 의사결정 로그](../1.%20의사결정%20로그/2026-09-19_의사결정_로그.md) · [의사결정 로그 README](../1.%20의사결정%20로그/README.md) · [관련 커밋 `8448516`](https://github.com/tail1887/hackathon-2person-project/commit/8448516)

## 작업·검증 기록

- 변경한 문서: `AGENTS.md`, 기획서, 날짜별 의사결정 로그, 기존 협업 기록의 폴더 경로와 링크, 이 개발 일지
- 확인한 결과: DAG의 기준 흐름에는 역방향 의존성을 두지 않고, 탐색용 문서 링크와 판단 근거 관계를 구분했다. 의사결정 로그 반영과 Markdown 공백 검사를 완료했다.
- 하네스 탐색성 보완: 모든 제목 계층을 `0`~`5.3` 번호 체계로 정리하고, 상단 빠른 탐색 목차와 작업별 진입 안내를 추가했다. 정책 내용은 바꾸지 않았다.
- 구조화 원칙 보완: 주 기준 문서와 관련 문서의 역할을 구분해, 기존 규칙의 관련 문서 반영 의무와 충돌하지 않음을 확인했다.
- 협업 기록 재구성: 날짜별 의사결정 로그 4개에 기존 결정 47개가 모두 이관됐고, 모든 로컬 Markdown 링크의 대상 존재를 확인했다.
