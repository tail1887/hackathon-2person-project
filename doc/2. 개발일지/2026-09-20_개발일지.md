## 작업·검증 기록

- 변경한 문서: 의사결정 로그, M1.3 페이즈 4 검증, M1.3 검증보고서 v3·v4.
- 확인한 결과: Vercel Git 설정에서 저장소 연결과 Root Directory `web`을 확인했고, 공개 URL에 비로그인 HTTP 요청을 보내 `200` 응답을 확인했다.
- 로컬 Supabase: 첫 이미지 내려받기와 이전 실패 시도의 임시 컨테이너 정리를 거쳐 `supabase start`와 `supabase status`가 성공했다. REST·Functions 헬스 엔드포인트는 각각 `200`이고, `npm run lint`·`npm run build`도 다시 통과했다.
- M2 계획: 대국방 기반 구축을 인증·입장, 방·초대·권한, 실시간 대국방, 통합 검증의 구현 순서로 분리한 페이즈 문서를 만들었다. AI 심판을 우회하는 전송 UI는 M2에 포함하지 않고 M3의 필수 전송 규칙과 결합한다.
- 인증 범위 보정: 기존 MVP의 카카오·구글 로그인 포함 정책에 맞춰 M2 페이즈 2에 이메일·비밀번호와 두 OAuth 공급자의 대시보드·콜백 설정 및 실제 로그인 검증을 포함했다.
- M2 실행 프롬프트: 각 페이즈에 선행 기준, 허용 구현 경계, 검증·문서·커밋 조건을 담은 재사용 가능한 개발 프롬프트를 추가했다.
- M2 페이즈 1: MVP·시스템·인터페이스 계약과 구현 계획을 대조했다. OAuth 범위의 오래된 이관 표기를 수정하고, A·B·제3 사용자 시나리오를 페이즈·계약·검증에 연결한 추적표를 확정했다.
- 내 프로필 설정: M2 페이즈 2에 메인에서 여는 표시 이름 설정·저장·취소·로그아웃 경로를 추가했다. 기존 방의 표시 이름 스냅샷은 수정하지 않는다.
- 내 프로필 반영 범위 점검: 기획서의 MVP 동작·화면 구성과 마일스톤 계획의 M2 항목까지 대조해 갱신했다. M1.2 목업은 인증을 제외한 완료된 검증 도구이고, `web/`은 M2 페이즈 2 구현 전 뼈대이므로 변경 대상에서 제외했다.
- M2 문서 일관성 검사: 최신 인증·프로필·기본 아바타 정책과 M2 경계는 일치함을 확인했다. 마일스톤 현황(P01)·M2 완료 기준(P02)·검증보고서 색인 및 과거 목업 링크(P03)을 보완했고, 재검증에서 문서 항목 충족을 확인했다. [M2 문서 일관성 재검증보고서 v2](../3.%20검증보고서/M2_대국방_기반_구축/v2_문서_일관성_재검증보고서.md)
- OAuth 공급자 사전 설정: 새 Supabase 프로젝트에 Kakao·Google 공급자를 연결하고, Google OAuth 동의 화면·웹 클라이언트와 Supabase 콜백 URL을 설정했다. Supabase 공급자 목록에서 두 공급자가 모두 `Enabled`임을 확인했으며, Client Secret은 대시보드에만 보관하고 저장소에는 기록하지 않았다.
