- M2 방·초대 브라우저 호출 보완: CORS 사전 요청이 운영 함수의 JWT 게이트에서 `401`이 되는 것을 확인했다. 두 함수에 `POST, OPTIONS` CORS 헤더와 함수 내부 Supabase Auth 토큰 검증을 추가하고, 요청 전 JWT 검사 해제 설정을 코드·운영 배포에 함께 반영했다. 운영 `OPTIONS` 요청은 두 함수 모두 `200`, 인증 없는 실제 `POST`는 모두 `401`임을 확인했다. A/B/제3 사용자 권한 시나리오는 여전히 실사용자 검증으로 남긴다.
- M2 대국방 확정 시점 변경: 초대 발급 단계의 `waiting` 방이 수락 전 이탈에도 남아 새 대국을 막는 문제를 확인했다. 초대 대기만 먼저 만들고, 수락 시 방·두 멤버·초대 사용을 원자 생성하도록 스키마·명령·화면·기준 문서를 변경했다. 운영 마이그레이션과 두 함수 재배포를 마쳤으며, 테스트용 대국방·멤버·메시지·초대 대기는 0건으로 정리했고 로그인 계정·프로필은 각 3건으로 보존했다.
- M2 페이즈 3 실사용자 검증: 프로젝트 소유자가 A 초대 발급, B 링크·코드 수락, 동일 초대 재사용 거절, 제3 사용자의 방 URL·초대 코드 접근 차단을 확인했다. 방·초대·권한과 명령 페이즈를 완료로 전환하고 다음 작업을 페이즈 4 실시간 대국방으로 변경했다.
- M2 페이즈 4 대국 재입장: 메인 화면이 로그인 사용자의 `room_public` 활성 대국을 조회해 표시하고 대국방으로 돌아가게 보완했다. 새로고침·재접속 시에는 즉시 반영되며, 상대 수락을 화면에 자동 반영하는 실시간 구독은 페이즈 4의 다음 항목으로 남긴다.
- M2 페이즈 4 목업 구조 이관: 실시간 기반 확인용 멤버 카드 화면을 목업의 방 요약·메시지 타임라인·하단 도구/초안 구조로 교체했다. M3 전송 규칙을 지키기 위해 형세 파악·AI 문철·무승부·초안 확인은 비활성으로만 보여 주며 직접 전송은 제공하지 않는다.
- M2 페이즈 4 완료: 프로젝트 소유자가 실시간 대국방과 목업 구조 이관 결과를 확인해 완료로 승인했다. 검증보고서 v10에 코드 검증과 사용자 확인 근거를 남기고, 다음 작업을 M2 페이즈 5 통합 검증으로 전환했다.
- M3 페이즈 1: 시간 제약으로 M2 페이즈 5의 자동·통합 검증을 프로젝트 소유자 수동 테스트로 대체하고 M3를 시작했다. `gpt-5.6` Responses API Structured Outputs를 기본 AI 기준으로 정하고, 작성자 전용 초안·분석·private revision 스키마와 공개 투영을 추가했다. 실제 AI 호출과 메시지 전송 UI는 다음 페이즈에 남긴다.
- M3 페이즈 2 구현: `ai-judge` Edge Function이 작성자 초안을 저장하고 OpenAI Structured Outputs 심판 결과를 개인 분석으로 저장하게 했다. `message-send`는 최신 분석·초안 해시·전송 선택을 SQL RPC에서 검증한 뒤에만 공용 메시지를 확정한다. 대국방에는 AI 심판 시트와 원문·추천문 전송 선택을 연결했으며, 원격 배포·A/B 검증은 남아 있다.
