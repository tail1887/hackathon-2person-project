## 한눈에 보기

- 오늘의 목표: M3 AI 기능이 요구하는 운영 Supabase 스키마·함수를 CLI로 배포하고 기본 호출 경계를 확인한다.
- 핵심 결과: M3 마이그레이션과 7개 Edge Function을 운영 프로젝트에 배포했다. 실제 A/B 사용자 시나리오는 남겼다.

## 진행 순서와 결정

### 1. M3 운영 Supabase 배포

- 선택: 기존 M2 원격 스키마의 마이그레이션 이력을 먼저 연결한 뒤 M3 범위인 `006`~`014`만 CLI로 적용하고, M3 함수 7개를 같은 프로젝트에 배포했다.
- 이유: 이미 운영 중인 M2 테이블과 명령을 재생성하지 않고, M3의 데이터·Realtime·AI 계약만 안전하게 추가하기 위해서다.
- 반영 결과: 원격 이력은 `001`~`014`까지 로컬과 일치한다. AI 심판·메시지 확정·형세·문철 신청/수락/재시도/취소 함수가 모두 활성화됐다.
- 근거: [M3 전체 계획](../8.%20AI%20대화%20경험%20구축/README.md) · [원격 배포 검증보고서 v4](../3.%20검증보고서/M3_AI_대화_경험_구축/v4_원격_배포_검증보고서.md) · [관련 커밋](https://github.com/tail1887/hackathon-2person-project/commits/main/)

### 2. 대국방 목업 UI 직접 이관

- 선택: 일반화된 대국방 카드 UI를 유지하지 않고, `mockup/`의 대국방 카드·문철 배너·좌우 말풍선·하단 도구 및 초안 영역·AI 바텀 시트를 React 화면으로 직접 이관한다.

### 3. 운영 AI 호출 실패 진단

- 선택: 외부 API 오류 본문이나 키를 노출하지 않고, 실패 HTTP 상태 또는 구조화 결과 오류만 비공개 분석 기록에 남기도록 AI 함수의 오류 처리를 보완한다.
- 이유: 실제 운영 호출 6건이 모두 실패했지만 기존 함수는 모든 원인을 같은 문구로 처리해 키·모델·한도 문제를 판별할 수 없었다.
- 반영 결과: AI 심판·개인 형세·문철 수락·재시도 함수에 안전한 `failure_code` 기록을 추가하고 원격에 재배포했다. AI 심판 재호출의 `openai_http_400`을 근거로 최상위 `oneOf` Structured Outputs 스키마를 객체 스키마로 교체했다. 이어서 OpenAI 응답이 도착했지만 REST 원본의 `output[].content[].text` 대신 SDK 편의 필드만 읽던 오류를 확인해, 네 함수 모두 원본 구조화 응답을 읽도록 수정·재배포했다.
- 근거: [M3 AI 호출 실패 진단보고서 v5](../3.%20검증보고서/M3_AI_대화_경험_구축/v5_AI_호출_실패_진단보고서.md)

### 4. AI 추천문 전달 문장 계약 보완

- 선택: AI 심판의 `recommendations[].text`를 사용자에게 주는 행동 조언이 아니라, 사용자가 상대에게 바로 전송할 수 있는 1인칭 한국어 답장으로 한정한다.
- 이유: 실제 결과가 `~해보세요` 형태의 훈수로 생성돼 추천문을 바로 전송할 수 없었다.
- 반영 결과: OpenAI 시스템 지시와 구조화 출력 설명에 답장 형식을 명시하고, 대표적인 조언형 문구가 반환되면 전송 가능한 추천문으로 저장하지 않도록 서버 검증을 추가해 원격에 배포했다.
- 근거: [기획서의 필수 전송 규칙](../0_커플들이_집착하는_AI_심판이_되었다_기획서.md#62-ai-심판을-거친-필수-전송) · 사용자 실제 결과 확인

### 5. AI 추천문 화자·의도 보존 보완

- 선택: AI 심판은 입력 초안을 항상 현재 사용자가 상대에게 보내려는 말로 해석하고, 추천문에서 화자·수신자·핵심 발화 목적(질문·답변·요청·진술·경계)을 유지하도록 한다.
- 이유: `말 다했냐`를 사용자의 질문이 아닌 상대가 사용자에게 한 질문처럼 뒤집어, 사용자 의도와 반대되는 답장을 추천한 사례가 확인됐다.
- 반영 결과: Structured Outputs에 `speaker_intent`·`speech_act` 계약을 추가하고, 질문은 상대에게 묻는 질문으로 남기는 등 발화 방향을 뒤집지 않도록 AI 지시와 서버 검증을 보강해 원격에 배포했다.
- 근거: [MVP 명세의 필수 AI 심판 전송](../1_MVP_명세.md#32-대국방) · 사용자 실제 결과 확인

### 6. 위험 입력 restricted 결과 보장

- 선택: 자해·폭력·협박·통제 표현이 포함된 초안은 외부 모델 응답과 무관하게 AI 심판 서버가 즉시 `restricted` 결과로 확정한다.
- 이유: `나 자살할거야` 입력에서 모델의 안전 거절 형식이 구조화 결과로 변환되지 않아, 전송 불가 화면 대신 일반 AI 실패 안내가 표시됐다.
- 반영 결과: 위험 초안은 분석 기록을 `ready/restricted`로 저장하고, 추천문·원문 전송 없이 초안 수정만 가능한 기존 제한 화면을 반환하도록 Edge Function을 원격 배포했다.
- 근거: 사용자 수동 테스트 화면 · [위험 입력 실패 보완 검증보고서 v7](../3.%20검증보고서/M3_AI_대화_경험_구축/v7_위험_입력_실패_보완_검증보고서.md)

### 7. M3 완료와 M4 착수

- 선택: 위험 입력 restricted 화면과 A/B/제3 계정 공개 경계의 수동 확인을 근거로 M3를 완료 처리하고, M4를 데이터·명령 → 협상 화면 → 미션 화면 → 두 계정 검증 순서로 시작한다.
- 이유: M3의 완료 기준인 필수 AI 심판, 위험 입력 차단, 개인/공용 AI 공개 경계가 실제 사용 흐름에서 확인됐다. M4는 이미 확정된 협상·미션 상태 규칙을 구현하는 단계이므로 새 제품 정책 결정 없이 서버 전이 기반부터 쌓는다.
- 반영 결과: M3 완료 검증보고서와 마일스톤 상태를 갱신하고, M4 폴더에 4개 페이즈의 범위·불변식·검증 기준을 생성했다.
- 근거: [M3 완료 수동 검증보고서 v8](../3.%20검증보고서/M3_AI_대화_경험_구축/v8_M3_완료_수동_검증보고서.md) · [M4 계획](../9.%20무승부%20협상·미션%20완주/README.md)

## 작업·검증 기록

- `supabase migration list --linked`로 `20260920000100`~`20260920001400`의 로컬·원격 일치를 확인했다.
- M3 Edge Function 7개가 `ACTIVE`인지 확인했고, 각 운영 URL의 CORS `OPTIONS` 응답이 `200`인지 확인했다.
- `OPENAI_API_KEY` 비밀값은 이름만 확인했으며 값은 저장소·문서·로그에 기록하지 않았다.
- `npm run lint`, `npx tsc --noEmit`, `npm run build`를 통과했다. 로컬 브라우저는 공개 Supabase 연결값이 없어 인증된 대국방 데이터까지는 재현하지 못했다.
- 운영 데이터에서 normal 심판 2건, stale 분석 1건, 개인 형세 3건, 준비 완료 문철 1건·취소 문철 1건을 확인했다. restricted 결과와 상대·제3 계정 비공개 화면은 아직 증거가 부족해 M3 완료 판정을 보류했다. [수동 테스트 현황 검증보고서 v6](../3.%20검증보고서/M3_AI_대화_경험_구축/v6_수동_테스트_현황_검증보고서.md)에 남겼다.
- 위험 입력이 일반 실패로 표시된 사례를 재현했고, 서버 측 `restricted` 확정 분기로 보완·원격 배포했다. 화면 재확인은 남아 있다. [위험 입력 실패 보완 검증보고서 v7](../3.%20검증보고서/M3_AI_대화_경험_구축/v7_위험_입력_실패_보완_검증보고서.md)에 기록했다.
- M3의 위험 입력 restricted 화면과 A/B/제3 계정 공개 경계 수동 확인을 받아 [완료 검증보고서 v8](../3.%20검증보고서/M3_AI_대화_경험_구축/v8_M3_완료_수동_검증보고서.md)으로 완료 처리했다.
- M4 페이즈 1의 협상·제안·조건·카운터오퍼·미션·미션 이력 테이블과 멤버 전용 공개 뷰를 추가했다. `supabase migration up --local`, `supabase db lint --local`, 원격 `db push`, `migration list --linked`, `db lint --linked`를 통과했다.
- M4 협상 명령을 추가했다. 제안자는 활성 제안을 수정·재발송할 수 없고 카운터오퍼 뒤에만 새 버전을 낼 수 있으며, 응답자의 수락은 유효한 조건 선택·선택 조건별 미션 생성·방 종료를 원자적으로 처리한다. `20260921001600`을 로컬·원격에 적용하고 lint를 통과했다.
- M4 미션 명령을 추가했다. 개인 미션은 수행자의 완료 요청 뒤 상대만 확인·재수행 요청을 할 수 있고, 공동 퀘스트는 두 참여자의 현재 버전 체크인이 모두 있어야 완료된다. 수정 제안은 상대 수락 때만 새 미션 버전을 적용하며 기존 완료 체크인은 새 버전에 넘기지 않는다. `20260921001700`을 원격에 적용하고 lint를 통과했다.
- M4 협상 UI를 목업 기준으로 이관했다. 대국방의 협상 배너·협상 기록, 제안 작성·잠금·카운터오퍼·응답자 수락/계속 대국 화면을 실제 상태 전이 RPC 및 room broadcast와 연결했다. `20260921001800`으로 내부 ID 없이 현재 멤버를 식별하는 공개 플래그를 추가했고 원격 DB lint·웹 lint·타입 검사·프로덕션 빌드를 통과했다.
