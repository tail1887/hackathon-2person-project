# 인터페이스 설계

> 상태: M1.2 진행 중 · 2026-09-18

이 폴더는 [MVP 명세](../1_MVP_명세.md)와 [시스템·데이터 정의](../3_시스템_데이터_정의.md)를 바탕으로, M1.2 인터페이스 설계 작업을 페이즈별로 나누어 관리하는 기준이다. M1.2의 완료 기준과 전체 작업 순서는 [마일스톤 계획](../2_마일스톤_계획.md#M12-인터페이스-설계)을 따른다.

## 문서 구성

- 각 페이즈는 독립된 Markdown 문서 한 개로 관리한다.
- 파일명은 작업 순서와 페이즈명을 사용한다. 예: `01_화면_흐름과_와이어프레임.md`.
- 각 페이즈에서 다루는 화면은 하나의 흐름으로 묶어 기록한다. 다음 페이즈에서 앞선 설계의 범위나 결정을 바꿔야 하면 해당 문서를 함께 갱신한다.

## 페이즈별 설계 양식

각 문서는 아래 항목 중 해당 페이즈 범위에 필요한 내용을 포함한다.

1. 목적과 진입 조건
2. 화면 구조와 주요 요소
3. 사용자 행동과 상태 전이
4. 로딩·빈 상태·오류·진행 상태
5. 요청·응답·실시간 이벤트 계약
6. 권한·비공개 정보 처리
7. MVP 명세와 시스템 정의의 근거 링크

## 페이즈별 진행 계획

### 01. 화면 흐름과 와이어프레임

- **목표:** 두 사용자가 대국방 생성부터 미션 상대 확인까지 완주하는 화면 이동과 각 화면의 기본 구조를 하나의 흐름으로 만든다.
- **진행 순서:**
  1. MVP 명세의 고정 데모 시나리오와 시스템 문서의 권한·상태 전이를 대조한다.
  2. 방 생성자와 초대받은 사용자의 로그인·초대 입장 경로를 설계한다.
  3. 대국방, AI 심판 시트, AI 문철, 무승부 협상, 미션 보드의 진입·이탈·이동을 연결한다.
  4. 각 화면의 주요 영역, 버튼, 표시 정보만 담은 텍스트 와이어프레임을 만든다.
  5. 필수 전송 규칙과 양측 수락 전 미션 미생성 규칙이 흐름에 빠지지 않았는지 대조한다.
- **산출물:** `01_화면_흐름과_와이어프레임.md`
- **완료 기준:** A와 B가 각각 거치는 화면, 주요 행동, 다음 화면을 한 문서에서 따라갈 수 있다.

### 02. 화면 상태 설계

- **목표:** 페이즈 1의 모든 주요 화면에서 정상·로딩·빈 상태·오류·진행·재연결 상태를 사용자가 이해하고 다음 행동을 선택할 수 있게 정의한다.
- **진행 순서:**
  1. 화면별로 서버 응답 대기, 데이터 없음, 권한 거절, 요청 실패, 상대 변경 수신 상태를 나열한다.
  2. AI 심판 대기·실패·안전 안내, 초대 만료·방 정원 초과, 협상 응답 대기, 미션 확인·수정 대기 상태를 설계한다.
  3. 비공개 초안 동기화와 `draft_revision_conflict`에서 최신 초안 확인·내 입력 보존·재시도 흐름을 설계한다.
  4. 재연결 뒤 공용·비공개 데이터를 복구하는 동안의 표시와 조작 제한을 정리한다.
  5. 상태마다 사용자에게 보여 줄 안내, 가능한 행동, 재시도 또는 이탈 조건을 표로 기록한다.
- **산출물:** `02_화면_상태_설계.md`
- **완료 기준:** MVP의 모든 핵심 행동에 성공 외 상태와 복구 행동이 정의되고, 페이즈 3에서 오류·이벤트 계약으로 옮길 수 있다.

### 03. 요청·응답·실시간 이벤트 계약

- **목표:** 페이즈 1·2의 화면이 서버와 주고받아야 하는 데이터와 오류·동기화 경계를 구현 가능한 수준으로 정리한다.
- **진행 순서:**
  1. 화면 행동을 명령 요청, 상태 조회, 실시간 이벤트로 분류한다.
  2. 각 항목의 요청 필드, 성공 응답, 권한·상태 충돌 오류, 화면 반영 대상을 정의한다.
  3. 공용 `room_revision`과 작성자 전용 `private_revision`의 조회·재연결·스냅샷 폴백 흐름을 연결한다.
  4. 초안 저장·버림·AI 심판 요청의 `expected_revision`과 `draft_revision_conflict` 응답을 구체화한다.
  5. 내부 사용자 ID, 비공개 초안, AI 심판 결과가 상대 또는 공용 이벤트에 포함되지 않는지 검토한다.
- **산출물:** `03_요청_응답_실시간_이벤트_계약.md`
- **완료 기준:** 프런트엔드와 서버가 각 화면의 데이터 책임, 오류 처리, 공용·비공개 동기화 방식을 같은 계약으로 구현할 수 있다.

## 페이즈별 작업 프롬프트

아래 프롬프트는 해당 페이즈 문서를 새로 작성할 때 사용한다. 기준 문서에 없는 정책을 임의로 확정하지 말고, 판단이 필요한 항목은 `결정 필요`로 분리한다.

### 01. 화면 흐름과 와이어프레임

```text
이 저장소의 M1.2 인터페이스 설계 페이즈 1을 진행해줘.

먼저 다음 기준 문서를 읽고 서로 충돌하는 내용이 있는지 확인해줘.
- doc/1_MVP_명세.md
- doc/3_시스템_데이터_정의.md
- doc/2_마일스톤_계획.md
- doc/4. 인터페이스 설계/README.md

목표는 로그인한 A와 B가 대국방 생성·초대 입장부터 AI 심판, AI 문철, 무승부 협상, 미션 상대 확인까지 완주하는 화면 흐름과 텍스트 와이어프레임을 정의하는 것이다.

doc/4. 인터페이스 설계/01_화면_흐름과_와이어프레임.md를 만들고 다음을 기록해줘.
1. 설계 범위와 근거 문서
2. A와 B의 전체 화면 흐름
3. 화면별 진입 조건, 주요 사용자 행동, 다음 화면 또는 종료 조건
4. 시작·로그인·초대 입장, 대국방, AI 심판 시트, AI 문철, 무승부 협상, 미션 보드의 텍스트 와이어프레임
5. 필수 AI 심판 전송 규칙, 최신 분석만 전송 가능, 양측 수락 전 미션 미생성 규칙이 반영된 지점
6. 기준 문서에 없는 결정 필요 항목

화면의 로딩·오류·재연결 세부 상태와 API 필드·이벤트 형식은 페이즈 2·3 범위이므로 확정하지 말고 필요한 연결 지점만 표시해줘.
문서 링크와 Markdown 형식을 확인하고, 제품 정책이나 디자인 원칙을 새로 확정했다면 의사결정 로그 반영 필요 여부를 함께 알려줘.
```

### 02. 화면 상태 설계

```text
이 저장소의 M1.2 인터페이스 설계 페이즈 2를 진행해줘.

먼저 다음 기준 문서를 읽어줘.
- doc/4. 인터페이스 설계/01_화면_흐름과_와이어프레임.md
- doc/1_MVP_명세.md
- doc/3_시스템_데이터_정의.md
- doc/4. 인터페이스 설계/README.md

목표는 페이즈 1에서 정의한 주요 화면마다 정상 상태 외에 로딩·빈 상태·오류·진행·재연결 상태와 사용자의 복구 행동을 정의하는 것이다.

doc/4. 인터페이스 설계/02_화면_상태_설계.md를 만들고 다음을 기록해줘.
1. 설계 범위와 페이즈 1 의존성
2. 화면별 상태표: 상태 진입 조건, 사용자에게 보이는 정보, 가능한 행동, 다음 상태
3. 초대 만료·방 정원 초과·권한 거절·상대 입장 대기 상태
4. AI 심판 pending·failed·safety_guidance, 분석 stale, 추천 또는 원문 전송 불가 상태
5. 협상 응답 대기·카운터오퍼·합의 처리와 미션 완료 요청·상대 확인·수정 대기 상태
6. room_revision 재연결 복구, private_revision 비공개 기록 복구, draft_revision_conflict에서 내 입력 보존과 선택 흐름
7. 기준 문서에 없는 결정 필요 항목

API 요청·응답 필드나 이벤트 payload는 페이즈 3에서 확정한다. 이번 문서에는 사용자가 경험하는 상태와 화면 행동만 정의해줘.
문서 링크와 Markdown 형식을 확인하고, 제품 정책이나 디자인 원칙을 새로 확정했다면 의사결정 로그 반영 필요 여부를 함께 알려줘.
```

### 03. 요청·응답·실시간 이벤트 계약

```text
이 저장소의 M1.2 인터페이스 설계 페이즈 3을 진행해줘.

먼저 다음 기준 문서를 읽어줘.
- doc/4. 인터페이스 설계/01_화면_흐름과_와이어프레임.md
- doc/4. 인터페이스 설계/02_화면_상태_설계.md
- doc/1_MVP_명세.md
- doc/3_시스템_데이터_정의.md
- doc/4. 인터페이스 설계/README.md

목표는 페이즈 1·2의 화면과 상태를 구현할 수 있도록 명령 요청, 상태 조회, 오류 응답, 공용·비공개 실시간 이벤트의 입출력 경계를 정의하는 것이다.

doc/4. 인터페이스 설계/03_요청_응답_실시간_이벤트_계약.md를 만들고 다음을 기록해줘.
1. 계약 범위와 용어 정의
2. 화면 행동별 명령 요청: 인증·권한 전제, 요청 필드, 성공 결과, 오류 코드 또는 오류 상태, 화면 반영
3. 초기 조회와 재연결 조회: room_revision, private_revision, 변경 목록, 스냅샷 폴백
4. 공용 이벤트와 작성자 전용 이벤트: 수신자, payload, 순번, 화면 반영 규칙
5. 초안 저장·버림·AI 심판 요청의 expected_revision과 draft_revision_conflict 응답
6. 메시지 전송에서 최신 AI 분석, 원문 해시, 추천 문구를 검증하는 계약
7. 비공개 초안·AI 심판 결과·내부 사용자 ID의 비노출 검토와 결정 필요 항목

시스템 문서에 없는 저장소·프레임워크·프로토콜은 선택하지 말고, 기술 선택이 필요한 항목은 M1.3 이관 항목으로 표시해줘.
문서 링크와 Markdown 형식을 확인하고, 제품 정책이나 디자인 원칙을 새로 확정했다면 의사결정 로그 반영 필요 여부를 함께 알려줘.
```

페이즈 작업에서 화면 구조·디자인 원칙을 확정할 때는 관련 의사결정 로그와 기준 문서를 함께 갱신한다.
