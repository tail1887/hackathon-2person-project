### 1.1 공통 화면 원칙

- 로딩 중에는 중복 전송을 막되, 이미 확정된 메시지·협상·미션 기록은 계속 읽을 수 있게 한다.
- 실패 안내는 실패한 행동과 복구 행동을 함께 보여 준다. 권한·비공개 데이터의 존재나 본문을 상대에게 암시하지 않는다.
- 공용 변경은 두 멤버에게 같은 최종 상태를 보이고, 작성자 전용 초안·AI 심판·개인 형세 파악은 작성자 화면에서만 상태를 바꾼다.
- 결과가 준비되어도 AI 문철 결과 창을 자동으로 열지 않는다. 사용자가 직접 연다.
- 종료된 대국은 읽기 전용이며, 생성된 미션은 대국 종료와 독립적으로 계속 처리한다.

## 2. 진입·메인·초대 상태

| 화면 | 상태와 진입 조건 | 사용자에게 보이는 정보 | 가능한 행동과 다음 상태 |
| --- | --- | --- | --- |
| 로그인·회원가입 | 인증 전 앱 또는 미로그인 초대 링크 진입 | 로그인·회원가입만 표시한다. 초대 링크의 유효성·방 정보는 표시하지 않는다. | 인증 성공 뒤 메인 또는 저장한 초대 경로로 복귀한다. 실패 시 인증 오류를 해당 입력 아래에 표시하고 재시도한다. |
| 메인 | 초기 조회 중 | 미션·대국 영역에 골격 또는 `불러오는 중`을 표시한다. | 중복 대국 시작은 막는다. 조회 성공 시 아래 상태로 전환하고, 실패 시 메인 조회 재시도만 제공한다. |
| 메인 | 미션 없음·진행 중 대국 없음 | `진행 중인 미션이 없어요`, `진행 중인 대국이 없어요`를 각각 표시한다. 지난 대국이 있으면 읽기 전용 목록은 계속 보인다. | `대국 시작하기`, 지난 대국 열기. |
| 메인 | 진행 중 대국 있음 | 미션을 먼저, 진행 중 대국 하나를 최상단 강조 카드로, 지난 대국을 그 아래에 표시한다. | 대국 재개, 미션 상세, 지난 대국 읽기 전용 열기. 새 대국 시작은 제공하지 않는다. |
| 대국 만들기 | 생성 요청 중 | `대국방을 준비하는 중`과 초대 정보가 아직 확정되지 않았음을 표시한다. | 만들기 중복 요청을 막는다. 성공 시 초대 대기, 실패 시 재시도·메인으로 돌아가기. 이미 진행 중인 대국이 확인되면 해당 대국 재개로 이동한다. |
| 초대 수락 | 인증 뒤 링크 재방문 또는 코드 제출 확인 중 | `초대를 확인하는 중`만 표시한다. | 중복 수락을 막는다. 성공 시 대국방, 실패 시 원인별 안내 상태로 전환한다. |
| 초대 수락 | 만료·이미 사용됨·유효하지 않은 링크/코드 | 방 안의 대화·멤버·협상 정보는 보이지 않는다. `이 초대는 사용할 수 없어요`와 새 링크 또는 코드 요청 안내를 표시한다. | 로그인 상태를 유지한 채 메인으로 돌아가기. |
| 초대 수락 | 방 정원 초과 또는 수락자에게 이미 진행 중 대국 존재 | `지금은 이 대국방에 입장할 수 없어요`와 이유를 구분해 표시한다. | 진행 중인 내 대국 재개 또는 메인으로 돌아가기. |
| 초대 대기 | 방 생성 뒤 상대 입장 전 | 초대 링크·코드, `상대가 입장하면 시작돼요`를 표시한다. | 링크·코드 복사, 메인으로 돌아가기. 상대 입장 확정 시 대국방으로 전환한다. |
| 초대 대기 | 상대 입장 실시간 알림을 놓침 또는 연결 복구 중 | 마지막으로 확정된 대기 화면을 유지하고 `연결을 복구하는 중`을 표시한다. | 복구 조회 성공 시 대국방 또는 계속 대기 상태를 반영한다. |

## 3. 대국방·비공개 초안·AI 상태

### 3.1 대국방 공통 상태

| 상태와 진입 조건 | 사용자에게 보이는 정보 | 가능한 행동과 다음 상태 |
| --- | --- | --- |
| 대국방 초기 조회 | 메시지·멤버·현재 협상·문철 도구 영역의 로딩 표시 | 작성창과 상태 변경 버튼은 조회 완료 전 막는다. 성공 시 진행 중 또는 종료됨 상태, 실패 시 재시도·메인으로 돌아가기. |
| 진행 중·동기화됨 | 메시지 목록, 내 초안, 현재 협상 요약, 형세 파악·AI 문철·무승부 제안·미션 진입점을 표시한다. | 초안 작성, AI 기능, 협상, 미션으로 이동한다. |
| 상대의 공용 변경 반영 중 | 새 메시지·상대 입장·협상·미션 변경을 확정 순서로 반영한다. | 이미 시작한 내 입력은 덮어쓰지 않는다. 최신 공용 상태 반영 뒤 진행 중 상태로 돌아간다. |
| 방 종료됨 | `대국이 종료되었어요`와 지난 대국 읽기 전용 상태를 표시한다. | 메시지 전송, 새 협상, 새 AI 문철 신청은 제공하지 않는다. 양쪽이 확인한 AI 문철 기록과 협상 기록을 읽고, 미션 보드·메인으로 이동한다. |
| 권한 없음·멤버 아님 | 방 내용·상대 정보·존재 여부를 더 표시하지 않는다. | 메인으로 돌아가기. |

### 3.2 초안과 AI 심판

| 상태와 진입 조건 | 사용자에게 보이는 정보 | 가능한 행동과 다음 상태 |
| --- | --- | --- |
| 빈 초안 | 작성창과 비활성 `확인`을 표시한다. | 입력 후 초안 작성 상태. |
| 초안 저장 중 | 작성창에 `저장 중`을 표시한다. | 입력은 유지한다. 저장 완료 시 작성 상태, 실패 시 저장 재시도 상태. |
| 초안 저장 실패 | 내 입력을 지우지 않고 `저장하지 못했어요`를 표시한다. | 재시도, 내 기기에 남은 입력 수정, 버리기. 상대에게 표시하지 않는다. |
| `draft_revision_conflict` | 최신 저장 초안과 내 미저장 입력이 다름을 작성자에게만 알린다. | `내 입력 유지 후 다시 저장`, `최신 초안으로 바꾸기`, `두 내용을 비교해 직접 수정`을 제공한다. 선택 전 작성창을 자동 교체하지 않는다. |
| AI 심판 요청 중 | 작성한 최신 초안의 미리보기와 `AI 심판이 확인 중이에요`를 시트에 표시한다. | 원문·추천 전송, 무승부 조건 생성, 같은 초안의 재확인은 막는다. 초안 수정으로 돌아가면 결과 대기 상태를 버리고 새 확인이 필요하다. |
| AI 심판 `normal` | 위험·AI의 추정·추천문과 원문/추천 전송 선택을 작성자에게만 표시한다. | 원문 전송 또는 추천 전송 후 대국방으로, 초안 수정 후 새 확인. |
| AI 심판 `restricted` | 전송할 수 없다는 안내와 `초안 수정`만 표시한다. 추천·원문 전송·협상 조건 생성은 표시하지 않는다. | 초안 수정 후 새 확인. |
| AI 심판 실패 | 초안은 보존하고 `AI 심판을 준비하지 못했어요`를 작성자에게만 표시한다. | 같은 초안 재확인 또는 수정. 분석 성공 전 전송은 제공하지 않는다. |
| 분석 stale | AI 요청 뒤 초안이 바뀌었거나 최신 분석이 아닌 결과가 도착한 경우다. | 이전 결과를 전송 선택에 사용하지 않는다는 안내와 최신 초안 `확인`을 표시한다. |
| 전송 완료 | 확정 메시지를 양쪽 메시지 목록에 표시한다. 작성자만 본문을 눌러 원문·추천문·실제 선택을 읽기 전용으로 펼칠 수 있다. | 계속 대화. 상대에게는 상세 진입점 자체를 표시하지 않는다. |

### 3.3 개인 형세 파악과 AI 문철

| 기능 | 상태와 진입 조건 | 사용자에게 보이는 정보 | 가능한 행동과 다음 상태 |
| --- | --- | --- | --- |
| 개인 형세 파악 | 요청·분석 중 | 요청자에게만 `형세를 정리하는 중`을 표시한다. | 동일 요청은 막고, 완료·실패 상태로 전환한다. 상대 화면은 변하지 않는다. |
| 개인 형세 파악 | 준비 완료 | 형세·쟁점·AI의 추정·다음 판단을 요청자에게만 표시한다. | 대국방으로 돌아가기, 새 분석 요청. |
| 개인 형세 파악 | 실패 | 요청자에게만 실패와 재시도를 표시한다. | 재시도 또는 대국방으로. |
| AI 문철 | 신청 전 | `AI 문철 신청하기`를 표시한다. | 신청 시 신청자 대기와 상대 수락 안내로 나뉜다. |
| AI 문철 | 신청자 대기 | 신청자에게 `상대의 수락을 기다리고 있어요`를 표시한다. | 대국방의 다른 읽기·대화 행동은 가능하다. 상대 수락 뒤 공용 로딩으로 전환한다. |
| AI 문철 | 상대 수락 대기 | 상대에게 신청자와 함께 정리한다는 안내·수락 행동을 표시한다. | 수락 시 공용 로딩. 수락하지 않은 채 대국방을 계속 볼 수 있다. |
| AI 문철 | 공용 로딩 | 두 멤버에게 같은 `AI 문철을 준비하는 중`을 표시한다. | 현재 문철 열기·새 신청은 비활성화한다. 메시지·미션 등 다른 허용된 행동은 유지한다. |
| AI 문철 | 현재 결과 준비 | 대국방에는 `AI 문철 확인하기`와 준비 완료 안내를 표시한다. 결과 창은 자동으로 열지 않는다. | 사용자가 직접 현재 결과를 열면 본인 알림만 확인 처리한다. |
| AI 문철 | 현재 결과 열람 | 대화 요약, 서로 다른 지점, `AI의 추정`, 다음 수 제안, 무승부 제안·새 신청 진입을 표시한다. | 대국방, 무승부 협상, 새 신청. |
| AI 문철 | 이전 기록 있음 | 현재 결과 창 안에만 `이전 AI 문철 기록 보기`를 표시한다. 현재 결과는 목록에서 제외한다. | 이전 결과를 읽기 전용으로 열 수 있다. 첫 문철만 있으면 이 버튼을 숨긴다. |
| AI 문철 | 새 신청 진행 중 | 현재 결과·이전 기록은 읽을 수 있지만 새 신청과 현재 문철 열기는 막는다. | 공용 로딩·현재 결과 준비로 전환한다. |
| AI 문철 | 분석 실패 | 현재 문철을 새 결과로 바꾸지 않는다. 실패 안내의 공개 범위와 재시도 주체는 [결정 필요](#6-결정-필요)로 남긴다. | 결정 뒤 재시도 또는 신청 전 상태로 복귀한다. |

## 4. 무승부 협상과 미션 상태

### 4.1 무승부 협상

| 상태와 진입 조건 | 사용자에게 보이는 정보 | 가능한 행동과 다음 상태 |
| --- | --- | --- |
| 협상 없음 | 대국방과 현재 AI 문철에 `무승부 제안하기`를 표시한다. | 제안자 작성 화면으로 이동. |
| 제안자 작성·수정 가능 | 조건, 선택 방식, 책임 주체를 편집하는 폼을 표시한다. 카운터오퍼 뒤에는 원 제안과 요청 메시지를 함께 표시한다. | 제안 전송, 계속 대국. 전송 성공 시 제안자 잠금 상태. |
| 활성 제안·제안자 잠금 | 제안자에게 보낸 조건과 `상대 응답 대기`를 읽기 전용으로 표시한다. | 수정·재발송은 제공하지 않는다. 상대 수락·카운터오퍼·계속 대국 또는 공용 변경 수신을 기다린다. |
| 활성 제안·상대 응답 가능 | 상대에게 조건, 선택 방식, 책임 주체를 읽기 전용으로 표시한다. | 선택 후 수락, 카운터오퍼, 계속 대국. `none`은 조건 선택 없이 수락한다. |
| 카운터오퍼 전송 처리 중 | 보낸 버튼을 잠그고 중복 전송을 막는다. | 성공 시 양쪽 `counter_requested`, 실패 시 입력을 보존하고 재시도. |
| `counter_requested`·제안자 | 원 제안 아래의 카운터오퍼 메시지와 수정 폼 진입을 표시한다. | 카운터오퍼를 보며 새 버전 작성·전송. |
| `counter_requested`·응답자 | `제안자 수정 대기`와 기존 제안을 읽기 전용으로 표시한다. | 조건 선택·수락·추가 카운터오퍼·계속 대국을 제공하지 않는다. 새 버전 도착을 기다린다. |
| 수락·합의 처리 중 | 양쪽에 `합의를 기록하는 중`을 표시하고 협상 행동을 막는다. | 성공 시 방 종료·메인 갱신. 실패 시 서버의 최신 협상 상태를 다시 조회해 유효한 상태를 표시한다. |
| 합의 완료 | 대국이 종료되어 지난 대국으로 이동했음을 표시한다. 조건이 있으면 선택된 미션이, `none`이면 미션 없음이 메인에 반영된다. | 메인, 생성 미션, 읽기 전용 협상 기록. |
| 계속 대국 완료 | 협상 종료 안내와 대국방을 표시한다. | 새 협상 시작 또는 대화 계속. |
| 현재/최근 기록 | 현재 또는 가장 최근 협상 1건의 제안 버전·카운터오퍼·수락·종료·합의 결과를 시간순 읽기 전용으로 표시한다. | 닫고 원 화면으로. 새 협상 시작 뒤 이전 협상은 이 기록 대상이 아니다. |

### 4.2 미션 보드·상세

| 미션 유형 | 상태와 진입 조건 | 사용자에게 보이는 정보 | 가능한 행동과 다음 상태 |
| --- | --- | --- | --- |
| 공통 | 초기 조회·갱신 중 | 기존 카드가 있으면 유지하고 해당 카드에 갱신 표시, 처음이면 로딩 표시 | 완료·수정·포기 등 중복 변경을 막는다. 성공 후 최신 카드 상태로, 실패 시 재시도. |
| 공통 | 없음 | `진행 중인 미션이 없어요`를 표시한다. | 메인 또는 지난 대국으로 이동. |
| 개인 | `in_progress`·수행자 | 수행자와 확인자, 진행 중 상태를 표시한다. | 수행자만 완료 요청·포기·수정 제안을 할 수 있다. 완료 요청 시 상대 확인 대기. |
| 개인 | `completion_requested`·확인자 | `상대 확인 대기`와 수행자가 요청한 완료 근거를 표시한다. | 확인으로 완료, 다시 요청으로 `revision_requested`. 수행자는 대기 안내만 본다. |
| 개인 | `revision_requested`·수행자 | `재수행 요청을 받았어요`를 표시한다. | 수행자만 재수행 시작으로 `in_progress`, 포기. |
| 개인 | `completed` 또는 `abandoned` | 최종 상태와 이력을 읽기 전용으로 표시한다. | 새 완료 요청·수정 제안은 제공하지 않는다. |
| 공동 | `in_progress`·`0/2` | 두 참여자와 `0/2 완료`를 표시한다. | 각 참여자는 본인 완료 체크인 또는 포기. |
| 공동 | `in_progress`·`1/2` | 완료한 사람을 추정하지 않는 범위에서 내 체크인 여부와 `상대 완료 대기`를 표시한다. | 아직 체크인하지 않은 참여자만 완료 체크인 또는 포기. 이미 체크인한 참여자는 중복 체크인할 수 없다. |
| 공동 | `completed`·`2/2` | `두 사람 완료`를 표시한다. | 읽기 전용. |
| 공동 | `abandoned` | 한 참여자의 포기로 완료될 수 없음을 포함해 종료 상태를 표시한다. | 읽기 전용. |
| 수정 제안 | `open` | 현재 미션은 그대로 유지되고, 제안 내용·제안자·상대 수락 대기를 표시한다. | 상대만 수락·거절, 제안자만 취소. |
| 수정 제안 | 수락 처리 중 | `수정 내용을 적용하는 중`을 표시한다. | 성공 시 새 미션 버전·`in_progress`; 이전 완료 요청·공동 체크인은 무효화된 상태를 반영한다. |
| 수정 제안 | `stale` | 미션이 완료·포기됐거나 버전이 달라 적용할 수 없음을 표시한다. | 최신 미션 확인. |

## 5. 재연결과 상태 복구

| 복구 범위 | 상태와 화면 표시 | 복구 뒤 처리 |
| --- | --- | --- |
| 공용 `room_revision` | 연결이 끊기면 상단에 `연결을 복구하는 중`을 표시하고, 마지막으로 확정된 공용 메시지·협상·미션 카드는 읽기 전용으로 유지한다. 새 공용 변경 행동은 잠근다. | 마지막 적용 순번 이후 공용 변경을 조회한다. 순서가 이어지면 차례대로 반영하고, 누락되었거나 보관 범위를 넘으면 최신 공용 스냅샷으로 교체한다. |
| 작성자 전용 `private_revision` | 내 초안·AI 심판·개인 형세 파악 영역에만 `내 기록을 복구하는 중`을 표시한다. 상대 화면과 공용 대국방은 이 상태를 보지 않는다. | 마지막 적용 순번 이후 내 변경을 조회한다. 누락 시 최신 초안·현재 AI 심판 상태·삭제 표식만 스냅샷으로 받으며 삭제된 본문·AI 결과는 되살리지 않는다. |
| 동시 복구 | 공용 복구가 끝나도 비공개 복구가 끝나지 않았다면 메시지·미션 읽기는 가능하지만 작성창의 전송 확인은 막는다. | 두 복구가 모두 끝나면 최신 상태에서 행동을 다시 활성화한다. |
| 복구 중 새 입력 | 미저장 초안을 유지하고 자동 교체하지 않는다. | 최신 초안을 확인한 뒤 충돌이면 `draft_revision_conflict` 선택 흐름으로 보낸다. |
| 복구 실패 | 마지막 확정 상태에 `복구하지 못했어요`와 재시도를 표시한다. | 재시도 또는 메인으로 이동. 재시도 전에는 확정 상태를 바꾸는 행동을 제공하지 않는다. |

## 6. 결정 필요

다음은 기준 문서에 없는 정책 선택이다. 이 문서는 확정하지 않으며, 사용자 또는 팀의 결정 뒤 의사결정 로그부터 갱신한다.

1. **공용 AI 문철 실패의 안내 범위와 재시도 주체**: 상대 수락 뒤 공용 분석 생성에 실패하면 실패 안내를 두 멤버 모두에게 보일지, 신청자만 재시도할지 또는 어느 멤버나 새 신청할지를 정해야 한다. 개인 AI 심판·형세 파악 실패는 요청자에게만 보인다는 기준과 구분이 필요하다.
2. **재연결 장기 실패 시 대기 시간과 이탈 문구**: 재시도 횟수, 자동 재시도 간격, 고객 지원 또는 새로고침 안내 여부는 기술·운영 선택과 함께 M1.3에서 정한다.
3. **초대 사용 불가 사유의 노출 수준**: 만료·이미 사용·유효하지 않음은 구분할 수 있지만, 외부 사용자에게 세부 사유를 모두 보여 줄지 공통 문구로 묶을지는 보안·제품 판단이 필요하다.
