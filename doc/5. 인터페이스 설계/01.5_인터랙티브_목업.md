## 2. 목업 위치 및 실행 방법

- **목업 파일**: [`mockup/index.html`](../../mockup/index.html)
- **목업 코드 구조**: 상태·화면 임시 상태는 [`mock-state.js`](../../mockup/js/mock-state.js), 순수 도메인 생성 규칙은 [`mock-domain.js`](../../mockup/js/mock-domain.js), 화면 렌더링은 [`mock-render.js`](../../mockup/js/mock-render.js), 사용자 행동·전이 어댑터는 [`mock-actions.js`](../../mockup/js/mock-actions.js)에 둔다. `index.html`은 화면 마크업과 스크립트 로더만 담당한다.
- **실행 방법**:
  - 별도 서버 설치 없이 브라우저로 직접 열기:
    ```bash
    open mockup/index.html
    ```
  - 또는 로컬 웹 서버 실행:
    ```bash
    python3 -m http.server 8000
    # 브라우저 접속: http://localhost:8000/mockup/
    ```

### 2.1 목업 컨트롤러 기능

- **사용자 시점 전환**: 상단 툴바의 `민준 (A)` / `서연 (B)` 버튼을 클릭하여 방 생성자 및 초대받은 사용자의 시점을 실시간 전환하여 검증
- **시나리오 셀렉트**: 핵심 시나리오(메인, AI 심판, 무승부 협상 조건/0개/카운터오퍼, 미션 보드)로 즉시 이동
- **리셋 버튼**: 목데이터 및 상태를 초기값으로 복원

## 4. 발견한 화면 문제 및 페이즈 2·3 이관 사항 (`결정 필요`)

1. **상대방 시점의 무승부 제안 수락 상태 동기화**
   - 현 목업에서는 A가 제안을 작성하고 B 시점으로 전환해 수락하는 방식을 검증함. 실제 서비스에서는 SSE/WebSocket 실시간 이벤트를 통해 B의 제안 수락 즉시 A의 대국방이 `closed` 상태로 변경되어야 함 (페이즈 3 계약 이관).
2. **카운터오퍼 수신 후 제안 수정 폼**
   - [D2026-09-19-14](../1.%20의사결정%20로그/2026-09-19_의사결정_로그.md)·[D2026-09-19-15](../1.%20의사결정%20로그/2026-09-19_의사결정_로그.md)·[D2026-09-19-16](../1.%20의사결정%20로그/2026-09-19_의사결정_로그.md)에 따라 목업에 반영했다. 카운터오퍼는 일반 대화에 중복하지 않고 원 제안 아래에만 표시한다. 제안자는 상대 응답 전 제안을 읽기 전용으로만 보고, 카운터오퍼가 도착한 뒤에만 수정할 수 있다. 카운터오퍼를 보낸 상대도 수정 대기 상태로 잠기며, 새 제안이 오기 전에는 기존 제안을 수락하거나 다시 카운터오퍼를 보낼 수 없다. `무승부 협상 기록 보기`에는 현재 또는 가장 최근 협상 1건의 흐름만 남는다. 실제 실시간 동기화와 저장 계약은 페이즈 2·3에서 정의한다.
3. **미션 완료 요청 거절/재수행 시 표시**
   - B가 완료 확인 시 `[다시 요청]`을 눌렀을 때, 수행자 A의 화면에서 `재수행 대기` 라벨과 `[재수행 시작]` 버튼이 올바르게 전환됨을 확인함.
4. **AI 문철의 생성 오해 방지**
   - 기존 목업은 `AI 문철`을 누르면 즉시 공용 결과를 열어, 메시지마다 AI 답변을 자동 생성하는 기능처럼 보일 수 있었다.
   - [D2026-09-19-12](../1.%20의사결정%20로그/2026-09-19_의사결정_로그.md)에 따라 신청자 대기, 상대 수락 안내, 두 사람 공용 로딩, 완료 뒤 함께 확인으로 바꿨다. 수락 전에는 분석을 생성하지 않는다.
5. **현재 문철·새 신청·기록의 구분**
   - [D2026-09-19-13](../1.%20의사결정%20로그/2026-09-19_의사결정_로그.md)에 따라 준비된 문철은 대국방의 `AI 문철 확인하기`로 열고, 새 문철은 결과 하단에서만 신청하도록 했다. 이전 문철은 `문철 기록`의 읽기 전용 카드에서 확인한다. 새 문철 로딩 동안 문철 버튼은 비활성화되고, 완료 토스트 뒤 사용자가 직접 결과를 연다.
   - [D2026-09-19-17](../1.%20의사결정%20로그/2026-09-19_의사결정_로그.md)에 따라 `함께 확인하기`로 현재 문철을 연 사용자의 준비 완료 알림은 그 사용자에게만 숨긴다. 이후에는 `AI 문철 확인하기`로 재진입하며, 상대의 확인 여부는 표시하지 않는다.
   - [D2026-09-19-18](../1.%20의사결정%20로그/2026-09-19_의사결정_로그.md)에 따라 종료된 대국에는 두 멤버가 모두 확인한 공용 문철만 `AI 문철 기록`으로 표시한다. 개인 형세 파악과 미확인 문철은 이 기록에 넣지 않는다.
6. **전송 메시지의 개인 상세**
   - [D2026-09-19-19](../1.%20의사결정%20로그/2026-09-19_의사결정_로그.md)에 따라 AI 심판을 거쳐 보낸 내 메시지에만 클릭 가능한 상세를 두었다. 같은 카드에서 원문·AI 추천문·실제 전송 선택을 읽기 전용으로 열며, 상대 시점과 초기·시스템·협상 메시지에는 상세 진입점을 만들지 않는다.
7. **목업 코드 책임 분리**
   - [D2026-09-19-20](../1.%20의사결정%20로그/2026-09-19_의사결정_로그.md)에 따라 HTML 인라인 스크립트를 제거하고 상태·도메인·렌더링·행동 어댑터를 별도 파일로 분리했다. 직접 HTML을 여는 실행 방식은 유지한다.
8. **AI 문철 기록 진입점 통합**
   - [D2026-09-19-21](../1.%20의사결정%20로그/2026-09-19_의사결정_로그.md)에 따라 대국방의 별도 `문철 기록` 버튼을 제거하고, 현재 `AI 문철 확인하기` 결과 창 안에서 이전 기록을 열도록 했다.
