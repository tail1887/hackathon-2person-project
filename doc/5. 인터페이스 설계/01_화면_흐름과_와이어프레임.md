# M1.2 페이즈 1 — 화면 흐름과 와이어프레임

> 상태: 확정 · 2026-09-19

## 1. 설계 범위와 근거

이 문서는 로그인한 두 사용자 A(방 생성자)와 B(초대받은 사용자)가 대국방 생성부터 미션 상대 확인까지 이동하는 화면 흐름과 기본 화면 구조를 정의한다. 로딩·오류·재연결의 세부 상태는 페이즈 2, 요청·응답·실시간 이벤트의 필드는 페이즈 3에서 정의한다.

- [MVP 명세](../1_MVP_명세.md): 고정 데모 시나리오, 화면별 목적·입력·출력·동작 규칙
- [시스템·데이터 정의](../3_시스템_데이터_정의.md): 권한, 상태 전이, 비공개 기록, 실시간 동기화 규칙
- [마일스톤 계획](../2_마일스톤_계획.md#M12-인터페이스-설계): M1.2 완료 기준

화면에는 내부 `user_id`를 표시하지 않는다. 방 안의 상대 식별은 `room_display_name`, 필요할 때만 `member_label`과 방 전용 `public_member_key`에 연결된 화면 정보로 처리한다.

## 2. 전체 화면 흐름

### 2.1 대국방 연결

```text
A
앱 진입 → 로그인/회원가입 → 시작 화면 → 대국방 만들기
     → 초대 대기 화면(링크·6자리 코드 공유) ─────────────┐
                                                   │ B 입장 확정
                                                   ▼
                                             대국방

B — 초대 링크
초대 링크 → 로그인/회원가입 → 원래 링크 복귀·초대 수락 → 대국방

B — 초대 코드
로그인/회원가입 → 시작 화면 → 초대 코드 입력·초대 수락 → 대국방

로그인 사용자
로그인/회원가입 → 메인 → 미션 상세 또는 진행 중·지난 대국 선택
                       └→ 내 프로필 → 표시 이름 저장 또는 취소 → 메인
```

- 미로그인 B에게는 링크의 유효성도 알려 주지 않고 로그인·회원가입 화면만 제공한다. 초대 코드 입력은 로그인 뒤 시작 화면에서만 제공한다.
- B의 인증 뒤 링크를 다시 열거나 코드를 입력하면 서버가 초대 유효성·빈자리·B의 진행 중인 다른 방 여부를 확인한다. 통과하면 B를 멤버로 추가하고 초대를 사용 처리하며 방을 활성화한 뒤 대국방으로 이동한다.
- A는 B가 들어오기 전에는 초대 대기 화면에 머문다. 상대 입장이 확정되면 A와 B 모두 같은 대국방으로 이동하거나, 이미 대국방을 보고 있던 A의 화면에 상대 입장 상태가 반영된다.
- 메인에는 미션과 대국 목록을 함께 표시한다. 진행 중인 대국은 한 개만 허용하며 최상단에, 종료된 대국은 그 아래에 읽기 전용으로 표시한다.

### 2.2 메시지와 AI 심판

```text
대국방
  → 초안 작성 → 확인 → AI 심판 시트
                         ├→ 원문 전송 → 대국방의 확정 메시지
                         ├→ 추천 메시지 전송 → 대국방의 확정 메시지
                         ├→ 초안 수정 → 대국방의 작성창 → 확인
                         └→ restricted 결과 → 초안 수정 → 확인

대국방 → 형세 파악 → 개인 형세 파악 → 대국방
대국방 → AI 문철 신청하기 → 상대 수락 대기
  → 상대 수락 → 두 사람의 AI 문철 로딩 → 준비 완료 알림
  → AI 문철 확인하기 → 함께 보는 AI 문철 → 대국방 또는 무승부 협상
                               ├→ 새 AI 문철 신청하기 → 상대 수락 대기
                               └→ 현재 문철 창의 `이전 AI 문철 기록 보기` → 이전 문철 읽기 전용
```

- `확인`은 항상 AI 심판 시트를 연다. 대국방에서 바로 전송하는 경로는 두지 않는다.
- 초안을 수정하면 이전 분석은 사용할 수 없으므로, 작성창으로 돌아가 새 초안에 다시 `확인`해야 한다.
- AI 심판을 거쳐 전송한 메시지는 작성자만 전송 본문을 눌러 같은 카드에서 `내 원문`, `AI 추천문`, `실제 전송: 원문/AI 추천문`을 읽기 전용으로 펼친다. 상대·시스템 메시지·무승부 협상 메시지에는 이 동작을 제공하지 않는다.
- AI 심판이 `restricted`이면 전송·추천·재작성·협상 조건 생성 경로는 제공하지 않는다. 사용자는 시트에서 초안을 수정한 뒤 재확인한다.
- 개인 형세 파악은 요청자만 보는 비공개 결과다. 상대에게는 요청 여부·결과·알림을 보내지 않는다.
- AI 문철 신청은 두 멤버에게 보인다. 신청자는 자신의 동의를 표시하고, 상대가 수락하기 전에는 분석을 생성하지 않는다. 상대 수락 뒤 두 사람에게 같은 로딩 상태를 보이고, 준비 완료 알림 뒤 사용자가 직접 현재 문철을 연다.
- 최신 문철이 있으면 대국방의 문철 도구는 `AI 문철 확인하기`가 된다. 새 문철 신청과 이전 기록 보기는 현재 결과 창 하단에서 제공하며, 이전 결과는 읽기 전용으로 확인한다. 로딩 중에는 문철 확인·신청을 비활성화한다.
- 준비 완료 뒤 `함께 확인하기`를 눌러 현재 문철을 연 사용자의 알림만 즉시 숨긴다. 이후 재확인은 `AI 문철 확인하기`로 통일하고, 상대의 확인 여부는 표시하지 않는다.
- 종료 대국의 읽기 전용 기록에는 `AI 문철 기록` 섹션을 두고, 두 멤버가 모두 확인한 공용 문철만 카드·`문철 보기` 버튼으로 연다. 개인 형세 파악과 수락 전·생성 중·한쪽만 확인한 문철은 표시하지 않는다.
- AI 문철 결과는 대화 요약, 서로 다른 지점, `AI의 추정`인 바람과 걱정, 다음 수를 두 멤버에게 함께 보여 주며, 승패·잘잘못·관계 상태를 표시하지 않는다.

### 2.3 무승부 협상과 미션

```text
대국방 또는 AI 문철 → 무승부 협상 작성(A)
  → 활성 제안(B)
       ├→ 조건 선택·수락 → 합의·대국 종료 → 선택된 조건만 미션 생성 → 메인
       ├→ 카운터오퍼 메시지 → 기존 제안 아래 카운터오퍼 표시 → A의 제안 수정 → 새 활성 제안(B)
       └→ 계속 대국 → 대국방

미션 보드
  개인: 수행자 완료 요청 → 상대 확인 → 완료
                         └→ 다시 요청 → 수행자 재수행 시작 → 진행 중
  공동: 두 참여자의 완료 처리 → 완료
  진행 중/재수행 요청: 수정 제안 → 상대 수락 → 수정된 미션으로 진행 중
```

- 협상 제안자는 조건의 책임 주체를 `나`·`상대`·`함께` 중에서 정한다. 상대는 조건을 직접 편집하지 않고 카운터오퍼 메시지로 변경을 요청한다.
- 제안자는 제안을 보낸 뒤 상대 응답 전까지 보낸 제안을 읽기 전용으로만 보며 수정·재발송할 수 없다. 카운터오퍼가 기존 제안 아래에 도착한 뒤에만 그 메시지를 바탕으로 조건·선택 방식을 수정해 새 버전을 낸다. 카운터오퍼를 보낸 상대는 `제안자 수정 대기` 읽기 전용 상태가 되어 기존 제안의 수락·선택·추가 카운터오퍼를 할 수 없고, 새 버전이 도착한 뒤에만 다시 응답한다. 상대의 유효한 선택과 수락 전에는 미션을 만들지 않는다.
- 카운터오퍼는 일반 대화가 아니라 원 제안 아래의 협상 항목으로만 표시한다. 대국방에는 최신 협상 상태만 요약하고, `무승부 협상 기록 보기`에서 현재 진행 중이거나 가장 최근에 종료된 협상 1건의 제안·카운터오퍼·수락·계속 대국·합의 결과를 읽기 전용으로 확인한다.
- 합의 때 상대가 선택한 조건만 개인 미션 또는 공동 퀘스트가 된다. 개인 미션의 수행자와 확인자는 서로 다르며, 공동 퀘스트는 두 참여자가 각자 완료 처리한다.
- 미션 수정 제안은 기존 미션을 즉시 바꾸지 않는다. 상대가 수락할 때만 새 미션 버전을 적용한다.

## 3. 화면 목록과 이동

| 화면 | 진입 조건 | 주요 행동 | 다음 화면 또는 종료 |
| --- | --- | --- | --- |
| 로그인·회원가입 | 미로그인 앱 첫 진입, 미로그인 초대 링크 | 로그인, 회원가입, 표시 이름 설정 | 시작 화면 또는 원래 초대 링크 복귀 |
| 메인 | 로그인 완료 | 미션 확인, 진행 중·지난 대국 확인, 대국 시작, 내 프로필 열기 | 미션 상세, 대국방, 대국 시작 선택, 내 프로필 |
| 내 프로필 | 로그인한 사용자가 메인에서 진입 | 표시 이름 수정·저장·취소, 로그아웃 | 메인 또는 인증 전 화면 |
| 초대 수락 | 로그인한 사용자가 초대 링크를 열거나 코드를 입력 | 초대 수락 결과 확인 | 대국방 또는 입장 불가 안내 |
| 초대 대기 | A가 대국방을 만든 직후 | 링크·코드 공유, 대국방 열기 | 상대 입장 뒤 대국방 |
| 대국방 | 방이 활성화된 뒤 | 초안 작성·확인, 형세 파악, AI 문철 신청·상대 수락, 무승부 제안, 미션 보드 열기 | AI 심판, 개인 형세 파악, AI 문철 수락 대기·로딩·결과, 무승부 협상, 미션 보드 |
| AI 심판 시트 | 초안의 `확인` | 원문 전송, 추천 전송, 초안 수정 | 대국방 또는 작성창 |
| 개인 형세 파악 | 대국방의 `형세 파악` | 대국방으로 돌아가기 | 대국방 |
| AI 문철 | 대국방의 `AI 문철` | 대국방으로 돌아가기, 무승부 제안 | 대국방 또는 무승부 협상 |
| 무승부 협상 | 대국방 또는 AI 문철 | 제안 작성·수정, 조건 선택·수락, 카운터오퍼 메시지, 계속 대국, 협상 기록 보기 | 대국방, 협상 기록 또는 미션 보드 |
| 미션 보드·상세 | 합의 뒤 또는 대국방의 미션 요약 | 완료 요청·확인·다시 요청·재수행·포기·수정 제안 | 미션 상태 갱신, 대국방 |

## 4. 텍스트 와이어프레임

### 4.1 시작·로그인·초대 입장

```text
┌──────────────────────────────────┐
│ 커플들이 집착하는 AI 심판이 되었다 │
│                                  │
│ [구글로 계속]                      │
│                                  │
│ [로그인] [회원가입]                │
└──────────────────────────────────┘

로그인 뒤 메인
┌──────────────────────────────────┐
│ 미션                              │
│ [상대 확인 대기] 오늘 산책 30분     │
│ [진행 중] 답장이 늦을 때 알려주기   │
│                                  │
│ 대국                              │
│ [진행 중] [상대 이름] [대국 재개]   │
│ [종료됨] [상대 이름] 2026.09.19     │
│                                  │
│ [내 프로필]        [대국 시작하기] │
└──────────────────────────────────┘

내 프로필
┌──────────────────────────────────┐
│ 내 프로필                         │
│ [하] 기본 아바타                   │
│ 표시 이름 [하늘________________]  │
│                                  │
│ [취소]                    [저장]  │
│                                  │
│ [로그아웃]                        │
└──────────────────────────────────┘
```

- 인증 전에는 로그인·회원가입만 제공한다. 미로그인 초대 링크 방문도 같은 인증 화면을 보여 주며, 초대 상태나 방 정보를 표시하지 않는다.
- 메인은 미션을 먼저 보여 주고, 진행 중인 대국을 강조 색·`진행 중` 라벨로 지난 대국보다 먼저 정렬한다. 색만으로 상태를 구분하지 않는다.
- 진행 중인 대국이 없을 때 `대국 시작하기`를 누르면 `대국방 만들기`와 `초대 코드로 입장`을 제공한다. 종료된 대국은 읽기 전용이다.
- `내 프로필`에서는 로그인한 본인의 표시 이름만 수정한다. 표시 이름 이니셜과 사용자별 기본 색상 아바타를 함께 보이며 사진 업로드는 제공하지 않는다. 저장 뒤 새 표시 이름은 이후 새로 만들거나 입장하는 방에만 적용하며, 기존 방의 표시 이름은 바꾸지 않는다.

### 4.2 초대 대기·대국방

```text
초대 대기
┌──────────────────────────────────┐
│ 대국방을 준비했어요                │
│ 초대 링크 [복사]                   │
│ 입장 코드 123456 [복사]            │
│ 상대가 입장하면 대국을 시작합니다   │
│ [대국방 열기]                      │
└──────────────────────────────────┘

대국방
┌──────────────────────────────────┐
│ [상대 이름]  대국 진행 중   [미션] │
│ 진행 중인 무승부 제안 요약          │
├──────────────────────────────────┤
│ 메시지 목록                        │
│  상대 이름  메시지                  │
│  나          메시지                  │
├──────────────────────────────────┤
│ [형세 파악] [AI 문철 신청/확인]      │
│                       [무승부 제안] │
│ 초안 입력                           │
│                         [확인]      │
└──────────────────────────────────┘
```

- `확인`은 활성 초안이 있을 때만 AI 심판 시트로 연결한다.
- 대국방의 메시지에는 전송 본문과 방 안의 발신자 표시만 보인다. AI 심판을 거친 내 전송 메시지만 본문을 눌러 같은 카드 안의 읽기 전용 상세를 열 수 있다.

```text
내 전송 메시지 상세 — 작성자만
┌──────────────────────────────────┐
│ 나  실제로 전송한 메시지 본문       │
│                                  │
│ 내 원문                           │
│ AI 추천문                         │
│ 실제 전송: 원문 / AI 추천문        │
└──────────────────────────────────┘
```

- 상대에게는 상세 진입점·원문·추천문·실제 전송 선택을 표시하지 않는다. 시스템 메시지와 무승부 협상 메시지는 클릭 상세 대상이 아니다.
- 무승부 협상이 열려 있으면 상단 요약을 누르면 현재 제안 화면으로 이동한다.

### 4.3 AI 심판 시트

```text
AI 심판 시트 — normal
┌──────────────────────────────────┐
│ AI 심판                           │
│ 이 수의 위험                      │
│ 숨은 감정: AI의 추정               │
│                                  │
│ 추천 1 [추천 메시지 전송]          │
│ 추천 2 [추천 메시지 전송]          │
│ 추천 3 [추천 메시지 전송]          │
│ [초안 수정]        [원문 전송]     │
└──────────────────────────────────┘

AI 심판 시트 — restricted
┌──────────────────────────────────┐
│ AI 심판                           │
│ 이 문장에는 AI 심판을 제공할 수     │
│ 없습니다. 문장을 수정해 다시       │
│ 확인해 주세요.                     │
│                                  │
│ [초안 수정]                        │
└──────────────────────────────────┘
```

- AI 심판의 `normal` 결과에서만 원문·추천 메시지 전송 버튼을 노출한다.
- AI 심판 시트와 전송 뒤 개인 기록은 요청자에게만 보인다.

### 4.4 개인 형세 파악

```text
개인 형세 파악
┌──────────────────────────────────┐
│ 개인 형세 파악                    │
│ 현재 형세: 교착                    │
│ 내가 확인할 쟁점                   │
│ AI의 추정                          │
│ 다음 판단                          │
│                                  │
│ [대국방으로]                       │
└──────────────────────────────────┘
```

- 개인 형세 파악은 요청자와 같은 계정의 다른 기기에서만 보며, 상대에게는 요청·결과·알림을 보내지 않는다.

### 4.5 AI 문철 신청·수락·함께 확인

```text
신청자 화면
┌──────────────────────────────────┐
│ AI 문철 신청을 보냈어요            │
│ 상대의 수락을 기다리고 있어요.      │
└──────────────────────────────────┘

상대 화면
┌──────────────────────────────────┐
│ 민준님이 AI 문철을 신청했습니다.    │
│ 함께 대화를 정리해 볼까요?          │
│                    [동의하고 시작] │
└──────────────────────────────────┘

상대 수락 뒤 — 두 사람 화면
┌──────────────────────────────────┐
│ AI 문철을 준비하고 있어요            │
│ 두 사람의 대화를 함께 정리하는 중    │
└──────────────────────────────────┘

AI 문철 — 함께 확인
┌──────────────────────────────────┐
│ AI 문철                           │
│ 함께 확인할 대화 요약               │
│ 서로 다른 지점                     │
│ 바람과 걱정 · AI의 추정             │
│ 다음 수 제안                        │
│                                  │
│ [대국방으로]        [무승부 제안]  │
│ [새 AI 문철 신청하기]               │
│ [이전 AI 문철 기록 보기]             │
└──────────────────────────────────┘

문철 기록
┌──────────────────────────────────┐
│ 문철 2 · 14:30 · 읽기 전용          │
│ 문철 1 · 13:10 · 읽기 전용          │
└──────────────────────────────────┘
```

- 신청자는 자신의 동의를 표시한다. 상대가 수락하기 전에는 AI 문철 분석·결과를 만들지 않으며, 상대 수락 뒤에만 두 화면이 공용 로딩을 거쳐 결과를 확인할 수 있다.
- AI 문철의 내용은 두 멤버가 함께 보며, 대화 요약에는 확정 메시지의 말·사건만 정리한다.
- 서로 다른 지점은 각자가 중요하게 말한 기준·요청의 차이로, 바람과 걱정은 `AI의 추정`으로 표시한다. 다음 수는 먼저 확인할 질문·작은 약속·잠시 쉬고 다시 이야기하기를 제안한다.
- 결과 화면에서 무승부 제안으로 이동할 수 있다.
- 새 문철 준비 완료 알림은 결과를 자동으로 열지 않는다. 사용자가 대국방의 `AI 문철 확인하기`를 선택하며, 로딩 중에는 문철 관련 버튼을 누를 수 없다.

### 4.6 무승부 협상

```text
제안자 작성·수정
┌──────────────────────────────────┐
│ 조건부 무승부 제안                 │
│ 선택 방식: [한 개] [여러 개]        │
│                                  │
│ 조건 1: [내용] 책임 [나|상대|함께] │
│ 조건 2: [내용] 책임 [나|상대|함께] │
│ [+ 조건 추가]                      │
│ [계속 대국]          [제안하기]     │
└──────────────────────────────────┘

상대 응답
┌──────────────────────────────────┐
│ 상대의 무승부 제안                 │
│ □ 조건 1 · 수행: 제안자            │
│ □ 조건 2 · 함께                    │
│ [계속 대국] [카운터오퍼 메시지]     │
│                     [선택 후 수락] │
└──────────────────────────────────┘

상대 응답 — 조건 없음
┌──────────────────────────────────┐
│ 상대의 무승부 제안                 │
│ 합의할 조건이 없습니다.            │
│ 수락하면 미션 없이 대국방으로       │
│ 돌아갑니다.                        │
│                                  │
│ [계속 대국] [카운터오퍼 메시지]     │
│                              [수락] │
└──────────────────────────────────┘

제안자 — 카운터오퍼 수신
┌──────────────────────────────────┐
│ 내가 보낸 무승부 제안 · 수정 가능  │
│ 조건 1 · 수행: 나                 │
│                                  │
│ 카운터오퍼                        │
│ "조건을 이렇게 바꿔보면 어때?"     │
│                                  │
│ [무승부 협상 기록 보기] [수정하기] │
└──────────────────────────────────┘

카운터오퍼를 보낸 상대 — 수정 대기
┌──────────────────────────────────┐
│ 카운터오퍼를 보냈어요              │
│ 상대가 수정한 새 제안을 보낼 때까지 │
│ 기존 제안을 수락하거나 다시 보낼 수 │
│ 없습니다.                          │
│                                  │
│ [무승부 협상 기록 보기]            │
└──────────────────────────────────┘
```

- 선택 방식이 `한 개`면 상대는 정확히 하나를, `여러 개`면 하나 이상을 선택해야 수락할 수 있다.
- 조건이 없으면 선택 방식도 없다. 이때 상대는 선택 UI 없이 `수락`할 수 있으며, 수락하면 대국은 종료되어 지난 대국으로 보관되고 미션은 만들지 않는다.
- 제안자는 제안을 보낸 뒤 상대 응답 전에는 현재 제안을 읽기 전용으로 확인하며, `수정하기`·재발송을 제공하지 않는다. 카운터오퍼는 조건 편집 화면이 아니라 제안자에게 변경을 요청하는 메시지 작성 화면이다. 카운터오퍼가 도착하면 원 제안 아래에 메시지를 표시하고, 제안자는 그 메시지를 확인한 뒤에만 자신의 제안을 새 버전으로 수정한다. 카운터오퍼를 보낸 상대는 제안자의 수정 대기 화면만 보며, 새 제안 버전이 오기 전까지 기존 제안 수락·조건 선택·추가 카운터오퍼 버튼을 제공하지 않는다.
- `무승부 협상 기록 보기`는 현재 협상 또는 가장 최근에 합의·계속 대국으로 종료된 협상 1건에서 열 수 있으며, 그 협상의 제안 버전·카운터오퍼·수락·종료·합의 결과를 시간순 읽기 전용으로 표시한다. 새 협상을 시작하면 이전 협상 기록은 이 화면에서 교체한다.

### 4.7 미션 보드와 상대 확인

```text
┌──────────────────────────────────┐
│ 미션 보드                          │
│                                  │
│ 개인 미션 · 수행: 나 · 오늘         │
│ 오늘 밥은 내가 사기                 │
│ 상태: 진행 중                      │
│ [완료 요청] [수정 제안] [포기]      │
│                                  │
│ 공동 퀘스트 · 참여: 둘 다 · 내일    │
│ 같이 산책하기                       │
│ 상태: 상대 완료 대기                │
│ [내 완료 처리] [수정 제안] [포기]   │
│                                  │
│ 수정 제안                           │
│ 변경 전 / 제안 값                    │
│ [수락] [거절] 또는 [취소]           │
└──────────────────────────────────┘
```

- 개인 미션에서는 수행자에게 `완료 요청`·`재수행 시작`·`포기`, 상대에게 `확인`·`다시 요청`을 노출한다.
- 공동 퀘스트에서는 각 참여자에게 본인의 완료 처리·포기만 노출한다. 두 사람의 완료 처리 뒤 완료 상태가 된다.
- 진행 중 또는 재수행 요청 상태에서는 누구나 수정 제안을 만들 수 있다. 제안자는 취소, 상대는 수락·거절만 할 수 있으며 수락 전에는 기존 미션을 계속 표시한다.
- MVP의 수행 근거는 텍스트 완료 요청과 상대 확인만 사용한다. 사진 첨부·인증은 제공하지 않는다.

## 5. 필수 규칙 반영표

| 규칙 | 반영 화면과 경로 | 확인 방법 |
| --- | --- | --- |
| AI 심판은 메시지 전송 전 필수 | 대국방의 `확인` → AI 심판 시트만 전송 버튼 제공 | 대국방 와이어프레임에 전송 버튼이 없고 `확인`만 존재 |
| 최신 분석만 전송 가능 | AI 심판 시트의 `초안 수정` → 작성창 → 재확인 | 수정 뒤 이전 시트에서 전송으로 돌아가는 경로가 없음 |
| restricted 분석은 전송 불가 | restricted AI 심판 시트 | `초안 수정`만 표시하고 원문·추천 전송 버튼을 제거 |
| 초안·AI 심판 결과는 작성자 전용 | 대국방과 AI 심판 시트 | 대국방에는 전송 본문만, AI 심판 시트는 요청자만 진입 |
| 양측 합의 전 미션 미생성 | 무승부 협상 → 상대 선택·수락 → 미션 보드 | 제안·카운터오퍼·수정 중에는 미션 보드 생성 경로가 없음 |
| 카운터오퍼는 직접 조건 수정이 아님 | 상대 응답의 카운터오퍼 메시지 → 제안자 수정 | 상대 화면에는 조건 편집이 아니라 메시지 작성만 제공 |
| 선택된 조건만 미션 생성 | 상대 응답 → 선택 후 수락 | 선택 UI와 미션 보드의 조건 단위를 연결 |
| 미션 수정은 양측 수락 전 미적용 | 미션 보드의 수정 제안 | 기존 값과 제안 값을 함께 보이고, 상대 수락 뒤에만 갱신 |

이 문서는 화면 이동과 기본 구조만 정의한다. 각 항목의 로딩·실패·권한 거절·재연결 화면은 페이즈 2, 정확한 명령·조회·이벤트 payload는 페이즈 3에서 이어서 정의한다.
