# M1.2 페이즈 3 — 요청·응답·실시간 이벤트 계약

> 상태: 확정 · 2026-09-19

## 1. 범위와 공통 규칙

이 문서는 화면 행동을 명령, 상태 조회, 공용·비공개 이벤트로 나눠 구현 경계를 정의한다. HTTP·WebSocket·SSE, 저장소, 프레임워크는 선택하지 않는다.

### 1.1 용어와 응답 형태

- **명령**은 로그인 세션으로 호출자를 확인한 뒤 상태를 바꾸는 요청이다. 브라우저가 보낸 사용자 ID·역할·수락 여부는 권한 근거가 아니다.
- **조회**는 서버의 확정 상태를 읽는다. 이벤트는 알림이며, 누락·역순이면 조회가 기준이다.
- 공용 결과·이벤트에는 `room_id`, `room_revision`, 발생 시각을, 작성자 전용 결과·이벤트에는 `room_id`, `private_revision`, 발생 시각을 둔다. 더 오래된 순번은 적용하지 않는다.
- 성공 응답은 `ok: true`와 갱신 대상·최신 순번을, 실패 응답은 `ok: false`, `error.code`, 화면에 필요한 안전한 안내 키만 반환한다. 방 내부 정보가 없는 초대 실패에는 방 이름·멤버·대화·협상을 포함하지 않는다.

## 2. 조회 계약

| 조회 | 권한·입력 | 성공 결과 | 실패·화면 반영 |
| --- | --- | --- | --- |
| `main.get` | 로그인 | 내 미션, 진행 중 대국 최대 1개, 지난 대국, 각 요약 상태 | `unauthenticated`면 인증 화면. 실패면 메인 재시도 상태. |
| `profile.get` | 로그인 | 내 `display_name` | `unauthenticated`면 인증 화면. 실패면 프로필 재시도 상태. |
| `room.get` | 방 멤버, `room_id` | 멤버 표시 정보, 방 상태, 메시지, 현재 협상, 미션 요약, 현재/이전 공용 문철의 허용 범위 | `room_not_found`·`not_room_member`면 방 정보를 표시하지 않고 메인으로. |
| `room.changes.get` | 방 멤버, `room_id`, 마지막 `room_revision` | 이후 공용 변경 목록 또는 최신 공용 스냅샷 | 순번 단절·보관 범위 초과면 스냅샷. 30초 복구 실패면 읽기 전용과 수동 재시도. |
| `private.changes.get` | 작성자, `room_id`, 마지막 `private_revision` | 내 초안·AI 심판·개인 형세 파악·삭제 표식의 이후 변경 또는 최신 스냅샷 | 상대에게 호출·결과를 보내지 않는다. 삭제 본문·분석은 스냅샷에도 포함하지 않는다. |
| `room_review.history.get` | 방 멤버, `room_id` | 현재 결과를 제외한 이전 공용 문철 읽기 전용 목록 | 첫 문철만 있으면 빈 목록이며 진입점을 숨긴다. 종료 방은 두 사람이 확인한 `ready` 결과만 반환한다. |
| `settlement.history.get` | 방 멤버, `room_id` | 현재 또는 가장 최근 협상 1건의 버전·카운터오퍼·수락·종료·합의 기록 | 읽기 전용. 새 협상 시작 뒤 이전 협상은 반환하지 않는다. |

## 3. 명령 계약

| 명령 | 권한·필수 입력 | 성공 결과와 화면 반영 | 주요 오류 |
| --- | --- | --- | --- |
| `room.create` | 로그인 | `waiting` 방·활성 초대 생성, 초대 대기 화면 | `active_room_exists` → 내 대국 재개 |
| `profile.update` | 로그인, `display_name` | 내 표시 이름 갱신. 기존 방의 `room_display_name`은 유지 | `invalid_display_name` → 입력 아래 안내, `unauthenticated` → 인증 화면 |
| `invite.accept` | 로그인, 링크 토큰 또는 6자리 코드 | 멤버 생성·초대 사용·방 `active`를 원자 확정, 양쪽 대국방 | `invite_expired_or_revoked`, `invite_used_or_full`, `active_room_exists`, `invalid_invite`; 모두 방 내부 정보 비노출 |
| `draft.save` | 작성자, `room_id`, 본문, `expected_revision` | 내 초안·`private_revision` 갱신 | `draft_revision_conflict` → 최신/내 입력/직접 편집 선택 |
| `draft.discard` | 작성자, 초안 식별자·현재 revision | 내 초안 삭제 표식과 `private_revision` 갱신 | `draft_not_active`, `draft_revision_conflict` |
| `ai_judge.request` | 작성자, 최신 초안 식별자·revision·입력 해시 | 작성자 전용 분석 `pending` | `draft_stale`, `analysis_in_progress`, `room_closed` |
| `message.send` | 작성자, 최신 `normal` 분석 식별자, 원문 해시, `original` 또는 추천문 선택 | 메시지·초안 `sent`·분석 연결을 원자 확정, `room_revision` 갱신 | `analysis_not_ready`, `analysis_restricted`, `analysis_stale`, `room_closed` |
| `private_position.request` | 방 멤버, `room_id`, 기준 메시지 순번 | 요청자 전용 분석 `pending` | `room_closed`, `analysis_in_progress` |
| `room_review.request` | 방 멤버, `room_id`, 기준 메시지 순번 | 공용 `pending` 신청, 상대 수락 안내 | `room_closed`, `review_already_open` |
| `room_review.accept` | 신청 상대, 신청 식별자 | 수락·공용 `processing`, 두 화면 로딩 | `not_review_responder`, `review_not_pending` |
| `room_review.retry` | 최초 신청자, 최초 `failed` 신청 식별자 | 기존 기준 순번·상대 수락을 유지해 한 번 다시 `processing` | `not_review_requester`, `review_not_failed`, `review_retry_used` |
| `room_review.cancel` | 최초 신청자, `failed` 신청 식별자 | 신청 종료, 신청 전 문철 상태 | `not_review_requester`, `review_not_failed` |
| `room_review.viewed` | 방 멤버, 현재 `ready` 결과 식별자 | 호출자 개인 준비 완료 알림만 확인 처리 | `review_not_ready`; 상대 확인 여부는 반환하지 않음 |

| `settlement.offer.accept` | 활성 제안의 상대, 선택 조건 | 협상·선택 조건 미션·방 `closed`를 원자 확정 | `not_offer_responder`, `invalid_selection`, `offer_not_open` |
| `settlement.counteroffer.create` | 활성 제안의 상대, 메시지 | `counter_requested`, 공용 카운터오퍼 표시 | `not_offer_responder`, `offer_not_open` |
| `settlement.cancel` | 활성 `open` 제안의 허용 멤버 | 협상 `cancelled`, 대국 계속 | `offer_not_open` |

## 5. 재연결·비노출 검토

- 연결 회복 뒤 클라이언트는 공용·비공개 순번을 각각 조회한다. 최대 30초 안에 완료하지 못하면 마지막 확정 상태를 읽기 전용으로 유지하고, 같은 조회를 수동 재시도하거나 메인으로 이동한다. 자동 재시도 횟수·간격은 M1.3에서 정한다.
- 공용 이벤트와 조회에는 내부 `user_id`, 비공개 초안 본문, AI 심판·개인 형세 파악 결과, 개인 알림 확인 상태를 넣지 않는다.
- 로그인 전에는 `invite.accept`를 호출하지 않으며 초대 상태도 반환하지 않는다. 로그인 뒤 실패 응답은 4개 안내 키만 반환하고 방 내부 정보를 포함하지 않는다.
- 종료 방은 새 메시지·AI·협상 명령을 `room_closed`로 거절하지만, 미션 조회·허용된 미션 행동·읽기 전용 협상/문철 기록은 유지한다.

## 6. M1.3 이관과 완료 확인

- HTTP·실시간 전송 방식, 인증 세션 보관, 오류 코드의 전송 형태, 자동 재시도 횟수·간격, 저장 트랜잭션 구현은 M1.3에서 선택한다.
- 화면 상태의 모든 행동에 명령 또는 조회·이벤트 경계를 연결했고, D2026-09-19-22~24의 실패·복구·초대 공개 규칙을 계약에 포함했다.
- 새로운 제품 정책·기술 스택은 확정하지 않았다.
