## 1. 목적과 범위

페이즈 1의 확정 화면 흐름이 목데이터 상태에서도 사용자가 클릭으로 이해·완주되는지 확인한다. 이 목업은 화면 이동 검증 도구이며, 제품 정책·권한·데이터 공개 범위·API·실시간 동기화의 기준은 아니다.

- [의사결정 로그](../1.%20의사결정%20로그/README.md) 및 [D2026-09-19-08](../1.%20의사결정%20로그/2026-09-19_의사결정_로그.md): 메인의 미션 우선 표시, 진행 중 대국 1개, 합의 뒤 대국 종료·지난 대국 보관
- [MVP 명세](../1_MVP_명세.md#3-화면별-명세): 대국 시작, 필수 AI 심판, 협상·미션 화면 규칙
- [시스템·데이터 정의](../3_시스템_데이터_정의.md#42-ai-심판과-메시지) 및 [무승부 협상](../3_시스템_데이터_정의.md#44-무승부-협상): AI 심판 전송 경계와 조건 유무별 합의 처리
- [페이즈 1 화면 흐름과 와이어프레임](01_화면_흐름과_와이어프레임.md): 화면 구조와 이동의 선행 기준

## 2. 목업 위치와 실행

- 위치: [`mockup/index.html`](../../mockup/index.html)
- 구성: 외부 의존성 없는 단일 HTML 파일. 목데이터와 화면 상태는 브라우저 메모리에서만 바뀌며 새로고침하면 초기 상태로 돌아간다.
- 실행: 저장소 루트에서 `python3 -m http.server 4173 --directory mockup`를 실행한 뒤 `http://localhost:4173`을 연다.

목업의 `진행 중 대국 없음 보기`와 `새 대국 흐름 보기`는 진행 중 대국이 없는 분기를 재현하기 위한 검증 전용 제어다. 제품 화면에 추가할 기능이 아니다.

## 3. 클릭 검증 시나리오와 결과

| 시나리오 | 클릭 경로 | 결과 |
| --- | --- | --- |
| 메인 우선순위·목록 | 메인 진입 | 미션이 먼저 보이고, 그 아래에 진행 중 대국 강조 카드와 종료된 지난 대국 카드가 구분되어 보인다. |
| 대국 없는 시작 | `새 대국 흐름 보기` → `대국 시작하기` → `대국방 만들기` → `대국방 열기` | 대국방 만들기와 코드 입장 선택지를 거쳐 초대 대기·대국방으로 이동한다. |
| 필수 AI 심판 전송 | 대국방 초안 → `확인` → `추천 메시지 전송` 또는 `원문 전송` | 작성창에는 즉시 전송이 없고 AI 심판 시트에서만 두 전송 선택지가 보인다. 선택한 메시지가 확정 메시지 목록에 추가된다. |
| 조건 선택 수락 | `무승부 제안` → 조건 선택 → `선택 후 수락` | 선택 조건 수를 알려 주고, 대국을 종료해 진행 중 카드가 사라진 메인과 지난 대국 경로를 보여 준다. |
| 조건 0개 수락 | `무승부 제안` → `조건 0개 수락 흐름 보기` → `수락` | 선택 UI 없이 수락되며, `새 미션은 만들지 않았다`는 결과를 메인에 명시하고 대국은 종료된다. 기존 목데이터 미션은 새 합의에서 생성한 데이터가 아니다. |
| 카운터오퍼 | `무승부 제안` → `카운터오퍼 메시지` → `카운터오퍼 보내기` → `수정 후 재제안` | 상대는 조건을 직접 편집하지 않고 변경 메시지를 보내며, 제안자 A만 조건 수정·재제안을 수행한다. |
| 계속 대국 | 협상 화면 → `계속 대국` | 협상 시트를 닫고 진행 중 대국방으로 돌아간다. |
| 종료 대국·미션 이동 | 메인 지난 대국 → `미션 보드로` | 종료 대국에는 메시지 작성·협상 제어가 없고 읽기 전용임을 표시한다. 미션 보드는 대국 종료와 독립적으로 열린다. |

## 4. 발견 사항과 처리

- 조건 0개 합의 뒤 정적 목데이터의 기존 미션이 새 미션으로 오인될 여지가 있었다. 합의 결과 안내에 `새 미션은 만들지 않았다`를 표시해, 조건 0개 합의 규칙과 기존 미션 목록을 구분했다.
- 이 변경은 검증 화면의 설명 보완이며, 조건 유무와 관계없이 합의 뒤 대국을 종료한다는 확정 정책을 바꾸지 않는다.

## 5. 결정 필요

이번 범위에서 새로 확정할 정책·권한·데이터 공개 결정은 없다. 로딩·실패·`restricted`·재연결·초안 충돌의 사용자 상태는 페이즈 2에서, 요청·응답·이벤트 형식은 페이즈 3에서 정한다.

## 6. 다음 페이즈 입력

- 메인에는 미션 없음, 진행 중 대국, 지난 대국을 구분하는 상태가 필요하다.
- 합의 처리 뒤 메인 갱신과 종료 대국 읽기 전용 상태는 페이즈 2의 사용자 상태표에 포함한다.
- 목업에서 고정한 클릭 경로는 페이즈 3의 명령 후보를 찾는 참고일 뿐이며, 필드·권한·오류 계약은 시스템·데이터 정의를 근거로 별도 확정한다.
