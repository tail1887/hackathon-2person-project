# 커플들이 집착하는 AI 심판이 되었다 — 마일스톤 계획

> 이 문서는 해커톤 MVP를 만들기 위한 작업 순서와 각 단계의 완료 기준을 정한다. 화면·상태의 상세 기준은 [MVP 명세](1_MVP_명세.md), 제품 방향은 [기획서](0_커플들이_집착하는_AI_심판이_되었다_기획서.md)를 따른다.
>
> 각 완료 마일스톤의 검증 근거는 [검증보고서](2.%20검증보고서/README.md)에 남긴다.

## 진행 원칙

- 앞 단계의 완료 기준을 충족한 뒤 다음 단계로 넘어간다.
- 기능을 넓히기보다, 두 사용자가 고정 데모 시나리오를 끝까지 완주하는 데 필요한 흐름을 우선한다.
- 확장 기능인 AI 대리전, 공개 인증 피드, 개인·공용 대국 복기는 MVP 완료 뒤에 검토한다.

---

## M0. 제품 방향·MVP 명세 확정 — 완료

**목표:** 무엇을 만들지와 데모에서 반드시 보여 줄 경험을 합의한다.

### M0.1 제품 정체성과 핵심 가치 정의 — 완료

- 프로젝트명 `커플들이 집착하는 AI 심판이 되었다` 확정
- 관계 문제를 미루지 않게 하는 완충 장치와, 재미있는 게임형 대화 장치라는 두 사용 가치를 정의
- 진지한 감정 대화와 가벼운 대화 재미를 동등한 사용 방식으로 규정

**완료 기준:** 프로젝트명, 제품 한 줄, 핵심 가치와 사용자 사용 맥락이 기획서에 정리되고 팀이 확인한다.

### M0.2 문제 정의·사용자 시나리오 설계 — 완료

- 상처·감정 소모를 우려해 문제를 꺼내지 못하는 사용자 문제 정의
- 대국·중계·퀘스트 문법으로 대화 진입 장벽을 낮추는 제품 가설 정의
- 대국방 생성과 초대부터 AI 훈수, 무승부, 미션 완료까지의 핵심 사용자 플로우 정의

**완료 기준:** 핵심 사용자, 사용 순간, 고정 데모 시나리오와 전체 사용자 플로우가 기획서에 정리된다.

### M0.3 MVP 범위·상세 명세 확정 — 완료

- MVP 필수 기능과 이후 확장 기능을 분리
- 커플 연결·대국방 입장, 필수 AI 훈수, 무승부 협상, 미션·상대 확인을 MVP로 확정
- 화면별 입력·출력·상태 전이·인수 기준을 MVP 명세서에 정리
- 로그인 방식, 초대 링크·코드, 실시간 동기화, 사진 인증 범위에 대한 팀 확인 완료

**완료 기준:** 구현 대상과 제외 대상이 명확하고, 두 사용자가 고정 데모 시나리오를 완주하기 위한 상세 명세가 팀 확인을 받는다.

### M0.4 협업·문서 운영 기반 구축 — 완료

- 의사결정 로그와 프로젝트 컨텍스트를 포함한 작업 하네스 구성
- 기획서, MVP 명세, 마일스톤 계획을 생성 순서에 따라 문서화
- 중요한 결정은 로그에 남기고 변경 사항은 `main`에 커밋·푸시하는 작업 원칙 확정

**완료 기준:** 팀원이 같은 제품 맥락, 문서 구조, 의사결정 기록 방식과 작업 규칙을 확인할 수 있다.

### M0 전체 완료 기준

- 제품 방향, 사용자 시나리오, MVP 명세, 협업 방식이 문서화되고 팀 확인을 받는다.

## M1. 시스템·데이터·기술 설계 — 다음 단계

**목표:** MVP를 구현할 최소 시스템 구조와 기술 선택을 확정한다.

### M1.1 시스템·데이터 정의 — 완료

상세 초안은 [시스템·데이터 정의](3_시스템_데이터_정의.md)를 따른다.

완료 전 검토 이력은 [M1.1 검증보고서](2.%20검증보고서/M1.1_검증보고서.md), 최신 문서 대조 결과와 남은 보완 사항은 [M1.1 검증보고서 v2](2.%20검증보고서/M1.1_검증보고서_v2.md)를 참고한다.

- 사용자, 대국방, 초대, 메시지, AI 분석, 무승부 제안, 미션의 데이터 모델 정의
- 대국방·협상·미션의 상태 전이와 권한 규칙 확정
- 초대 입장과 두 브라우저 실시간 동기화 방식 정의

**완료 기준:** 고정 시나리오에 필요한 데이터, 상태, 접근 권한과 실시간 동기화 규칙이 빠짐없이 정의된다.

### M1.2 인터페이스 설계

페이지별 설계 문서는 [인터페이스 설계](4.%20인터페이스%20설계/README.md)에 작성한다.

- 대국방, AI 훈수 시트, AI 문철, 무승부 협상, 미션 보드의 화면 흐름과 와이어프레임 정의
- 각 화면의 로딩·빈 상태·오류·진행 상태 정의
- 시스템 정의를 바탕으로 화면 요청, API, 실시간 이벤트의 입출력 계약 확정

**완료 기준:** 두 사용자의 고정 시나리오를 화면 단위로 따라갈 수 있고, 화면과 서버가 주고받을 정보의 경계가 정리된다.

### M1.3 기술 스택·프로젝트 뼈대

- 프론트엔드, 백엔드·DB·인증·실시간, AI API, 배포 방식의 기술 스택 선택
- 개발 환경과 기본 프로젝트 구조 생성
- 선택한 배포 환경에서 빈 애플리케이션이 실행되는지 확인

**완료 기준:** 기술 선택의 근거가 기록되고, 팀원이 같은 환경에서 프로젝트를 실행할 수 있다.

### M1 전체 완료 기준

- 시스템·데이터 설계 문서와 기술 스택 결정이 팀 확인을 받는다.
- 두 사용자가 고정 시나리오를 수행할 때 필요한 데이터와 이벤트가 빠짐없이 정의된다.
- 구현을 시작해도 되는 수준의 화면·API·실시간 이벤트 경계가 정리된다.

**경계:** 커플 연결부터 대국방, AI 훈수, 협상·미션을 실제로 구현·통합하는 일은 M2~M5에서 수행한다.

---

## M2. 대국방 기반 구축

**목표:** 두 사용자가 하나의 대국방에서 실시간으로 만난다.

**작업 항목**

- 로그인·회원가입 후 입장
- 대국방 생성, 초대 링크·6자리 코드, 상대 입장 처리
- 대국방 화면과 실시간 메시지 송수신
- 대국방 접근 권한과 진행 중인 대국 상태 표시

**완료 기준**

- 서로 다른 두 브라우저가 같은 대국방에 들어갈 수 있다.
- 양쪽에서 메시지가 같은 순서로 즉시 보인다.

---

## M3. AI 대화 경험 구축

**목표:** 모든 메시지 전송 전에 AI 훈수를 거치고, 필요할 때 현재 대화 형세를 본다.

**작업 항목**

- 메시지 `확인` → AI 심판 필수 진입
- 원문 전송·추천 메시지 전송 선택
- AI 문철의 형세·쟁점·과열도 안내
- 위험 입력에는 프롬프트가 `restricted`를 반환하고 AI 추천을 생성하지 않음

**완료 기준**

- 사용자가 AI 심판을 건너뛰고 메시지를 전송할 수 없다.
- AI 출력에 `추정` 표기와 안전 규칙이 적용된다.
- 고정 시나리오에서 AI 훈수와 형세 파악이 자연스럽게 이어진다.

---

## M4. 무승부 협상·미션 완주

**목표:** 갈등 대화를 조건부 합의와 실제 행동으로 끝낸다.

**작업 항목**

- 무승부 제안, 수락, 카운터오퍼, 계속 대국 상태
- 합의 후 개인 미션·공동 퀘스트 생성
- 완료 요청, 상대 확인, 재수행 요청·시작, 포기, 양측 수락형 수정 제안 상태

**완료 기준**

- 두 사람의 수락 전에는 미션이 생성되지 않는다.
- 합의 조건에 따라 개인 미션과 공동 퀘스트가 올바르게 생성된다.
- 상대 확인까지 고정 시나리오를 완주할 수 있다.

---

## M5. 데모 완성·QA

**목표:** 발표에서 고정 시나리오를 안정적으로 보여 준다.

**작업 항목**

- 고정 데모 데이터와 두 사용자 테스트 환경 준비
- 입장 실패, AI 응답 실패, 협상 중단 등 핵심 오류 흐름 점검
- 모바일·데스크톱 화면 점검과 발표용 화면 정리
- 인수 기준 체크리스트 전체 확인

**완료 기준**

- 처음부터 미션 상대 확인까지 데모를 반복 재현할 수 있다.
- MVP 범위 밖 기능 없이도 제품 가치를 설명할 수 있다.
- 알려진 치명적 오류가 없다.
