## 02. AI 심판 필수 전송

```text
이 저장소의 M3 AI 대화 경험 구축 페이즈 2를 진행해줘.

먼저 AGENTS.md, doc/2_마일스톤_계획.md, doc/1. 의사결정 로그/README.md와 2026-09-20 로그, doc/1_MVP_명세.md의 대국방·AI 심판 시트, doc/3_시스템_데이터_정의.md의 작성자 개인 기록·권한·순번 규칙, doc/5. 인터페이스 설계의 화면 흐름·상태 설계·요청 응답 계약, doc/8. AI 대화 경험 구축/README.md와 01·02 문서를 읽어줘.

목표는 사용자가 AI 심판을 건너뛰고 메시지를 전송할 수 없게 하는 것이다.

1. Supabase Edge Function에서만 OpenAI Responses API를 호출한다. `OPENAI_API_KEY`는 비밀값으로만 읽고, 기본 모델은 `gpt-5.6`으로 둔다. 결과는 Structured Outputs JSON 스키마로 파싱한다.
2. 초안 저장·수정·AI 심판 요청·원문/추천문 전송을 서버 명령으로 구현한다. 모든 명령은 로그인·방 멤버·방 active 상태·초안 revision·입력 해시·최신 ready 분석을 검증한다.
3. AI 심판 normal 결과는 위험, `AI의 추정` 감정/의도, 추천 문장 2~3개를 작성자에게만 반환·저장한다. 위험 입력은 `restricted`만 반환하고 추천·원문 전송·협상 조건 생성을 허용하지 않는다.
4. 전송 명령은 analysis id와 최신 초안 해시, `original` 또는 `recommendation` 선택을 검증한 뒤에만 공용 messages에 저장한다. 공용 이벤트·메시지 조회에는 초안·AI 분석·내부 user_id를 넣지 마.
5. 대국방 목업 구조에 초안 입력, 확인 버튼, AI 심판 시트, 초안 수정, 원문/추천 전송 UI를 이관한다. 수정 뒤 이전 분석은 stale로 바꾸고 다시 확인하게 한다. 상대는 전송 본문만 보며 개인 심판 시트·상세에 접근할 수 없어야 한다.
6. AI 응답 실패, 초안 충돌, restricted, 오래된 분석, 권한 없음·종료 방의 안전한 오류와 재시도·수정 흐름을 구현한다.

OpenAI API 키·Service Role 키·분석 원문을 로그·브라우저·커밋에 남기지 마. 관련 마이그레이션·함수는 원격 배포 전 코드로 준비하고, 실제 배포와 수동 A/B 확인이 필요한 항목은 문서에 분리해 적어줘. lint·build·DB lint 등 좁은 검증을 수행하고, 페이즈 문서·개발일지·검증보고서를 갱신한 뒤 main에 커밋·푸시해줘.
```

## 03. 개인 형세 파악과 AI 문철

```text
이 저장소의 M3 AI 대화 경험 구축 페이즈 3을 진행해줘.

먼저 AGENTS.md, 최신 의사결정 로그, MVP 명세의 형세 파악·AI 문철, 시스템·데이터 정의의 ai_analysis·room_review_request·공개 범위, 인터페이스 설계의 형세/문철 화면·상태·이벤트, doc/8. AI 대화 경험 구축/README.md와 03 문서를 읽어줘. 페이즈 2 구현·마이그레이션·함수도 확인해줘.

1. `형세 파악`은 요청한 방 멤버만 자신의 개인 결과를 보게 한다. 최근 확정 공용 메시지만 입력으로 사용하고, 현재 형세·쟁점·다음 판단을 모두 `AI의 추정`으로 구조화해 저장·표시한다. 상대에게 요청 여부·분석·알림을 보내지 마.
2. AI 문철은 한 명의 신청 → 상대 수락 → 공용 생성 순서를 서버 상태로 강제한다. 수락 전에는 OpenAI를 호출하지 않는다.
3. 수락 뒤 두 멤버에게 같은 공용 로딩 상태를 보여 주고, 준비되면 자동으로 결과 창을 열지 말고 `AI 문철 확인하기`로 열게 한다. 결과에는 대화 요약, 서로 다른 지점, AI의 추정인 바람과 걱정, 다음 수만 포함하며 승패·잘잘못·관계 판정은 만들지 마.
4. 문철 실패는 두 멤버에게 분석 내용 없이 같은 실패 상태만 표시한다. 최초 신청자만 같은 수락 완료 요청을 재시도할 수 있게 하고, 취소 또는 재시도 실패 뒤 새 신청에는 다시 상대 수락이 필요하게 한다.
5. 현재 문철·새 신청·이전 읽기 전용 기록을 목업과 인터페이스 설계대로 연결한다. 개인 초안·개인 AI 심판 결과는 문철의 입력·출력·공용 이벤트에 절대 포함하지 마.
6. private_revision과 room_revision, 작성자 전용 이벤트와 방 공용 이벤트를 섞지 말고, 재연결 뒤 각 범위에 맞춰 상태를 복구한다.

OpenAI 호출은 Edge Function 비밀값과 `gpt-5.6` Structured Outputs를 사용해 구현한다. 권한·수락 전 호출 차단·개인 결과 비공개·문철 공용 결과를 검증하고, 문서·개발일지·검증보고서를 갱신한 뒤 main에 커밋·푸시해줘.
```

## 04. 검증과 M4 인계

```text
이 저장소의 M3 AI 대화 경험 구축 페이즈 4를 진행해줘.

먼저 AGENTS.md, 마일스톤 계획의 M3 완료 기준, 최신 의사결정 로그, MVP 명세의 AI 심판·형세·문철 인수 기준, 시스템·데이터 정의의 권한·상태·이벤트, 인터페이스 설계의 상태·계약, doc/8. AI 대화 경험 구축의 모든 페이즈 문서와 최신 구현을 읽어줘.

다음 고정 시나리오를 검증해줘.

1. A가 초안을 확인하면 A만 normal AI 심판 결과와 원문/추천 전송 선택을 본다.
2. A가 원문과 추천문을 각각 전송하면 A·B는 같은 공용 본문·순서를 보고, B는 A의 초안·분석을 볼 수 없다.
3. 초안 수정 뒤 이전 분석·전송 선택은 stale로 막히고 새 확인이 필요하다.
4. 위험 입력은 restricted만 반환하며 원문·추천 전송과 협상 조건 생성이 차단된다.
5. 형세 파악은 요청자에게만 보이고, AI 문철은 B 수락 전 생성되지 않으며 수락 뒤 두 사람에게 같은 공용 결과를 제공한다.
6. AI 실패·권한 없음·종료 방·연결 복구·제3 사용자 접근을 안전하게 처리한다.
7. OpenAI 키·Service Role 키·개인 초안·개인 AI 결과가 브라우저, 공용 조회, Broadcast payload, 저장소 로그에 노출되지 않는지 확인한다.

통과·미통과와 근거를 M3 검증보고서에 기록해줘. 미통과 항목이 있으면 완료로 표시하지 말고 보완 계획 또는 남은 위험으로 남겨줘. 통과하면 M3를 완료로 바꾸고, M4가 사용할 수 있는 메시지·AI 분석·문철 입력 경계를 문서에 기록해줘. 변경사항은 main에 커밋·푸시해줘.
```
