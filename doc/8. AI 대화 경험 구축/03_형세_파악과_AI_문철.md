# M3 페이즈 3 — 형세 파악과 AI 문철

> 상태: 구현 완료 · 원격 배포·A/B 수동 검증 대기 · 2026-09-20

개인 형세 파악은 요청자 전용으로, AI 문철은 신청·상대 수락 뒤 방 멤버 공용 결과로 구현한다.

## 구현 결과

- `private-position`은 방 멤버·활성 방을 확인한 뒤 최근 확정 공용 메시지 최대 20개만 입력으로 사용한다. 결과는 요청자의 `private_position` 분석으로 저장하고, 요청자 전용 `private_analysis_public`·개인 바텀시트로만 제공한다.
- `room-review-request`는 한 명의 신청만 열 수 있고, `room-review-accept`는 상대만 수락할 수 있다. 수락 전 OpenAI 호출은 없다.
- 상대 수락은 서버에서 즉시 `processing`으로 전환한 뒤 공용 `room_review` 분석을 만들고, 성공 시 `ready`로 전환한다. 실패하면 `failed`로 남아 결과를 공개하지 않는다.
- `room_review_request_public`에는 현재 사용자의 신청자·수락자 여부만, `room_review_public`에는 방 멤버에게 허용된 공용 결과만 투영한다. 초안·개인 분석·요청자 내부 ID는 노출하지 않는다.
- 문철 상태 변경은 기존 비공개 `room:{roomId}` Broadcast 채널로 전송한다. 두 사용자 화면은 동일한 대기·준비 상태를 갱신하며, 준비된 결과도 자동으로 열지 않고 `AI 문철 확인하기` 버튼으로 연다.

## 남은 원격 확인

- 새 SQL 마이그레이션과 세 Edge Function을 Supabase에 배포한다.
- A가 형세 파악을 요청했을 때 B에게 어떤 상태·결과도 보이지 않는지 확인한다.
- A 신청 → B 수락 → 두 화면의 처리 상태 → 동일한 공용 결과 확인과 수락 전 OpenAI 미호출을 확인한다.
