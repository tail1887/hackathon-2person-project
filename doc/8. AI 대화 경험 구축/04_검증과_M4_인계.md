# M3 페이즈 4 — 검증과 M4 인계

> 상태: 진행 중 · 원격 스키마·함수 배포 완료 · A/B 검증 대기 · 2026-09-21

AI 심판 우회 차단, restricted·실패·초안 수정·권한 분리와 A/B 고정 시나리오를 검증하고 M4 협상 입력 경계를 확정한다.

## 진행 결과

- 공용 AI 문철이 수락 뒤 실패하면 분석 본문 없이 두 멤버가 같은 실패 상태를 받는다.
- 최초 신청자만 같은 기준 메시지 순번으로 한 번 재시도할 수 있으며, 재시도 뒤 다시 실패하면 취소 후 새 신청·새 상대 수락 흐름으로 돌아간다.
- 최초 신청자만 실패 요청을 취소할 수 있다. 다른 멤버·제3 사용자의 재시도·취소는 SQL RPC에서 차단한다.
- 실패·재시도·취소도 기존 멤버 전용 Broadcast와 `room_revision`으로 동기화한다.

## 원격 A/B 검증 순서

1. A의 normal 심판·원문/추천 전송과 B의 비공개 정보 비노출을 확인한다.
2. 수정 후 stale 전송 차단, restricted 전송 차단, 종료 방·제3 계정 거절을 확인한다.
3. A 개인 형세 파악의 B 비노출을 확인한다.
4. A 문철 신청 → B 수락 → 두 화면 공용 로딩·동일 결과를 확인한다.
5. 의도적으로 OpenAI 비밀값을 사용할 수 없는 테스트 환경에서 문철 실패 안내, A만의 한 번 재시도·취소, 취소 뒤 새 신청의 재수락을 확인한다.

M4는 위 원격 검증이 통과하고 M3 전체 완료 판정이 난 뒤 시작한다.

원격 스키마(`20260920000100`~`20260920001400`)와 M3 Edge Function 7개는 운영 프로젝트에 배포됐다. `OPENAI_API_KEY` 비밀값 존재와 각 함수의 CORS 사전 요청도 확인했다. 세션이 필요한 실제 AI 호출과 위 A/B/제3 계정 시나리오는 아직 별도로 확인해야 한다. 자세한 근거는 [M3 원격 배포 검증보고서 v4](../3.%20검증보고서/M3_AI_대화_경험_구축/v4_원격_배포_검증보고서.md)에 남겼다.
