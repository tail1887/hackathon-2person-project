# M4 페이즈 3 — 미션 보드와 상호 확인

합의 뒤 메인과 미션 상세에 개인 미션·공동 퀘스트를 목업 구조로 표시하고, 완료 요청·상대 확인·재수행·포기·수정 제안을 실제 상태 전이와 연결한다.

## 구현 결과

- 메인의 활성 미션 영역에서 진행 중·상대 확인 대기·재수행 요청 미션을 우선 표시하고, 해당 종료 대국방의 미션 보드로 이동한다.
- 종료 대국방은 목업의 미션 보드 구조로 개인 미션·공동 퀘스트·기한·현재 버전·상태를 표시한다.
- 개인 미션은 수행자 완료 요청·포기, 상대 확인·재수행 요청, 수행자의 재수행 시작을 연결했다. 공동 퀘스트는 각 참여자의 완료 체크와 포기를 연결했다.
- 수정 제안은 공개 멤버 키만 브라우저에서 보내며, 서버가 내부 수행자 ID를 해석한다. 상대 수락·거절 또는 제안자 취소와 버전 기록을 화면에 표시한다.

## 검증

- 원격 `20260921001900`, `20260921002000` 적용 및 `db lint --linked` 통과
- `npm run lint`, `tsc --noEmit`, `npm run build` 통과
- 두 계정에서 개인·공동 미션의 각 전이와 제3 계정 차단은 페이즈 4에서 수동 검증한다.
