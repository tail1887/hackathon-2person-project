# M4 페이즈 1 — 협상·미션 데이터와 명령

## 목표

협상 제안 버전·조건·선택·카운터오퍼와 미션·행동·수정 제안을 서버가 원자적으로 확정할 데이터 모델과 명령 경계로 구현한다.

## 구현 순서

1. 협상, 제안 버전, 조건, 선택, 카운터오퍼, 미션, 미션 버전·행동·수정 제안 테이블과 방 멤버 전용 공개 뷰를 만든다.
2. 협상 제안·카운터오퍼·계속 대국·수락 명령을 구현한다. 수락은 조건 검증, 선택된 조건만 미션 생성, 방 종료, 공용 순번 증가를 하나의 트랜잭션으로 처리한다.
3. 개인·공동 미션의 완료·확인·재수행·포기와 수정 제안 명령을 구현한다.
4. 모든 공용 상태 변경 뒤 `room_revision`과 공용 broadcast를 갱신한다. 개인 초안·AI 분석은 이 데이터에 넣지 않는다.

## 핵심 불변식

- 방 멤버·방 상태·현재 협상/미션 상태·제안 버전은 서버에서 다시 확인한다.
- 제안자는 자동 수락 상태이며, 상대만 조건 선택·수락·카운터오퍼·계속 대국을 할 수 있다.
- 카운터오퍼는 조건 수정이 아니라 메시지다. 카운터오퍼가 없는 제안자는 재제안할 수 없다.
- 수락 처리 전에는 미션이 없고 방은 active다. 수락 성공 시에만 선택된 조건별 미션과 방 closed 상태가 함께 확정된다.
- 개인 완료 확인자는 수행자가 아닌 상대다. 공동 퀘스트는 두 참여자의 현재 버전 체크인이 있어야 완료된다.

## 검증

- 마이그레이션을 원격에 적용하고 DB lint를 실행한다.
- 각 명령의 권한·중복·상태 오류를 좁게 확인한다.
- 공개 뷰·방송 payload에 내부 user id·개인 AI 데이터가 없는지 확인한다.

## 진행 기록

- `20260921001500_create_settlement_mission_foundation.sql`로 협상·조건·카운터오퍼·미션·이력 테이블과 방 멤버 전용 공개 뷰를 추가했다.
- 로컬 Supabase에 마이그레이션을 적용하고 `supabase db lint --local`을 통과했다.
- 원격 적용과 명령 구현은 다음 작업이다. 원격 Supabase CLI 토큰이 현재 유효하지 않아 원격 DB에는 아직 반영하지 않았다.
