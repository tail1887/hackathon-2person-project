# M4 페이즈 2 — 무승부 협상 화면과 동기화

목업의 무승부 제안·상대 응답·카운터오퍼·읽기 전용 기록 화면을 실제 협상 명령과 연결한다. 활성 제안에서는 제안자를 잠그고, 카운터오퍼 뒤에만 새 버전 폼을 열며, 협상 변경은 두 화면에 같은 순서로 반영한다.

## 구현 결과

- 대국방의 `무승부 제안`·진행 중 협상 배너·`협상 기록` 진입점을 목업의 정보 순서와 문구로 연결했다.
- 제안 작성, 조건 책임 주체, 조건 0개, 제안자 잠금, 카운터오퍼, 응답자의 조건 선택·수락·계속 대국, 최신 협상 기록 시트를 실제 RPC와 연결했다.
- `settlement.offer_changed`, `settlement.cancelled`, `settlement.agreed` broadcast를 구독해 두 브라우저가 최신 협상 스냅샷을 다시 읽는다.
- `room_member_public.is_self`는 내부 사용자 ID를 보내지 않고 현재 멤버의 공개 키만 UI가 식별하게 한다.

## 검증

- 원격 `20260921001800` 적용 및 `db lint --linked` 통과
- `npm run lint`, `tsc --noEmit`, `npm run build` 통과
- 실제 A/B 제안·카운터·수락·계속 대국 시나리오는 페이즈 4에서 수동 검증한다.
