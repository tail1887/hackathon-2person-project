- 영향 범위: 내 프로필·메인·대국방 멤버 표시, M2 페이즈 2 UI, 이후 프로필 사진 확장 경계, 사진 첨부 제외 범위

### D2026-09-20-06 · 인증 범위 · 확정

- 결정: MVP의 Kakao OAuth를 제외하고, 인증 수단은 Google OAuth와 이메일·비밀번호 회원가입·로그인만 제공한다. 로그인 화면과 Supabase Kakao 공급자는 비활성화하며, 기존 Kakao Developers 앱·동의 설정은 삭제하지 않고 사용하지 않는다.
- 이유/근거: Supabase 기본 Kakao 공급자가 `account_email` 범위를 요청해 권한 없음(KOE205)이 지속되고, 해당 권한을 위한 사업자 전환을 진행할 수 없다. 빠른 개발이 목표인 MVP에서는 인증 보완보다 방·초대·실시간 대국방 구현을 우선한다.
- 영향 범위: MVP·시스템·인터페이스·기술 스택·M2 인증 기준, 로그인 UI와 Supabase Auth 공급자 설정, M2 검증 범위 및 이후 작업 프롬프트

### D2026-09-20-07 · 방·초대 명령의 브라우저 인증 경계 · 확정

- 결정: `room-create`와 `invite-accept` Edge Function은 CORS 사전 요청을 허용하기 위해 플랫폼의 요청 전 JWT 검사를 해제하되, 실제 `POST` 요청에서는 함수 내부가 Supabase Auth로 액세스 토큰을 검증한 뒤에만 RPC를 실행한다.
- 이유/근거: 브라우저의 CORS 사전 요청에는 인증 토큰이 포함되지 않아 플랫폼 선행 검사와 충돌한다. 단순히 검사를 해제하면 방 상태 변경 경계가 약해지므로, 유효 사용자 확인을 함수 내부에서 명시적으로 수행한다.
- 영향 범위: M2 페이즈 3 `room-create`·`invite-accept` 배포 설정, CORS 응답 헤더, 방 생성·초대 수락 인증 실패 처리, A/B/제3 사용자 검증

### D2026-09-20-08 · 대국방 확정 시점 · 확정

- 결정: 대국방은 생성자가 초대를 발급할 때 만들지 않고, 초대받은 사용자가 링크 또는 6자리 코드를 수락하는 시점에 두 멤버와 함께 원자적으로 생성한다. 생성자가 먼저 만드는 것은 방이 아닌 활성 초대 대기 기록이다. 기존 테스트용 방·멤버·초대·메시지 데이터는 정리하되, 로그인 계정과 프로필은 보존한다.
- 이유/근거: 초대를 수락하지 않은 상태에서 `waiting` 대국방이 영구 생성되면, 사용자가 초대를 공유하거나 수락하기 전에 이탈했을 때 고아 방과 잘못된 `진행 중인 대국` 제한이 남는다. 실제 대화 단위인 대국방은 두 사용자의 입장이 함께 확정될 때만 존재해야 한다.
- 영향 범위: M2 방·초대 상태 전이와 스키마, `room-create`·`invite-accept` 명령, 메인 초대 대기 화면·오류 문구, 기존 테스트 데이터 정리, M2 페이즈 3 인수·권한 검증
