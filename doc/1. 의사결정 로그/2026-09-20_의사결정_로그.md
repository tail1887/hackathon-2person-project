### D2026-09-20-02 · 인증 정책 · 폐기

- 결정: 카카오 OAuth 인증에 성공한 사용자는 `account_email` 동의를 제공하지 않아도 로그인한 사용자로 취급하고 서비스를 이용할 수 있다. 이메일은 일반 이메일·비밀번호 인증에서만 필수이며, 카카오 사용자의 방 표시 이름은 프로필 또는 카카오 닉네임으로 확보한다.
- 이유/근거: 서비스의 권한 기준은 이메일이 아니라 인증 세션과 방 멤버십이다. 카카오 인증 성공 사용자를 이메일 부재만으로 막으면 확정된 카카오 로그인 제공 범위와 충돌한다.
- 영향 범위: Supabase Kakao provider 설정, profiles 생성·표시 이름 처리, M2 페이즈 2 OAuth 검증, 인증 수단 데이터 모델

### D2026-09-20-03 · 화면 구조 · 확정

- 결정: M2 페이즈 2에 메인에서 진입하는 `내 프로필` 설정 화면을 추가한다. 사용자는 자신의 표시 이름을 확인·수정하고, 저장 또는 취소한 뒤 메인으로 돌아가며 같은 화면에서 로그아웃할 수 있다.
- 이유/근거: 계정 표시 이름은 방 입장과 카카오 이메일 미제공 사용자의 식별에 쓰이지만, 현재는 가입 뒤 사용자가 직접 확인·수정할 화면 경로가 없다.
- 영향 범위: 메인 화면, 프로필 설정 화면, `profiles.display_name` 자기 수정, 인증·세션 UI, M2 페이즈 2 구현·검증

### D2026-09-20-04 · 프로필 아바타 범위 · 확정

- 결정: MVP에서는 사진 업로드·저장·교체를 제공하지 않는다. 프로필과 방 표시에는 사용자 표시 이름의 이니셜과 사용자별로 결정되는 기본 색상 아바타를 사용한다. UI 컴포넌트는 이후 `avatarUrl`을 받을 수 있게 만들되, URL 필드·Storage 버킷·업로드 권한은 사진 기능을 추가하는 후속 단계에서만 만든다.
- 이유/근거: 대국방 기반 구축의 핵심은 인증·초대·권한·실시간 동기화이며, 사진 업로드는 Storage·파일 검증·권한·실패 처리를 추가한다. 지금은 프로필 식별성을 확보하면서도 MVP 범위를 유지한다.
- 영향 범위: 내 프로필·메인·대국방 멤버 표시, M2 페이즈 2 UI, 이후 프로필 사진 확장 경계, 사진 첨부 제외 범위

### D2026-09-20-05 · 팀 작업과 외부 서비스 권한 경계 · 확정

- 결정: 팀원은 GitHub 저장소의 코드·문서만 수정하고, Supabase·Vercel·Google Cloud·Kakao Developers 설정과 비밀 환경 변수는 프로젝트 소유자 계정에서 관리한다. 팀원 로컬 실행에는 공개 Supabase URL·Publishable key만 각자의 `web/.env.local`에 설정하며 커밋하지 않는다.
- 이유/근거: 빠른 병렬 코드 개발은 허용하되 OAuth Client Secret·Service Role 키와 배포 권한을 저장소나 팀원 작업 환경으로 확산하지 않고, 외부 서비스 변경의 책임 주체를 명확히 하기 위해서다.
- 영향 범위: M2 이후 모든 구현 페이즈의 작업 프롬프트, Supabase·Vercel·OAuth 설정 요청·검증 절차, 비밀값 취급 규칙

### D2026-09-20-06 · 인증 범위 · 확정

- 결정: MVP의 Kakao OAuth를 제외하고, 인증 수단은 Google OAuth와 이메일·비밀번호 회원가입·로그인만 제공한다. 로그인 화면과 Supabase Kakao 공급자는 비활성화하며, 기존 Kakao Developers 앱·동의 설정은 삭제하지 않고 사용하지 않는다.
- 이유/근거: Supabase 기본 Kakao 공급자가 `account_email` 범위를 요청해 권한 없음(KOE205)이 지속되고, 해당 권한을 위한 사업자 전환을 진행할 수 없다. 빠른 개발이 목표인 MVP에서는 인증 보완보다 방·초대·실시간 대국방 구현을 우선한다.
- 영향 범위: MVP·시스템·인터페이스·기술 스택·M2 인증 기준, 로그인 UI와 Supabase Auth 공급자 설정, M2 검증 범위 및 이후 작업 프롬프트
