## 3. 후보 조합

## 4. 공식 문서로 확인한 사실

- Supabase는 Postgres, Auth, Realtime, 서버 함수와 Row Level Security 기반 권한 구성을 제공하며, Realtime Broadcast는 보안·확장성 관점에서 권장된다. [Supabase 개요](https://supabase.com/docs) · [Realtime](https://supabase.com/docs/guides/realtime/subscribing-to-database-changes) · [Realtime 권한](https://supabase.com/docs/guides/realtime/authorization)
- Supabase Auth는 이메일·비밀번호와 Google 소셜 로그인을 지원한다. 목록에 없는 공급자는 OAuth2/OIDC 호환 여부와 별도 연동 경로를 검증해야 한다. [Supabase Auth](https://supabase.com/docs/guides/auth)
- Firebase Authentication은 이메일·비밀번호와 주요 연동 공급자를 지원하고, Firestore는 다중 문서 원자 트랜잭션을 제공한다. Realtime Database는 클라이언트 동기화·오프라인 복구를 제공한다. [Firebase Auth](https://firebase.google.com/docs/auth) · [Firestore 트랜잭션](https://firebase.google.com/docs/firestore/manage-data/transactions) · [Realtime Database](https://firebase.google.com/docs/database)
- Next.js는 `.env`를 지원하며 `NEXT_PUBLIC_` 접두사가 붙은 값은 브라우저 번들에 포함된다. OpenAI API 키는 서버 환경 변수로만 보관해야 한다. [Next.js 환경 변수](https://nextjs.org/docs/pages/guides/environment-variables) · [OpenAI API 빠른 시작](https://platform.openai.com/docs/quickstart/make-your-first-api-request)
- Vercel은 Next.js의 기본 배포 흐름과 Git 기반 미리보기 배포를 지원한다. [Next.js on Vercel](https://vercel.com/docs/frameworks/full-stack/nextjs) · [Vercel 배포](https://vercel.com/docs/deployments/overview)

## 5. 페이즈 2 결정에 필요한 질문

1. 카카오·네이버 로그인은 MVP에서 제외하고, 이메일·Google로 데모를 완주한다.
2. 통합 관리형 서비스의 빠른 시작을 우선한다.
3. 사진 첨부는 MVP와 프로젝트 뼈대에서 제외한다.
4. Vercel을 배포 환경으로 사용하고, Git 기반 미리보기도 M1.3 기본 검증에 포함한다.
