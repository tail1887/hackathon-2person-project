# M1.3 기술 스택·프로젝트 뼈대

> 상태: M1.3 진행 중 · 2026-09-19

이 폴더는 완료된 M1.1 시스템·데이터 정의와 M1.2 인터페이스 설계를 실제 구현 가능한 기술 선택과 프로젝트 구조로 구체화하는 기준이다. 기술·서비스·배포 방식을 선택하기 전에는 제안과 확정을 구분하며, 확정한 선택은 의사결정 로그부터 남긴다.

## 1. 선행 기준과 범위

- [마일스톤 계획](../2_마일스톤_계획.md#M13-기술-스택프로젝트-뼈대): M1.3 목표와 완료 기준
- [시스템·데이터 정의](../3_시스템_데이터_정의.md): 데이터, 권한, 상태 전이, 실시간 복구 규칙
- [인터페이스 설계](../5.%20인터페이스%20설계/README.md): 화면·상태·요청·이벤트 계약
- [M1.2 완료 검증보고서](../3.%20검증보고서/M1.2_인터페이스_설계/v14_검증보고서.md): 실제 구현 전 남은 위험

M1.3에서 정할 범위는 프론트엔드, 백엔드·DB·인증·실시간, AI 연동, 배포, 개발 환경과 프로젝트 뼈대다. M2~M5의 실제 기능 구현·통합과 운영 정책은 포함하지 않는다.

## 3. 작업 순서와 의사결정 경계

1. 페이즈 1에서 구현 계약이 요구하는 최소 역량을 정리한다. 특정 제품·프레임워크는 아직 선택하지 않는다.
2. 페이즈 2에서 후보를 비교해 기술 조합을 확정한다. 기술 스택·아키텍처·외부 서비스·배포 방식 선택은 중요한 결정이므로 날짜별 의사결정 로그를 먼저 갱신한다.
3. 확정된 선택만 페이즈 3의 실제 디렉터리·설정·환경 변수 경계로 옮긴다. 선택 전의 뼈대 생성이나 외부 계정·유료 서비스 연결은 하지 않는다.
4. 페이즈 4에서 실행·배포 기본 검증과 M1.3 검증보고서를 작성한 뒤에만 M1.3을 완료로 바꾼다.

## 4. 필수 검토 항목

- M1.2의 `room_revision`·`private_revision`, 공용·비공개 이벤트, 원자 처리, 30초 복구를 구현할 수 있는가
- 카카오·구글 및 이메일·비밀번호 인증, 초대 링크·코드 권한 검증을 지원하는가
- AI 심판, 개인 형세 파악, 공용 AI 문철의 비공개·공개 범위를 분리할 수 있는가
- 개발 속도, 무료/예측 가능한 비용, 2인 협업, 배포·비밀값 관리가 해커톤에 적합한가
- 로컬·배포 환경에서 비밀값을 저장소에 넣지 않고 설정 누락을 안전하게 안내할 수 있는가

## 5. 완료 조건과 다음 단계

M1.3은 선택 근거가 의사결정 로그와 기준 문서에 남고, 선택한 프로젝트가 팀원 환경과 배포 환경에서 빈 애플리케이션으로 실행되며, [M1.3 검증보고서](../3.%20검증보고서/README.md)에 근거가 기록될 때 완료한다.

완료 뒤 다음 단계는 M2 대국방 기반 구축이다. M2 구현은 이 폴더의 확정 기술 선택과 프로젝트 뼈대를 전제로 한다.
