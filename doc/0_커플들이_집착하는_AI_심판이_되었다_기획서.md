> **싸움은 무승부로, 우리는 계속.**  
> AI가 보내기 전의 감정을 한 번 정리해, 미뤄진 대화를 다시 꺼낼 수 있게 하는 커플 갈등 대화 게임.

## 1. 문제 정의

이 서비스의 사용 이유는 하나가 아니다. 어떤 커플에게는 관계 문제를 꺼내기 위한 안전한 완충 장치이고, 다른 커플에게는 평소 대화를 더 재미있고 가볍게 이어 가는 게임 같은 대화 장치다. 두 방식은 충돌하지 않으며, 사용자는 그때그때 필요한 깊이로 서비스를 사용한다.

### 진지한 대화가 필요한 순간

커플 갈등은 대개 “말할 내용이 없어서”가 아니라, 그 말을 꺼냈을 때 생길 상처와 에너지를 감당하기 어려워서 길어진다. 사람들은 상대를 상처 입힐까 봐, 내 감정을 정확히 설명하기 어려워서, 혹은 대화 자체가 너무 소모적일까 봐 문제를 미룬다.

- 감정을 정리하지 못한 채 날것의 문장을 전송하거나, 아예 말을 꺼내지 못한다.
- 내 본심이 서운함인지, 불안인지, 인정받고 싶은 마음인지 나도 모른 채 대화를 미룬다.
- 상대의 의도를 사실처럼 해석하고, 문제를 꺼내는 일을 더 위험하게 느낀다.
- 대화를 멈추고 싶어도 누가 먼저 멈출지, 어떻게 다시 시작할지 모른다.
- 화해 후에도 실제로 무엇을 할지 정하지 못한다.

기존 상담형 서비스는 유용하지만, 문제를 꺼내기 망설이는 순간에 켜기에는 무겁고 진지하다. 이 서비스는 갈등을 가볍게 소비하지 않으면서도, **대국·중계·퀘스트**의 언어로 대화 진입 장벽을 낮춘다. AI 훈수는 감정과 대화 사이에서 한 번 멈추게 하는 쿠션이 되어, 사용자가 내 본심을 이해하고 상대에게 전할 말을 고르게 돕는다.

### 가볍게 대화를 시작하고 싶은 순간

모든 사용자가 깊은 갈등 해결을 목적으로 앱을 열지는 않는다. 어떤 커플은 AI의 훈수와 대국 문법 자체를 재미있는 대화 소재로 쓰고, 평소에는 하기 어려운 말도 부담 없이 주고받고 싶어 한다. 게임 같은 연출은 갈등을 가볍게 만들기 위한 장식이 아니라, 대화를 시작하는 부담을 낮추는 진입점이다.

**제품 원칙:** 진지한 회복 대화와 가벼운 대화 재미 중 어느 한쪽을 더 올바른 사용 방식으로 규정하지 않는다. 같은 기능이 사용자에게 필요한 깊이에 따라 관계의 완충 장치 또는 즐거운 대화 장치가 될 수 있게 설계한다.

> 메시지를 보내기 전 AI가 감정과 의도를 한 번 정리해 주고 게임 같은 선택지를 제시하면, 사용자는 가볍게 대화를 시작하거나 필요할 때 자신의 본심을 전달할 수 있는 다음 말을 선택한다.

### 승리 조건의 재정의

이 서비스는 상대를 이기는 게임이 아니다.

```text
표면: 대국, 형세, 판정, 무승부, 퀘스트
실제 승리: 갈등의 악화를 멈추고, 서로가 수락한 다음 행동을 만드는 것
```

## 3. 핵심 사용자와 사용 순간

| 사용자 | 상황 | 필요한 것 |
| --- | --- | --- |
| 재미있는 대화 소재를 찾는 커플 | 평소 대화에 게임 같은 장치를 더하고 싶을 때 | AI 훈수, 대국 문법, 가벼운 선택지 |
| 문제를 미루는 사용자 | 말을 꺼내면 상처를 주거나 너무 소모적일 것 같을 때 | 감정 정리와 대화 시작을 위한 안전한 첫 문장 |
| 말이 세게 나오는 사용자 | 화난 상태에서 답장을 보내려는 순간 | 보내기 전 문장 훈수 |
| 대화를 멈추고 싶은 사용자 | 감정이 격해져 결론이 나지 않을 때 | 형세 판정과 무승부 제안 |
| “누가 문제인지” 알고 싶은 커플 | 같은 주장을 반복한 뒤 | 쟁점·감정·요구 분리 |
| 화해를 행동으로 옮기고 싶은 커플 | 무승부가 성립한 뒤 | 오늘/내일 안에 할 미션 |

## 4. 제품 구조

```text
대국방(실제 커플 대화)
  ├─ AI 심판: 메시지 전송 전 문장 분석·추천
  ├─ AI 문철: 현재 형세와 쟁점 판정
  ├─ AI 대리전: 승인한 범위 안에서 AI가 조건을 조율하는 비공개 협상
  ├─ 무승부 협상: 조건 제안·카운터오퍼·수락
  ├─ 미션: 합의 조건의 개인/공동 실행
  └─ 인증 피드: 선택적으로 공개하는 회복 퀘스트 기록
```

### 바둑/체스 문법의 서비스 변환

| 게임 문법 | 서비스 안에서의 의미 |
| --- | --- |
| 한 수 | 전송하려는 메시지 |
| 수읽기 | 그 문장이 만들 수 있는 반응과 대안 |
| 형세 파악 | 현재 갈등 단계와 대화 가능성 분석 |
| 무승부 제안 | 조건을 붙여 보내는 갈등 종료 협상 |
| 카운터오퍼 | 상대가 조건을 추가해 다시 보내는 제안 |
| 복기 | 갈등이 커진 지점과 효과 있었던 표현 분석 |
| 퀘스트 | 합의된 회복 행동 |

## 5. 핵심 플로우

```text
1. 사용자가 카카오·구글·네이버 간편 로그인 또는 이메일·비밀번호 회원가입으로 로그인한다.
2. 한 사용자가 대국방을 만들고 초대 링크 또는 코드를 상대에게 보낸다.
3. 초대 링크를 받은 상대가 미로그인 상태면 회원가입 또는 로그인을 마치고, 원래 초대된 대국방으로 자동 이동한다.
4. 사용자가 대국방에서 메시지를 작성한다.
5. [확인]을 누르면 AI 심판이 반드시 개입한다.
6. 사용자는 훈수 결과를 본 뒤 원문 전송 / 추천 메시지 전송 중 선택한다.
7. 대국방에서 형세 파악을 누르면 AI 문철이 대화의 현재 판정을 제시한다.
8. 필요 시 한 사람이 조건부 무승부를 제안하거나 AI 대리전을 요청한다.
9. 대리전에서는 양측 AI가 각자가 승인한 요구·양보 범위 안에서 초안 합의안을 만든다.
10. 두 사람은 합의 초안을 확인한 뒤 수락 / 수정 요청 / 계속 대국 중 선택한다.
11. 무승부가 합의되면 조건별 개인 미션 또는 공동 퀘스트가 생성된다.
12. 오늘 또는 내일 안에 인증·상호 확인을 거쳐 미션을 완료한다.
13. AI 문철이 대국을 복기하고, 다음 판에 참고할 한 줄을 남긴다.
```

## 6. MVP 기능 상세

### 6.1 커플 연결과 대국방 입장

**목적:** 두 사람이 같은 대국방에 들어와 갈등 대화를 시작할 수 있게 한다. 관계 관리 기능을 넓게 만들기보다, 한 번의 초대로 빠르게 연결하는 데 집중한다.

#### MVP 동작

1. 사용자가 카카오·구글·네이버 간편 로그인 또는 이메일·비밀번호 회원가입으로 로그인한다.
2. 한 사용자가 대국방을 만든다.
3. 시스템이 일회성 초대 링크 또는 6자리 입장 코드를 만든다.
4. 상대가 링크 또는 코드를 통해 입장하면 두 사람의 대국방이 열린다. 초대 링크에서 일반 회원가입을 완료한 경우에는 자동 로그인 후 해당 방으로 바로 이동한다.
5. MVP에서는 진행 중인 대국 1개만 홈에서 다시 진입할 수 있다.

**MVP에서 단순화:** 친구 검색, 여러 상대 관리, 재초대·차단, 대국 기록 목록은 이후 확장한다.

---

### 6.2 AI 심판 — 보내기 전 문장 분석·추천

**목적:** 감정을 억누르는 것이 아니라, 사용자가 원하는 바를 더 전달 가능한 문장으로 고르게 돕는다.

#### 입력

- 직전 대화 맥락
- 사용자가 작성한 초안
- 선택 입력: “내가 진짜 원하는 것”

#### 출력 카드

| 카드 | 내용 |
| --- | --- |
| 이 수의 위험 | 상대의 방어를 부를 가능성, 단정·비난 표현 |
| 숨은 감정 | 초안에 담긴 서운함·불안·인정 욕구의 추정 |
| 추천 수 | 원래 의미를 살린 대안 문장 2~3개 |
| 지금은 멈춤 | 대화 과열 시 형세 파악 또는 무승부 제안 진입 |

#### UX 예시

```text
입력: "너는 내가 왜 화났는지도 모르잖아."

AI 심판
이 수는 상대의 방어를 유도할 가능성이 높습니다.

추천 수
"내가 화난 이유를 알아주길 바랐는데,
설명되지 않은 채 넘어가는 느낌이라 서운했어."

[원문 전송] [추천 수 두기] [형세 파악]
```

**중요 원칙:** AI는 상대의 마음을 사실처럼 단정하지 않는다. 모든 해석에는 `AI의 추정` 표기를 붙인다.

---

### 6.3 AI 문철 — 현재 형세 파악

**목적:** “누가 나쁜가”가 아니라, 지금 대화가 어디에서 멈췄고 어떤 선택이 유리한지 보이게 한다.

#### AI 문철 패널

```text
현재 형세: 난타전
대화 지속 가능성: 낮음
감정 과열도: 높음
서로 확인한 사실: 1개
서로 추측하고 있는 의도: 3개

해설
두 사람 모두 ‘무시당했다’는 감정을 다루지 못한 채,
사실관계의 승부로 대화를 옮기고 있습니다.

[무승부 제안] [계속 대국]
```

#### 다중 관점 표현

- **중립 심판:** 현재 쟁점과 사실관계
- **공감 해설:** 양측 메시지에 드러난 감정과 욕구
- **논리 해설:** 단정, 일반화, 대화 단절 지점
- **현실 코치:** 지금 시도할 수 있는 가장 작은 행동

여러 AI는 서로 다른 시각을 보여 주는 연출이며, 판정의 절대적 권위가 아니다.

---

### 6.4 무승부 협상 — 조건을 건 종료 제안

무승부는 단순히 “대화를 멈추자”가 아니다. 상대가 수락할 이유가 되는 행동을 붙여 보내는 협상 카드다. 조건 없이 무승부만 제안하는 것도 가능하다.

#### 제안 생성

```text
[무승부 제안]

이번 판을 무승부로 제안합니다.

조건 선택 (선택 사항)
[오늘 밥은 내가 사기]
[내일 산책 30분 먼저 제안하기]
[사과 카드 작성하기]
[상대가 회복 퀘스트 고르게 하기]
[직접 입력]

기한: [오늘] [내일]
[무승부 보내기]
```

#### 상대가 보는 화면

```text
⚑ 상대가 무승부를 제안했습니다.

제안 조건
오늘 식사는 상대가 대접합니다.

[무승부 수락] [조건 붙여 다시 제안] [계속 대국]
```

#### 카운터오퍼

```text
“밥은 좋지만, 내일 산책 30분도 먼저 제안해 줘.”
```

상대는 거절만 하지 않고 원하는 조건을 더해 다시 제안할 수 있다. 합의가 성립할 때까지 제안과 카운터오퍼가 이어진다.

#### 문구 원칙

- 수락: `🤝 무승부 성립. 합의한 미션이 생성되었습니다.`
- 거절: `무승부 협상 결렬. 대국은 계속됩니다.`
- 패배·벌점·강제의 언어는 사용하지 않는다.

---

### 6.5 미션 시스템 — 합의를 행동으로 바꾸기

#### 미션 소유 원칙

1. 조건을 제안한 사람에게 그 조건의 **개인 미션**이 생성된다.
2. 상대는 동의만 할 뿐, 제안자가 약속한 일을 대신 책임지지 않는다.
3. `같이 산책하기`처럼 공동 참여가 핵심인 조건만 공동 퀘스트가 된다.
4. 모든 미션의 기한은 **오늘 또는 내일**이다. 장기 약속을 점수화하지 않는다.

#### 예시

```text
A: “이번 판은 무승부로 하자. 오늘 밥은 내가 살게.”
B: 수락

→ A 개인 미션 생성
   [오늘] 식사 대접하기

B: “대신 내일 산책 30분도 먼저 제안해 줘.”
A: 수락

→ B가 제안한 조건이므로 B 개인 미션 생성
   [내일] 산책 30분 제안·실행하기
→ 둘이 함께 체크해야 하는 공동 퀘스트 연결
```

#### 미션 유형

| 유형 | 예시 | 제출 방식 | 완료 방식 |
| --- | --- | --- | --- |
| 사진 인증 | 밥 사기, 카페 가기, 산책하기 | 사람 얼굴이 없는 인증 사진 | AI 1차 확인 + 상대 승인 |
| 상대 확인 | 사과 카드, 먼저 연락하기 | 수행자가 완료 버튼 | 상대가 확인 또는 다시 요청 |
| 공동 체크인 | 같이 영화 보기, 같이 산책하기 | 양쪽 완료 버튼 | 둘 다 체크인 시 완료 |
| 시간 인증 | 오늘은 각자 쉬기 | 타이머 | 기한까지 유지 시 자동 완료 |
| 공개 인증 | 풍경·음식·손글씨 카드 | 안전한 사진 업로드 | AI 확인 + 상대 승인 + 양쪽 공개 동의 |

#### 상태 모델

```text
합의됨
→ 진행 중
→ 인증 제출
→ AI 확인 / 상대 확인 대기
→ 완료

인증 부족 또는 불이행
→ 다시 요청
→ 수정 인증 제출 또는 미션 포기
```

`다시 요청`은 벌점이 아니라 약속 이행 여부를 다시 확인하는 절차다.

## 7. 이후 확장 기능 상세

### 7.1 AI 대리전 — AI가 정리하는 비공개 협상

**목적:** 감정이 과열돼 직접 조건을 꺼내기 어려울 때, 각자의 AI가 사용자가 정한 범위 안에서 회복 조건의 초안을 조율한다. AI가 관계를 대신 결정하는 것이 아니라, 대화를 다시 시작할 수 있는 작은 합의안을 만든다.

#### 시작 조건과 진행

- 한쪽이 `AI 대리전 요청`을 보내고, 상대도 수락해야 시작된다.
- 각 사용자는 상대에게 공개되지 않는 개인 입력으로 `원하는 것`, `가능한 양보`, `하면 안 되는 것`을 작성한다.
- 양측 AI는 승인된 범위 안에서 조건을 교환하고, 합의 초안을 만든다. 기한은 오늘 또는 내일로 제한한다.

```text
[AI 대리전 준비]
원하는 것: [답장이 늦을 때 미리 알려주기]
가능한 양보: [오늘은 각자 쉬고 내일 다시 이야기하기]
수락하지 않을 조건: [비난하는 말 계속하기]

[내 AI에게 맡기기]
```

#### 결과와 승인

| 상태 | 의미 | 다음 행동 |
| --- | --- | --- |
| 조율 중 | AI들이 승인 범위 안에서 조건을 교환 중 | 진행 내용을 요약으로 확인 |
| 초안 도착 | 합의 가능한 조건 묶음이 생성됨 | 각자 수락 또는 수정 요청 |
| 한쪽 수정 요청 | 사용자 한 명이 조건 변경을 원함 | 해당 조건만 다시 조율 |
| 대리전 중단 | 어느 쪽이든 중단함 | 기존 대국으로 돌아가거나 무승부 직접 제안 |
| 양쪽 최종 수락 | 당사자가 모두 초안을 승인함 | 무승부 성립 및 미션 생성 |

#### 안전·권한 원칙

- AI는 사용자가 사전에 입력·승인한 조건 밖의 약속, 금전 지출, 만남, 연락을 제안하거나 확정하지 않는다.
- 상대의 비공개 입력 원문은 전달하지 않고, 합의에 필요한 조건만 중립적인 문장으로 요약한다.
- 한쪽의 수락만으로는 합의가 성립하지 않으며, 두 사람이 최종 화면에서 각각 승인해야 한다.
- 어느 쪽이든 언제나 대리전을 중단하고 직접 대화로 돌아갈 수 있다.
- 폭력·협박·통제·자해 위험이 감지되면 대리전을 시작하거나 계속하지 않고 안전 안내를 우선한다.

---

### 7.2 인증 게시판 — 회복 행동의 익명 피드

미션 완료 뒤 사용자는 선택적으로 인증을 공개할 수 있다. 공개는 반드시 양쪽의 동의가 필요하다.

#### 게시판 규칙

- 얼굴, 이름, 대화 화면, 정확한 위치, 갈등 내용은 게시하지 않는다.
- 음식·풍경·손글씨 카드처럼 미션의 결과물만 인증한다.
- 지역은 선택 태그만 제공하고, 정확한 위치 정보는 제거한다.
- 공개의 목적은 “누가 싸웠는가”가 아니라 “어떤 회복 행동을 했는가”를 공유하는 데 있다.

```text
익명 커플 · 용인
☕ 카페 화해 퀘스트 완료
연속 회복 3일
```

---

### 7.3 개인·공용 대국 복기와 관계 관리

- **개인 복기:** 사용자가 자신의 전송 메시지, 원문 초안, AI 심판 결과를 바탕으로 표현 선택과 다음에 시도할 한 수를 돌아본다. 본인의 비공개 기록만 사용하며 상대에게 공개하지 않는다.
- **공용 복기:** 두 사람이 함께 본 전송 메시지, 무승부 합의, 미션 수행 결과만 바탕으로 쟁점·전환점·효과 있었던 선택을 정리한다. 상대의 초안·AI 심판 기록은 사용하거나 노출하지 않는다.
- 개인·공용 복기는 모두 MVP 이후 확장 기능이다. 누가 옳았는지나 승패를 판정하지 않는다.
- **관계 관리:** 여러 대국 목록, 친구 검색, 재초대, 차단과 대국 기록 관리를 제공한다.

## 9. 해커톤 MVP 범위

상세 구현 기준은 [MVP 명세](1_MVP_명세.md)를 따른다.

개발 단계와 완료 기준은 [마일스톤 계획](2_마일스톤_계획.md)을 따른다.

### 반드시 구현할 경험

```text
대국방 생성 → 초대 링크/코드로 상대 입장
→ 갈등 메시지 작성
→ AI 훈수
→ AI 문철 형세 판정
→ 조건을 단 무승부 제안
→ 상대의 수락 또는 카운터오퍼
→ 제안자 개인 미션 생성
→ 상대 완료 확인
```

### 데모용 고정 시나리오

```text
상황: 한 사람이 답장이 늦었다며 서운함을 표현한다.

1. 사용자가 날선 답장을 작성한다.
2. AI 심판이 부드러운 대안과 형세 파악을 추천한다.
3. AI 문철이 난타전 판정을 낸다.
4. A가 “오늘 밥은 내가 살게” 조건으로 무승부를 제안한다.
5. B가 “내일 산책도 먼저 제안해 줘”라고 카운터오퍼한다.
6. A가 수락한다.
7. A와 B의 개인/공동 미션이 생성되고, 음식 사진 인증 화면으로 이어진다.
```

### MVP에서 제외할 것

- AI 대리전
- 공개 인증 피드와 개인·공용 대국 복기
- 여러 대국 목록, 친구 검색, 재초대·차단 등 관계 관리
- 외부 메신저의 실제 연동
- 장기간 관계 점수·랭킹
- 완전한 위치 기반 맛집 추천
- 모든 갈등 유형에 대한 정교한 AI 모델
- 공개 커뮤니티의 실서비스 운영

## 10. AI와 데이터 설계 원칙

### AI 출력의 역할

| 기능 | AI가 하는 일 | AI가 하지 않는 일 |
| --- | --- | --- |
| AI 심판 | 문장 위험도와 대안 제시 | 상대의 의도를 확정하지 않음 |
| AI 문철 | 쟁점·감정·대화 패턴 요약 | 누가 절대적으로 잘못했는지 판결하지 않음 |
| AI 대리전 | 승인된 범위 안에서 합의 초안 조율 | 사용자의 동의 없이 약속·연락·만남을 확정하지 않음 |
| 미션 추천 | 갈등 상태에 맞는 작은 행동 제안 | 화해나 만남을 강요하지 않음 |
| 사진 인증 | 얼굴·개인정보 노출, 미션 대상 여부 확인 | 사진을 공개하도록 강요하지 않음 |

### 안전 장치

- AI 분석은 `추정`임을 항상 표시한다.
- 폭력, 협박, 통제, 자해 위험 표현이 감지되면 게임 연출을 멈추고 안전 안내를 우선한다.
- 대화 로그·사진·지역 정보는 기본 비공개다.
- 전송된 메시지의 원문 초안과 AI 심판 결과는 작성자에게만 비공개로 보관하며, 상대에게는 전송된 메시지 본문만 공개한다.
- 공개 게시물은 양쪽의 명시적 동의를 필요로 한다.
- 상대를 조종하거나 모욕하는 답장은 추천하지 않는다.

## 11. 발표 구조

> “커플 관계에서 더 어려운 순간은, 꺼내야 할 문제를 계속 미루는 순간입니다.”

### 문제

> “상처를 줄까 봐, 감정을 설명할 에너지가 없어서 우리는 문제를 꺼내지 못합니다.”

### 해결

> “커플들이 집착하는 AI 심판이 되었다는 감정과 대화 사이에서 한 번 멈추게 하고, 내 본심을 전달 가능한 말로 바꿔 줍니다.”

### 데모

```text
날선 메시지 → AI 훈수 → AI 문철 → 조건부 무승부 → 미션 생성 → 인증
```

### 차별점

> “가볍게 대화를 시작할 때는 재미있는 대국 장치로, 진지한 대화가 필요할 때는 미뤄진 말을 꺼내게 하는 관계의 완충 장치입니다.”

### 클로징

> “싸움은 무승부로, 우리는 계속.”

### 이전 임시안

- **고스트 연애왕이 되었다**
  - AI가 대화방 뒤에서 훈수하는 구조의 의미

### 웹소설 제목형

- 커플들이 집착하는 갈등중재어플이 되었다
- 무승부 제안을 눌렀을 뿐인데
- 싸우다 보니 AI 연애대국이 되었다

- 남친과 싸우다 AI 심판을 소환했다
- 싸움은 AI에게 맡기고 밥을 먹으러 갔다
- 우리는 오늘도 AI에게 판정받는다
- 연애 싸움에 100명의 AI가 참전했다
- 화해 퀘스트를 깨야 대화방이 열린다
- AI로 연애천재가 되었다
- 연애 훈수 100배 AI를 얻었다
- 연애를 AI로 배웠다
- 연애갈등 속 지나가던 AI가 되었다
- 심각한 AI 연애대국 중독입니다
- 연애훈수 AI가 너무 유능함
- 연애갈등훈수 AI인데 커플들이 집착한다

## 13. 최종 피치

> **커플들이 집착하는 AI 심판이 되었다**는 커플이 AI 훈수와 대국 문법으로 가볍게 대화를 시작하거나, 필요할 때 감정과 본심을 정리해 전달 가능한 말을 고르게 돕는 AI 메신저다. AI 문철의 형세 파악, 조건을 건 무승부 협상과 회복 미션을 통해 미뤄진 대화를 현실의 행동까지 연결한다.
