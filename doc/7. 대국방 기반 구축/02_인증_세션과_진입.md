# M2 페이즈 2 — 인증·세션과 진입

> 상태: 예정

> 작업 권한 경계: 팀원은 코드만 수정한다. Supabase·Vercel·Google Cloud·Kakao Developers 설정과 비밀값은 프로젝트 소유자 계정에서만 관리하며, Client Secret은 저장소·채팅·`.env.local`에 기록하지 않는다.

## 목적과 범위

Supabase Auth의 이메일·비밀번호, 카카오, 구글 인증을 연결하고, 로그인 상태에 따라 메인·내 프로필·초대 링크·대국방 경로를 안전하게 분기한다.

## 구현 항목

- 메인에서 진입하는 `내 프로필` 화면과 `profiles`의 표시 이름 생성·수정 최소 경계, 인증 사용자 연결
- 표시 이름 이니셜과 사용자별 기본 색상으로 만든 아바타 표시 컴포넌트. 이후 선택적 `avatarUrl` 표시 경계만 두고, 사진 업로드·Storage는 만들지 않음
- 이메일·비밀번호 회원가입·로그인, 카카오·구글 로그인 버튼, 로그아웃·세션 복원 UI
- 로그인 필요 경로의 서버·클라이언트 가드와 메인 진입
- 미로그인 초대 링크의 원래 경로 보존, 인증 성공 뒤 해당 링크 복귀
- 인증 전 초대 유효성·방·멤버·메시지 정보를 조회하지 않는지 확인
- Supabase Auth의 카카오·구글 공급자 활성화, Client ID·Secret의 대시보드 비밀값 등록, 로컬·Vercel Redirect URL 허용 목록 설정
- 카카오 동의 항목에서 `profile_nickname`을 요청하고, `account_email`은 선택으로 요청한다. 이메일을 제공하지 않아도 Supabase 공급자의 이메일 없는 사용자 허용 설정과 표시 이름 처리로 로그인·이용이 가능해야 한다.

## 결과 화면

| 상태 | 표시 | 다음 행동 |
| --- | --- | --- |
| 인증 전 앱 | 이메일 로그인·회원가입, 카카오·구글 로그인 | 성공 뒤 메인 |
| 인증 전 초대 링크 | 로그인·회원가입만 | 성공 뒤 원래 초대 경로 |
| 인증 완료·진행 중 방 없음 | 메인·대국 시작 | 방 생성 또는 코드 입장 |
| 인증 완료·진행 중 방 있음 | 현재 방 재개 | 새 방·코드 입장 차단 |
| 내 프로필 | 현재 표시 이름, 기본 아바타, 저장·취소·로그아웃 | 저장 뒤 메인, 취소 뒤 메인, 로그아웃 뒤 인증 전 |

## 테스트와 완료 기준

- 새 이메일 계정 A·B로 가입·로그인·로그아웃·새로고침 뒤 세션 복원을 확인한다.
- 카카오·구글 계정으로 로그인한 뒤 Supabase 세션·`profiles` 생성·표시 이름 처리와 로그아웃을 확인한다.
- 로그인한 사용자가 메인에서 `내 프로필`을 열고 표시 이름을 저장·취소할 수 있는지, 변경 뒤 새 방의 표시 이름만 바뀌고 기존 방의 `room_display_name`은 유지되는지 확인한다.
- 프로필·메인·대국방의 기본 아바타가 같은 사용자에게 일관되게 표시되고, 이미지 업로드 동작이나 Storage 요청이 없는지 확인한다.
- 로컬 Supabase 콜백, Vercel Production 콜백, 보존 초대 링크 복귀를 각각 확인한다.
- 미로그인 링크 접근 시 네트워크 응답과 화면 어느 쪽에도 초대의 유효성·방 내부 정보가 없음을 확인한다.
- 인증 뒤 보존한 링크로 복귀하며, 아직 이 단계에서는 수락 처리를 페이즈 3 명령에 위임한다.
