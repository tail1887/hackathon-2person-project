# M2 페이즈 2 — 인증·세션과 진입

> 상태: 인증·프로필 운영 검증 완료 · 보존 초대 경로는 페이즈 3 통합 검증 · 2026-09-20

> 작업 권한 경계: 팀원은 코드만 수정한다. Supabase·Vercel·Google Cloud 설정과 비밀값은 프로젝트 소유자 계정에서만 관리하며, Client Secret은 저장소·채팅·`.env.local`에 기록하지 않는다.

## 목적과 범위

Supabase Auth의 이메일·비밀번호와 구글 인증을 연결하고, 로그인 상태에 따라 메인·내 프로필·초대 링크·대국방 경로를 안전하게 분기한다.

## 구현 항목

- 메인에서 진입하는 `내 프로필` 화면과 `profiles`의 표시 이름 생성·수정 최소 경계, 인증 사용자 연결
- 표시 이름 이니셜과 사용자별 기본 색상으로 만든 아바타 표시 컴포넌트. 이후 선택적 `avatarUrl` 표시 경계만 두고, 사진 업로드·Storage는 만들지 않음
- 이메일·비밀번호 회원가입·로그인, 구글 로그인 버튼, 로그아웃·세션 복원 UI
- 로그인 필요 경로의 서버·클라이언트 가드와 메인 진입
- 미로그인 초대 링크의 원래 경로 보존, 인증 성공 뒤 해당 링크 복귀
- 인증 전 초대 유효성·방·멤버·메시지 정보를 조회하지 않는지 확인
- Supabase Auth의 구글 공급자 활성화, Client ID·Secret의 대시보드 비밀값 등록, 로컬·Vercel Redirect URL 허용 목록 설정

## 구현 결과

- `web/src/app/auth/`에 이메일·비밀번호 로그인·회원가입과 서버 OAuth 콜백 경로를 추가했다. 콜백은 인증 코드를 서버에서 한 번만 세션으로 교환하고, 미로그인 접근은 `web/src/proxy.ts`가 `/auth`로 보내며 안전한 내부 경로만 `next`로 보존한다.
- `web/src/app/page.tsx`와 `web/src/app/profile/`에 로그인 뒤 메인과 내 프로필 화면을 추가했다. 표시 이름의 이니셜·결정적 기본 색상 아바타를 표시하며 사진 업로드·Storage 요청은 만들지 않았다.
- `supabase/migrations/20260920000100_create_profiles.sql`은 `profiles` 테이블, 본인 조회 RLS, 신규·기존 인증 계정의 프로필 생성 트리거를 만든다. 프로필 갱신은 `supabase/functions/profile-update/`가 인증 사용자만 대상으로 처리한다.
- 원격 Supabase에 마이그레이션과 Edge Function을 배포했고, Vercel Production에 공개 Supabase URL·Publishable key를 설정했다. Google 로그인은 운영 주소에서 세션 교환·`profiles` 생성·메인 및 내 프로필 조회까지 확인했다. OAuth Client Secret과 Service Role 키는 계속 대시보드·함수 비밀값에만 둔다.
> 변경 이력: Kakao OAuth의 KOE205 검사 결과는 M2 검증보고서 v3·v4에 보존한다. [D2026-09-20-06](../1.%20의사결정%20로그/2026-09-20_의사결정_로그.md)에 따라 Kakao OAuth와 관련 외부 설정은 현재 MVP 범위에서 제외한다.

## 테스트와 완료 기준

- 새 이메일 계정의 가입·로그인·로그아웃·새로고침 뒤 세션 복원은 사용자 직접 확인으로 완료했다. A·B 초대 연계는 페이즈 3 이후 확인한다.
- 구글 계정과 이메일·비밀번호로 로그인한 뒤 Supabase 세션·`profiles` 생성·표시 이름 처리와 로그아웃을 확인한다.
- 로그인한 사용자가 메인에서 `내 프로필`을 열고 표시 이름을 저장·취소할 수 있는지, 변경 뒤 새 방의 표시 이름만 바뀌고 기존 방의 `room_display_name`은 유지되는지 확인한다.
- 프로필·메인·대국방의 기본 아바타가 같은 사용자에게 일관되게 표시되고, 이미지 업로드 동작이나 Storage 요청이 없는지 확인한다.
- 로컬 Supabase 콜백, Vercel Production 콜백, 보존 초대 링크 복귀를 각각 확인한다.
- 미로그인 링크 접근 시 네트워크 응답과 화면 어느 쪽에도 초대의 유효성·방 내부 정보가 없음을 확인한다.
- 인증 뒤 보존한 링크로 복귀하며, 아직 이 단계에서는 수락 처리를 페이즈 3 명령에 위임한다.
