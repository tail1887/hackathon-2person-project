# M2 페이즈 2 — 인증·세션과 진입

> 상태: 예정

## 목적과 범위

Supabase Auth의 이메일·비밀번호, 카카오, 구글 인증을 연결하고, 로그인 상태에 따라 메인·초대 링크·대국방 경로를 안전하게 분기한다.

## 구현 항목

- `profiles`의 표시 이름 생성·수정 최소 경계와 인증 사용자 연결
- 이메일·비밀번호 회원가입·로그인, 카카오·구글 로그인 버튼, 로그아웃·세션 복원 UI
- 로그인 필요 경로의 서버·클라이언트 가드와 메인 진입
- 미로그인 초대 링크의 원래 경로 보존, 인증 성공 뒤 해당 링크 복귀
- 인증 전 초대 유효성·방·멤버·메시지 정보를 조회하지 않는지 확인
- Supabase Auth의 카카오·구글 공급자 활성화, Client ID·Secret의 대시보드 비밀값 등록, 로컬·Vercel Redirect URL 허용 목록 설정
- 카카오 동의 항목에서 `profile_nickname`과 `account_email`을 요청하고, 이메일 제공 불가 사용자의 가입 허용 여부를 Supabase 공급자 설정과 함께 검증

## 결과 화면

| 상태 | 표시 | 다음 행동 |
| --- | --- | --- |
| 인증 전 앱 | 이메일 로그인·회원가입, 카카오·구글 로그인 | 성공 뒤 메인 |
| 인증 전 초대 링크 | 로그인·회원가입만 | 성공 뒤 원래 초대 경로 |
| 인증 완료·진행 중 방 없음 | 메인·대국 시작 | 방 생성 또는 코드 입장 |
| 인증 완료·진행 중 방 있음 | 현재 방 재개 | 새 방·코드 입장 차단 |

## 테스트와 완료 기준

- 새 이메일 계정 A·B로 가입·로그인·로그아웃·새로고침 뒤 세션 복원을 확인한다.
- 카카오·구글 계정으로 로그인한 뒤 Supabase 세션·`profiles` 생성·표시 이름 처리와 로그아웃을 확인한다.
- 로컬 Supabase 콜백, Vercel Production 콜백, 보존 초대 링크 복귀를 각각 확인한다.
- 미로그인 링크 접근 시 네트워크 응답과 화면 어느 쪽에도 초대의 유효성·방 내부 정보가 없음을 확인한다.
- 인증 뒤 보존한 링크로 복귀하며, 아직 이 단계에서는 수락 처리를 페이즈 3 명령에 위임한다.
