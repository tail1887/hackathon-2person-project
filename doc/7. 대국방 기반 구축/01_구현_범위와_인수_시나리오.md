# M2 페이즈 1 — 구현 범위와 인수 시나리오

> 상태: 완료 · 기준 대조 완료 · 2026-09-20

## 목적

M2에서 만들 데이터·화면·실시간 경계를 M3·M4 기능과 분리하고, 두 사용자가 실제로 검증할 최소 시나리오를 고정한다.

## 구현 단위

| 단위 | M2 책임 | 이후 단계로 남기는 책임 |
| --- | --- | --- |
| 인증·내 프로필 | 이메일·비밀번호 가입·로그인·로그아웃, 카카오·구글 OAuth, 세션 복원, 보호 경로, 표시 이름 확인·수정 | M3 이후 인증 수단 추가 |
| 대국방 | `waiting`·`active` 방 조회, 멤버 표시, 입장 상태 | 종료 대국 기록·협상 상태 |
| 초대 | 링크 토큰·6자리 코드, 로그인 뒤 원자 수락, 4개 안전한 실패 사유 | 초대 만료·해제 관리 화면 |
| 메시지 기반 | 공용 메시지 저장 순서·조회·`message.sent` 동기화 | AI 심판을 거친 사용자 전송 UI와 상세 기록 |
| 실시간 | 상대 입장·공용 순번 이벤트·30초 복구 | 개인 초안·AI 분석의 `private_revision` 복구 |

## 고정 인수 시나리오

1. A가 이메일·비밀번호로 가입·로그인하고 대국방을 만든다.
2. A는 초대 링크와 6자리 코드를 확인하고 상대 입장을 기다린다.
3. B가 미로그인 상태로 링크를 열면 로그인 화면만 본다. 인증을 마치면 원래 링크로 돌아간다.
4. B가 초대를 수락하면 멤버 생성·초대 사용·방 활성화가 한 번에 확정된다. A와 B는 같은 방 화면을 본다.
5. 두 브라우저는 상대 입장과 테스트용 공용 메시지 이벤트를 같은 순서로 반영한다.
6. 제3 사용자는 링크·코드 실패나 방 URL을 통해 멤버·메시지·상태를 읽거나 바꿀 수 없다.
7. 한 사용자가 진행 중인 다른 방이 있는 경우 새 방 생성·초대 수락이 거절되고, 정해진 안내만 보인다.

## 시나리오 추적표

| 시나리오 | 구현 페이즈 | 기준 계약·규칙 | 검증 근거 |
| --- | --- | --- | --- |
| A의 이메일·카카오·구글 로그인과 방 생성 진입 | 02 → 03 | 인증 전 비공개, `room.create`, 진행 중 방 1개 제한 | 세 인증 방식의 세션·로그아웃·메인 진입, `active_room_exists` |
| A의 내 프로필 표시 이름 수정 | 02 | 본인만 `display_name` 수정, 기존 방 표시 이름 스냅샷 유지 | 저장·취소·로그아웃, 새 방 표시 이름 반영, 기존 방 표시 이름 유지 |
| A의 초대 대기와 링크·6자리 코드 제공 | 03 → 04 | 활성 초대 1개, 링크 토큰·코드, `waiting` 방 | 초대 원문 비공개, A 대기 화면·상대 입장 이벤트 |
| B의 미로그인 링크 로그인·원래 경로 복귀 | 02 → 03 | 인증 전 초대 조회 금지, 인증 뒤 `invite.accept` | 인증 전 네트워크·화면 비노출, 로그인 뒤 수락 |
| B의 링크·코드 수락과 A·B 방 활성화 | 03 → 04 | 멤버 생성·초대 사용·방 `active` 원자 처리, `room.member_joined` | 동시 수락·정원 초과, 두 브라우저 대국방 전환 |
| 공용 메시지 순서와 재연결 복구 | 04 | `room_revision`, `message.sent`, 변경 조회·스냅샷·30초 복구 | 늦은 입장·일시 단절 뒤 중복·역전 없는 동기화 |
| 제3 사용자와 실패 초대의 정보 차단 | 03 → 05 | RLS, 4개 안전한 초대 오류, 방 내부 정보 비노출 | 직접 조회·변경 거절, 오류별 화면에 방 정보 없음 |
| 진행 중 방 충돌 | 03 → 05 | `room.create`·`invite.accept`의 `active_room_exists` | 상태 변경 없음, 현재 방 재개 안내 |

## 완료 기준

- 각 시나리오가 페이즈 2~5의 구현·테스트 항목에 하나 이상 연결된다. 위 추적표로 연결을 확인했다.
- M3 전까지 사용자 화면에 AI 심판을 건너뛰는 메시지 전송 동작을 제공하지 않는다.
- M2 범위에 이메일·비밀번호와 카카오·구글 OAuth가 모두 포함됨을 확인했다.

## 기준 대조 결과

- 충돌 없음: M1.3의 `Next.js + Supabase Auth + Edge Functions` 선택과 M1.2의 명령·이벤트 계약은 M2 페이즈 2~4의 책임 경계와 일치한다.
- 구현 전제: OAuth Client ID·Secret과 허용 콜백 URL은 실제 공급자 콘솔·Supabase 대시보드에서 설정해야 한다. 비밀값이 준비되지 않은 경우 페이즈 2는 해당 검증을 완료로 표시하지 않는다.
- 이관 확인: AI 심판을 거친 `message.send`, 비공개 초안·`private_revision`은 M3에, 협상·미션·종료 방 흐름은 M4에 남긴다.
- 인증 정책 반영: 카카오 인증 성공 사용자는 이메일 동의가 없어도 이용할 수 있으며, 이메일은 이메일·비밀번호 회원가입에만 필수다. [D2026-09-20-02](../1.%20의사결정%20로그/2026-09-20_의사결정_로그.md)을 따른다.
