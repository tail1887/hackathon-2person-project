# M2 대국방 기반 구축

> 상태: 계획 완료 · 구현 시작 전 · 2026-09-20

이 폴더는 M1.3에서 준비한 Next.js·Supabase·Vercel 구조 위에, 로그인한 두 사용자가 하나의 대국방에 안전하게 연결되고 같은 공용 상태를 보게 하는 M2 구현 계획이다. AI 심판·개인 형세·AI 문철은 M3, 무승부 협상·미션은 M4에서 구현한다.

- [마일스톤 계획](../2_마일스톤_계획.md#m2-대국방-기반-구축): M2 목표·완료 기준
- [MVP 명세](../1_MVP_명세.md#31-시작대국방-연결): 로그인·초대·대국방 제품 규칙
- [시스템·데이터 정의](../3_시스템_데이터_정의.md): 두 명 제한, 권한, 원자 전이, 순번 규칙
- [화면 상태 설계](../5.%20인터페이스%20설계/02_화면_상태_설계.md): 로그인·초대·대국방·재연결 화면 상태

- [M1.3 완료 검증](../3.%20검증보고서/M1.3_기술_스택·프로젝트_뼈대/v4_검증보고서.md): 로컬·배포 실행 기반

## 2. 범위와 제외 범위

### M2에서 구현

- 이메일·비밀번호, 카카오·구글 OAuth 인증과 세션에 따른 로그인 전/후 경로 분기
- 사용자 프로필, 대국방, 멤버, 초대, 공용 메시지의 최소 데이터·RLS·원자 명령
- 초대 링크와 6자리 코드, 로그인 뒤 실패 사유 4종의 안전한 안내
- 대국방 초기 조회, 상대 입장 이벤트, 공용 메시지 순서 동기화와 재연결 복구
- 두 브라우저 통합 시나리오와 권한·실패 흐름 검증

### M2에서 제외

- 사용자에게 노출되는 메시지 전송 버튼과 AI를 건너뛰는 전송 흐름
- AI 심판·개인 형세·AI 문철(M3), 무승부 협상·미션(M4)
- 사진 첨부·네이버 로그인(MVP 제외)

M2에서는 실시간 공용 메시지 저장·수신 기반을 만들되, 제품 화면의 메시지 확정은 M3에서 `확인 → AI 심판 → 원문/추천문 선택` 규칙과 함께 연다. 이 원칙으로 필수 AI 심판을 우회하는 임시 사용자 흐름을 만들지 않는다.

## 4. 실행 순서와 경계

1. 페이즈 2와 3은 데이터 모델·명령과 화면 진입을 함께 작은 단위로 구현한다. 브라우저는 RLS를 통과한 조회만 하고, 방 생성·초대 수락처럼 상태를 바꾸는 명령은 Edge Function 또는 RPC에서 원자 처리한다.
2. 페이즈 4는 `room_revision`을 기준으로 공용 상태를 동기화한다. `private_revision`과 초안·AI 분석은 M3에서 추가하며 M2의 공용 메시지 이벤트에 섞지 않는다.
3. 테스트용 두 사용자·메시지는 테스트 코드 또는 로컬 데이터로만 만들고, 제품 UI에 목업 전환·직접 전송 제어를 이관하지 않는다.
4. 새 정책 결정이 필요하면 구현 전에 의사결정 로그부터 갱신한다. 구현 중 발견한 결함은 검증보고서 또는 보완계획에 기록한다.

## 5. M2 완료 후

M2가 끝나면 두 브라우저의 대국방 연결·권한·공용 동기화가 안정된 상태에서 M3의 AI 심판 필수 전송 흐름을 붙인다. M2의 공용 메시지 저장 명령은 M3에서 최신 `normal` AI 분석과 원문 해시 검증을 추가해 완성한다.
