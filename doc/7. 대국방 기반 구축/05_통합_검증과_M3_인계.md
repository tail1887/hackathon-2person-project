# M2 페이즈 5 — 통합 검증과 M3 인계

> 상태: 수동 테스트 대체 · 2026-09-20

## 목적

두 사용자 고정 시나리오를 로컬 Supabase와 Vercel 배포 환경에서 검증하고, M3 AI 심판 구현이 안전하게 이어질 경계를 확정한다.

## 현재 처리

시간 제약으로 별도 자동·통합 검증은 수행하지 않고 프로젝트 소유자의 수동 테스트로 대체했다. 이 문서의 시나리오는 M5 데모 QA에서 다시 확인한다. M3는 [D2026-09-20-09](../1.%20의사결정%20로그/2026-09-20_의사결정_로그.md)에 따라 이 상태에서 시작한다.

## 검증 시나리오

1. A 초대 발급 → 초대 링크·코드 확인 → 대기(대국방 없음)
2. B 미로그인 링크 접근 → 로그인 → 원래 링크 복귀 → 초대 수락
3. B 수락 순간 A·B 대국방 원자 생성 → 상대 입장·공용 상태 동기화
4. 테스트용 공용 메시지 이벤트의 순서 동일성
5. 만료/해제, 사용됨·정원 초과, 진행 중 방 존재, 유효하지 않음의 안전한 안내
6. 제3 사용자 권한 차단과 재연결 30초 복구·수동 재시도
7. Vercel Preview/Production에서 환경 변수 누락 시 안전한 안내와 비밀값 비노출

## M3 인계 조건

- `messages` 저장 명령에 AI 분석 검증을 추가할 위치와 테스트용 생성 경로 제거 시점을 명확히 한다.
- `private_revision` 기반 초안·AI 분석 전용 데이터를 공용 `room_revision`과 분리한다.
- OpenAI 키는 브라우저가 아닌 Supabase Edge Function 비밀값으로만 연결한다.
- M2 검증보고서에 통과·미통과·남은 위험을 기록하고, 통과 뒤에만 M3 구현을 시작한다.
