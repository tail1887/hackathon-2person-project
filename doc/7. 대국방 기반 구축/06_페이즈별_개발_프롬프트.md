# M2 페이즈별 개발 프롬프트

> 상태: 사용 가능 · 2026-09-20

아래 프롬프트는 각 M2 페이즈를 실제 구현할 때 그대로 사용할 수 있다. 기준 문서에 없는 제품 정책·권한·공개 범위·비용 결정을 임의로 확정하지 않는다. 그런 항목은 `결정 필요`로 분리하고, 중요한 결정은 구현 전에 의사결정 로그부터 갱신한다.

## 공통 작업 원칙

- 먼저 `AGENTS.md`, `doc/2_마일스톤_계획.md`, 최신 의사결정 로그, 해당 페이즈 문서를 읽는다.
- 기존 변경과 범위 밖 코드·문서를 보존한다. 목업의 사용자 전환·직접 전송 제어를 제품 UI로 옮기지 않는다.
- OpenAI 키·Supabase service role·OAuth Client Secret은 브라우저·저장소·로그에 넣지 않는다.
- 구현 뒤 가장 좁은 테스트 또는 실제 동작 확인을 수행하고, 결과·미검증 항목을 페이즈 문서와 개발일지에 기록한다.
- 중요한 정책 변경이 없다면 의사결정 로그를 새로 만들지 않는다. 변경한 파일은 작업 마무리에 `main`에 커밋·푸시한다.

## 01. 구현 범위와 인수 시나리오

```text
이 저장소의 M2 대국방 기반 구축 페이즈 1을 진행해줘.

먼저 다음 기준을 읽고 충돌·누락을 확인해줘.
- AGENTS.md
- doc/2_마일스톤_계획.md
- doc/1. 의사결정 로그/README.md와 최신 날짜별 로그
- doc/1_MVP_명세.md
- doc/3_시스템_데이터_정의.md
- doc/5. 인터페이스 설계/02_화면_상태_설계.md
- doc/5. 인터페이스 설계/03_요청_응답_실시간_이벤트_계약.md
- doc/7. 대국방 기반 구축/README.md
- doc/7. 대국방 기반 구축/01_구현_범위와_인수_시나리오.md

목표는 M2 범위를 인증·초대·대국방 공용 상태·실시간 동기화로 고정하고, A·B·제3 사용자의 인수 시나리오를 구현·테스트 항목에 추적 가능하게 연결하는 것이다.

1. 기존 기준과 M2 페이즈 문서를 대조해 구현 대상, M3·M4 이관 대상, MVP 제외 대상을 확인한다.
2. A 방 생성, B 미로그인 링크 로그인·복귀·수락, 두 브라우저 동기화, 제3 사용자 차단, 진행 중 방 충돌을 테스트 단위로 분해한다.
3. M3의 AI 심판을 건너뛰는 사용자용 전송 UI가 M2에 생기지 않도록 메시지 저장 기반과 제품 전송 화면의 경계를 확인한다.
4. 기준에 없는 항목만 `결정 필요`로 분리하고, 결과를 해당 페이즈 문서에 반영한다.

이 페이즈에서는 코드 구현이나 새 제품 정책 결정을 하지 마.
```

## 02. 인증·세션과 진입

```text
이 저장소의 M2 대국방 기반 구축 페이즈 2를 구현해줘.

먼저 다음 기준을 읽어줘.
- AGENTS.md, doc/2_마일스톤_계획.md
- doc/1. 의사결정 로그/README.md와 최신 날짜별 로그
- doc/1_MVP_명세.md의 시작·대국방 연결 규칙
- doc/3_시스템_데이터_정의.md의 사용자·표시 이름·초대 공개 범위
- doc/5. 인터페이스 설계/02_화면_상태_설계.md
- doc/5. 인터페이스 설계/03_요청_응답_실시간_이벤트_계약.md
- doc/7. 대국방 기반 구축/02_인증_세션과_진입.md

목표는 이메일·비밀번호, 카카오 OAuth, 구글 OAuth 인증과 세션 복원을 연결하고, 메인에서 내 프로필 표시 이름을 안전하게 수정하며, 미로그인 초대 링크가 초대 정보를 노출하지 않은 채 로그인 뒤 원래 경로로 복귀하게 만드는 것이다.

1. Next.js·Supabase SSR 경계에서 브라우저·서버 세션을 처리하고 로그인·회원가입·로그아웃·세션 복원 화면을 구현한다.
2. 이메일·비밀번호와 `google`·`kakao` OAuth 시작·콜백을 연결한다.
3. 메인에서 진입하는 내 프로필 화면에서 profiles의 표시 이름을 확인·수정·저장·취소하고 로그아웃할 수 있게 한다. 내부 user.id·인증 제공자 식별자·비밀번호를 표시하지 않는다. 변경 뒤 기존 방의 `room_display_name`은 바꾸지 않는다.
4. 보호 경로와 보존 초대 경로 복귀를 구현한다. 인증 전에는 초대 조회·수락을 호출하지 않는다.
5. Supabase Auth 공급자 활성화, Client ID·Secret, Supabase 콜백, 로컬·Vercel Redirect URL 설정을 문서화한다. 비밀값은 대시보드·환경 변수에만 둔다.
6. 이메일 A·B, 카카오, 구글 로그인 각각의 세션·로그아웃·새로고침 복원, 내 프로필 표시 이름 저장·취소, 미로그인 링크 비노출을 확인한다.

OAuth 콘솔 계정·키가 없으면 임의 값으로 우회하지 말고 필요한 설정을 정확히 보고해줘. 카카오 account_email은 선택이며, 인증 성공 사용자는 이메일이 없어도 이용 가능하게 Supabase의 이메일 없는 사용자 허용 설정과 표시 이름 처리를 적용해줘. 결과를 페이즈 문서·개발일지에 기록하고 main에 커밋·푸시해줘.
```

## 03. 방·초대·권한과 명령

```text
이 저장소의 M2 대국방 기반 구축 페이즈 3을 구현해줘.

먼저 AGENTS.md, 최신 의사결정 로그, MVP 명세의 방 생성·초대 수락 규칙, 시스템·데이터 정의의 방·멤버·초대 상태, M1.2 요청·이벤트 계약, doc/7. 대국방 기반 구축/03_방_초대_권한과_명령.md를 읽어줘.

목표는 방 밖 비공개, 방당 두 명 제한, 진행 중 방 하나 제한, 초대 수락의 원자 처리를 Supabase 데이터 계층에서 강제하는 것이다.

1. profiles, rooms, room_members, invites, messages의 M2 최소 마이그레이션·인덱스를 만든다.
2. RLS로 방 멤버만 공용 데이터를 읽게 하고, 초대 원문과 상태 변경을 브라우저 직접 쓰기에서 보호한다.
3. room.create와 invite.accept는 Edge Function으로만 노출한다. 원자 처리가 필요하면 Edge Function 내부에서 PostgreSQL 트랜잭션·RPC를 호출한다.
4. invite.accept는 invite_expired_or_revoked, invite_used_or_full, active_room_exists, invalid_invite만 반환하며 방 내부 정보는 어떤 실패에도 포함하지 않는다.
5. 링크·6자리 코드 입장을 로그인 뒤 명령에 연결한다.
6. A·B 동시 수락, 이미 찬 방, 다른 진행 중 방, 제3 사용자 직접 조회·변경을 테스트한다.

AI 분석·협상·미션 테이블은 추가하지 마. 구현·검증 결과를 페이즈 문서·개발일지에 기록하고 main에 커밋·푸시해줘.
```

## 04. 실시간 대국방과 메시지 기반

```text
이 저장소의 M2 대국방 기반 구축 페이즈 4를 구현해줘.

먼저 AGENTS.md, MVP 명세의 대국방 규칙, 시스템·데이터 정의의 room_revision·공용 이벤트·재연결 원칙, M1.2 화면 상태·이벤트 계약, doc/7. 대국방 기반 구축/04_실시간_대국방과_메시지_기반.md를 읽어줘.

목표는 두 브라우저가 같은 방의 멤버·입장 상태·공용 메시지 순서를 room_revision 기준으로 일관되게 확인하도록 만드는 것이다.

1. 대국방 초기 스냅샷·초대 대기 화면을 구현하고, 상대 입장 이벤트 뒤 두 화면을 active 대국방으로 갱신한다.
2. Supabase Realtime Broadcast 채널을 멤버만 구독하게 연결하고 room.member_joined·message.sent payload를 계약대로 제한한다.
3. 공용 메시지 저장·조회·순서 반영 기반을 구현한다. M2에서는 사용자 직접 전송 버튼을 노출하지 않으며, 테스트는 서버 호출 또는 테스트 코드로만 메시지를 만든다.
4. 마지막 room_revision 이후 변경 조회, 단절 시 스냅샷 교체, 30초 복구, 실패 뒤 읽기 전용·수동 재시도·메인 복귀를 구현한다.
5. 두 브라우저·늦은 입장·연결 단절에서 중복·역전 없이 같은 상태를 확인한다.

private_revision, 초안, AI 분석, 원문·추천 전송 선택은 M3 범위다. 공용 이벤트에 내부 user.id·비공개 초안·AI 결과를 넣지 마. 결과를 페이즈 문서·개발일지에 기록하고 main에 커밋·푸시해줘.
```

## 05. 통합 검증과 M3 인계

```text
이 저장소의 M2 대국방 기반 구축 페이즈 5를 진행해줘.

먼저 AGENTS.md, doc/2_마일스톤_계획.md의 M2 완료 기준, MVP 명세, 시스템·데이터 정의, M1.2 화면 상태·이벤트 계약, doc/7. 대국방 기반 구축/README.md, doc/7. 대국방 기반 구축/05_통합_검증과_M3_인계.md를 읽어줘.

목표는 두 브라우저 대국방 연결·권한·실시간 동기화의 M2 완료 기준을 검증하고, M3 AI 심판 구현에 필요한 경계를 명확히 인계하는 것이다.

1. 이메일·비밀번호·카카오·구글 로그인, 미로그인 링크 로그인·복귀, 링크·코드 수락, 대기·상대 입장, 두 브라우저 동기화를 검증한다.
2. 초대 4개 실패 사유, 제3 사용자 권한 차단, 진행 중 방 충돌, 재연결 30초 복구·수동 재시도를 검증한다.
3. 로컬 Supabase·Vercel에서 환경 변수 누락 안내와 비밀값 비노출을 확인한다.
4. 테스트용 메시지 생성 경로가 제품 UI에 노출되지 않았음을 확인하고, M3에서 message.send에 AI 분석·원문 해시·전송 선택 검증을 추가할 위치를 기록한다.
5. doc/3. 검증보고서/M2_대국방_기반_구축/에 검증보고서를 만들고 범위·결과·근거·미검증·위험·완료 판정을 기록한다.
6. 모든 완료 조건이 충족될 때만 M2 상태를 완료로 바꾸고 AGENTS.md·마일스톤 계획·M2 README를 갱신한다.

기준에 없는 정책을 새로 정하지 말고, 미충족이면 완료로 표시하지 말고 보완 계획 또는 결정 필요 항목을 남겨줘. 변경 파일을 main에 커밋·푸시해줘.
```
