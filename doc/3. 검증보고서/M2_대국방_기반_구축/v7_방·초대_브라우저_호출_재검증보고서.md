# M2 대국방 기반 구축 — v7 방·초대 브라우저 호출 재검증보고서

> 상태: 부분 검증 · 2026-09-20

## 검증 범위

- M2 페이즈 3 방 생성·초대 수락 Edge Function의 브라우저 CORS 사전 요청 호환성
- 요청 전 JWT 검사 해제 뒤 실제 상태 변경 요청의 함수 내부 인증 경계
- 원격 함수 배포와 프로젝트 설정 반영 여부

## 수행 결과

| 확인 항목 | 방법 | 결과 | 근거 |
| --- | --- | --- | --- |
| 함수 정적 검사 | `deno check`로 `room-create`, `invite-accept` 검사 | 통과 | 두 함수 모두 오류 없음 |
| 웹 회귀 검사 | `web`에서 `npm run lint`, `npm run build` 실행 | 통과 | lint·production build 성공 |
| 운영 함수·설정 반영 | 두 함수를 운영 Supabase에 재배포하고 함수 설정을 다시 조회 | 통과 | `room-create`, `invite-accept` 모두 최신 코드 배포 및 `Verify JWT with legacy secret` 꺼짐 확인 |
| `room-create` CORS 사전 요청 | 운영 URL에 `Origin`과 `Access-Control-Request-*` 헤더를 포함한 `OPTIONS` 요청 | 통과 | HTTP `200`, `Access-Control-Allow-Origin: *`, `POST, OPTIONS` 및 허용 헤더 반환 |
| `invite-accept` CORS 사전 요청 | 운영 URL에 동일한 `OPTIONS` 요청 | 통과 | HTTP `200`, 동일한 CORS 헤더 반환 |
| 인증 없는 실제 명령 차단 | 각 운영 함수에 토큰 없이 `POST` 요청 | 통과 | 두 함수 모두 HTTP `401`; 함수 내부 Auth 토큰 검증이 RPC 실행 전 차단 |

## 판정

브라우저의 인증 없는 CORS 사전 요청은 통과하지만, 실제 방 생성·초대 수락 요청은 유효 Supabase 세션 토큰 없이는 실행되지 않는다. 따라서 플랫폼의 요청 전 검사를 끈 설정은 CORS 호환성을 위한 것이며, 방 상태 변경 인증을 제거하지 않는다.

## 미검증 항목과 남은 위험

- 서로 다른 A·B 사용자와 제3 사용자의 실제 로그인 세션으로 방 생성, 링크·6자리 코드 수락, 중복 수락 거절, 비멤버 접근 거절을 아직 실행하지 않았다.
- 페이즈 4의 Realtime 구독·메시지 순서·재연결 복구는 아직 구현 전이다.
