## 검증 범위

- 개인 형세 파악과 양측 수락형 AI 문철의 SQL 상태 전이·공개 범위·화면 연결
- 페이즈 2 P01·P02 보완 여부와 웹 정적 빌드

## 수행 결과

| 항목 | 결과 | 근거 |
| --- | --- | --- |
| 개인 형세 비공개 | 통과 | `private-position`은 멤버·활성 방을 확인하고 `private_position`/`private_analysis_public` 경계로 결과를 저장한다. 방 공용 Broadcast를 만들지 않는다. |
| 문철 수락 전 AI 미호출 | 통과 | 신청 함수는 RPC만 호출하며, OpenAI 요청은 수락자 전용 `room-review-accept`의 `processing` 전환 이후에만 있다. |
| 문철 공용 결과 경계 | 통과 | `room_review_public`은 `is_room_member`를 만족하는 `room_review` 결과만 반환한다. 요청자의 개인 분석·초안은 포함하지 않는다. |
| 두 화면 상태 동기화 | 통과 | 요청 상태 변경 trigger가 기존 멤버 전용 `room:{roomId}` Broadcast로 `room.review_changed`를 전송하고 화면이 스냅샷을 다시 읽는다. |
| 자동 결과 열기 차단 | 통과 | 준비된 문철 결과는 `AI 문철 확인하기` 버튼을 눌러야 바텀시트가 열린다. |
| P01 비공개 순번 | 통과 | `ai-judge`의 ready/failed 결과가 `record_private_change`를 호출한다. |
| P02 구조화 출력 제약 | 통과 | AI 심판 normal은 추천 2~3개·`AI의 추정:` 접두어, restricted는 추천 0개를 JSON Schema로 강제한다. |
| 웹 정적 검증 | 통과 | `web`에서 `npm run lint`, `npm run build` 통과. |
| 로컬 마이그레이션·DB 스키마 검사 | 통과 | `supabase migration up --local`로 `20260920000100`~`20260920001300`을 적용하고, `supabase db lint --local`을 통과했다. 이 과정에서 기존 전송 RPC의 `digest` 스키마 누락·`sequence` 모호성도 `01200`·`01300`으로 보완했다. |

## 미검증 항목과 남은 위험

- 원격 Supabase에 `20260920000700`~`20260920001100` 마이그레이션과 `private-position`, `room-review-request`, `room-review-accept` Edge Function이 아직 배포됐는지 이 환경에서는 확인하지 못했다.
- 실제 `OPENAI_API_KEY`로 Structured Outputs가 각 스키마를 반환하는지, AI 실패 후 재시도 UX가 충분한지는 A/B 수동 검증이 필요하다.
- 제3 계정 차단, A 개인 형세의 B 비노출, 문철 신청·수락 처리 상태와 공용 결과 일치를 원격 환경에서 확인해야 한다.

## 판정

페이즈 3의 코드·문서·정적 검증은 완료했다. 원격 배포와 A/B 수동 시나리오를 통과하기 전에는 M3 전체 완료로 전환하지 않는다.
