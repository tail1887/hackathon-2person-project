# M3 AI 대화 경험 구축 — v5 AI 호출 실패 진단보고서

> 상태: OpenAI 요청 단계 실패 확인 · 안전한 실패 코드 배포 완료 · 재호출 결과 대기 · 2026-09-21

## 검증 범위

- 운영 `ai_analyses` 기록을 통한 AI 심판·개인 형세·AI 문철 실제 호출 결과
- 실패 원인을 노출하지 않으면서 구분 가능한 운영 진단 정보

## 수행 결과

| 항목 | 결과 | 근거 |
| --- | --- | --- |
| 실제 AI 호출 | 실패 확인 | 운영 `ai_analyses`에 `message_mediation` 4건, `private_position` 1건, `room_review` 1건이 모두 `failed`로 기록됐다. |
| 실패 위치 | OpenAI 요청 단계 | 각 기록은 초안·분석 레코드 생성 뒤 0.3~0.6초 안에 실패했다. 함수의 기존 처리 방식상 이 경로는 OpenAI HTTP 응답 또는 구조화 결과 검증 실패다. |
| 기존 진단 정보 | 부족 | 기존 함수가 외부 응답 상태를 공통 오류 문구로만 반환·저장해 인증·모델·한도·형식 오류를 구분할 수 없었다. |
| 보완 배포 | 완료 | AI 심판·개인 형세·문철 수락·문철 재시도 함수가 실패 시 안전한 `failure_code`만 비공개 분석 기록에 남기고, 운영 로그에도 코드만 기록하도록 재배포됐다. 키·입력 본문·외부 오류 본문은 기록하지 않는다. |

## 판정

AI 기능의 배포·함수 연결은 되어 있으나, 현재 운영 OpenAI 호출은 정상 동작하지 않는다. 키 자체가 존재한다는 사실은 API 인증, 선택 모델 접근 권한 또는 사용 한도를 보장하지 않는다. 재호출 뒤 기록되는 `failure_code`를 근거로 다음 조치를 확정해야 한다.

## 다음 확인

1. 로그인한 방 멤버가 초안을 입력하고 `확인`을 한 번 실행한다.
2. `ai_analyses.result.failure_code`를 확인한다.
3. `openai_http_401`이면 키 교체, `openai_http_404` 또는 `400`이면 모델·요청 계약 보완, `429`이면 사용 한도·결제 상태를 확인한다.
