# M3 AI 대화 경험 구축 — v4 원격 배포 검증보고서

> 상태: 원격 스키마·함수 배포 통과 · 실제 A/B 시나리오 미검증 · 2026-09-21

## 검증 범위

- 운영 Supabase 프로젝트의 M2·M3 마이그레이션 적용 상태
- M3 Edge Function 7개의 배포·활성 상태와 CORS 사전 요청
- 운영 Edge Function 환경의 `OPENAI_API_KEY` 비밀값 존재 여부

## 수행 결과

| 항목 | 결과 | 근거 |
| --- | --- | --- |
| 원격 마이그레이션 | 통과 | CLI 연결 후 `supabase migration list --linked`에서 `20260920000100`부터 `20260920001400`까지 로컬·원격 버전이 모두 일치했다. 기존 M2 스키마는 이력으로 등록했고, `006`~`014`를 원격에 적용했다. |
| M3 Edge Function 배포 | 통과 | `ai-judge`, `message-send`, `private-position`, `room-review-request`, `room-review-accept`, `room-review-retry`, `room-review-cancel`이 모두 `ACTIVE`이며 JWT 사전 검증 해제 상태로 확인됐다. 각 함수는 내부 인증·권한 검증을 수행한다. |
| AI 비밀값 | 통과 | 운영 비밀값 목록에서 `OPENAI_API_KEY`의 존재만 확인했다. 값 자체는 조회·기록하지 않았다. |
| 브라우저 사전 요청 | 통과 | 위 7개 함수의 운영 URL에 대한 `OPTIONS` 요청이 각각 HTTP `200`을 반환했다. |
| 실제 AI 호출·A/B/제3 계정 권한 | 미검증 | 로그인 세션과 서로 다른 사용자 계정이 필요한 흐름이다. 이 배포 검증에서는 실행하지 않았다. |

## 판정

운영 Supabase는 M3 코드가 요구하는 스키마와 Edge Function을 갖췄고, AI 키와 브라우저 호출의 기본 경계도 준비됐다. 다만 실제 OpenAI 응답·메시지 확정·개인 결과 비노출·문철 수락/실패 재시도는 사용자 세션으로 검증하지 않았으므로 M3 전체 완료 판정은 보류한다.

## 다음 확인 순서

1. A의 normal 심판 뒤 원문·추천문 전송과 B의 비공개 정보 비노출을 확인한다.
2. stale·restricted·종료 방·제3 계정의 전송/조회 거절을 확인한다.
3. A의 개인 형세 파악이 B에게 노출되지 않는지 확인한다.
4. A 문철 신청 → B 수락 → 양측 공용 결과, 실패 시 A만 한 번 재시도·취소 가능한지를 확인한다.
