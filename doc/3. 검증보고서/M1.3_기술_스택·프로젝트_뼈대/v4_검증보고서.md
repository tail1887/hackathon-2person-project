# M1.3 기술 스택·프로젝트 뼈대 — v4 검증보고서

> 상태: 완료 · 2026-09-20

## 검증 범위

- M1.3 페이즈 4의 마지막 미충족 항목인 로컬 Supabase 기동과 서비스 헬스 체크
- 로컬 웹 앱의 린트·프로덕션 빌드, Vercel Git 자동 배포·공개 접근을 포함한 M1.3 완료 조건

## 수행한 확인과 결과

| 확인 | 결과 | 근거 |
| --- | --- | --- |
| 로컬 웹 앱 | 충족 | `web`에서 `npm run lint`와 `npm run build`가 통과했다. |
| Docker·로컬 Supabase | 충족 | Docker Engine 29.4.0 환경에서 이미지 초기 내려받기와 이전 실패 시도 컨테이너 정리 뒤 `supabase start`·`supabase status`가 성공했다. DB·Auth·Realtime·REST·Studio 등 필요한 컨테이너가 정상 상태다. |
| 로컬 API·함수 준비 상태 | 충족 | REST 엔드포인트와 Functions 내부 헬스 엔드포인트가 각각 HTTP `200`을 반환했다. |
| Vercel Git 자동 배포 | 충족 | GitHub `main` 커밋 `878ac0d`가 새 Production 배포를 자동 생성했고 상태가 `Ready`가 됐다. |
| 공개 배포 접근 | 충족 | Vercel Authentication을 해제한 Production URL의 비로그인 HTTP 요청이 `200`을 반환했다. |
| 비밀값 경계 | 충족 | 저장소에는 비밀키가 없으며, 로컬 실행값·공개 연결값·서버 전용 비밀값의 경계는 환경 변수 예시와 프로젝트 뼈대 문서에 분리돼 있다. |

## 확인하지 않은 범위와 다음 단계

- 원격 Supabase 프로젝트 연결, 카카오·구글 OAuth, Realtime 권한·RLS, Edge Function·OpenAI 호출은 실제 기능이 추가되는 M2 이후에 검증한다.
- 로컬 Supabase 출력에는 개발용 키가 포함될 수 있으므로, 출력 전체를 문서·커밋·대화에 복사하지 않는다.

## 완료 판정

M1.3의 기술 선택·프로젝트 뼈대·로컬 및 배포 기본 기동 조건을 모두 충족했다. **M1.3을 완료**하며, 다음 마일스톤은 M2 대국방 기반 구축이다.
