# M1.3 기술 스택·프로젝트 뼈대 — v2 검증보고서

> 상태: 페이즈 4 부분 검증 · M1.3 완료 보류 · 2026-09-19

## 검증 범위

- v1 이후 페이즈 4의 로컬 실행, Docker·Supabase 로컬 기동, Vercel 배포·Git 연결 상태
- M1.3 완료 조건의 실제 충족 여부

## 수행한 확인과 결과

| 확인 | 결과 | 근거 |
| --- | --- | --- |
| 로컬 웹 앱 | 충족 | `npm run lint`·`npm run build` 통과 뒤 개발 서버의 `GET /`가 `200`을 반환했고 제품 제목과 뼈대 안내를 확인했다. |
| Docker 준비 | 충족 | Docker Desktop 시작 뒤 Engine 29.4.0 응답을 확인했다. 기존 컨테이너·프로젝트는 변경하지 않았다. |
| 로컬 Supabase 기동 | 미충족 | `supabase start`, `--debug`, `--agent no` 모두 전역 프로필 파일 읽기 오류로 컨테이너 생성 전 실패했다. |
| Vercel 빌드·배포 | 충족 | `web/` Root Directory를 감지해 Production 배포를 생성했고, Vercel 상태는 `Ready`, Next.js 빌드는 성공했다. [배포 기록](../../6.%20기술%20스택·프로젝트%20뼈대/04_실행과_배포_기본_검증.md) |
| Vercel Git 미리보기 | 미충족 | GitHub Login Connection 부재로 저장소 연결이 실패했다. 이후 `main` 푸시가 자동 배포되는지 확인하지 못했다. |
| 비로그인 배포 응답 | 미충족 | 배포 URL은 팀 SSO 로그인으로 302 이동한다. 앱 빌드 성공과 공개 접근 성공은 구분한다. |
| 비밀값 경계 | 충족 | API 키·service role 값은 추적 파일에 없고, 로컬·배포 비밀값 예시와 공개 연결값이 분리돼 있다. |

## 남은 위험과 재검증 조건

- Vercel GitHub 연결 뒤 `main` 푸시 또는 Preview 브랜치 배포가 자동 생성되는지 확인한다.
- 데모를 비로그인 사용자에게 보여 줄 필요가 있으면 Deployment Protection 변경을 팀이 결정한 뒤 실제 URL의 `200` 응답을 재검증한다.
- Supabase CLI 프로필 오류가 해결되면 `supabase start`, `supabase status`, 초기 마이그레이션 적용을 확인한다.
- OAuth·Realtime·RLS·Edge Function·OpenAI 호출은 M2 이후 실제 기능 단위에서 검증한다.

## 완료 판정

- M1.3은 **완료 보류**다. 실제 배포 생성은 성공했지만, 페이즈 4의 로컬 Supabase와 Git 연동·접근 경로 검증이 남았다.
- 제품 기능 구현은 시작하지 않았으며, M2의 선행 구조만 준비된 상태다.
