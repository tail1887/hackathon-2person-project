# M1.2 인터페이스 설계 — v2 검증보고서

> 상태: 페이즈 1.5 인터랙티브 목업 검증 완료 · M1.2 전체 완료 전 · 2026-09-19

## 1. 검증 범위

- **검증 대상**: M1.2 페이즈 1.5 인터랙티브 목업 ([`mockup/index.html`](../../mockup/index.html)) 및 관련 흐름 검증
- **주요 검증 항목**:
  1. 로그인 뒤 메인의 미션 우선 표시 및 대국 목록(진행 중 1개 / 지난 대국 읽기 전용)
  2. 진행 중 대국 없을 때 대국 시작하기 → 방 만들기 또는 6자리 초대 코드 입장
  3. 대국방 메시지 초안 입력 → `[확인]` → 필수 AI 심판 시트 (Normal 원문/추천 전송 vs Restricted 전송 불가)
  4. 개인 형세 파악(요청자 비공개) vs 함께 보는 AI 문철(공용 요약)
  5. 조건부 무승부 협상 4개 분기 (단일/복수 조건 수락, 조건 0개 수락, 카운터오퍼 메시지, 계속 대국)
  6. 합의 후 대국 종료(`closed`) & 지난 대국 보관 & 선택 조건 미션 생성 & 미션 상태 이동(완료 요청/상대 확인)
- **범위 밖**: 페이즈 2 상세 화면 상태(로딩·오류·재연결), 페이즈 3 API/이벤트 계약 필드, 실제 DB/인증/AI 연동

## 4. 미검증 항목과 남은 위험

- 네트워크 오류, 타임아웃, AI 분석 지연 중 로딩 스피너 및 빈 상태 디자인은 페이즈 2([`02_화면_상태_설계.md`](../../5.%20인터페이스%20설계/README.md#02-화면-상태-설계))에서 정의하고 검증할 예정이다.
- REST API 경로, WebSocket/SSE 이벤트 payload 구조, revision 기반 동기화는 페이즈 3([`03_요청_응답_실시간_이벤트_계약.md`](../../5.%20인터페이스%20설계/README.md#03-요청-응답-실시간-이벤트-계약))에서 정의하고 검증한다.
- 따라서 M1.2 인터페이스 설계 마일스톤은 아직 페이즈 2·3이 남아있으므로 전체 `완료`로 변경하지 않고, 페이즈 1.5 진행 상태로 관리한다.
