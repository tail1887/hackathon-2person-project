# 보완 계획

이 폴더는 검증보고서에서 확인한 보완 필요 항목의 문제 분석, 권장 보완안, 재검증 기준을 관리한다.

## 파일 규칙

- 보완계획은 작성 날짜의 `YYYY-MM-DD/` 폴더에 둔다.
- 파일명은 날짜 폴더 안에서 만든 순서대로 `1_Pxx_문제명_보완계획.md` 또는 `1_Rxx_문제명_보완계획.md`로 쓴다. 순번은 날짜 폴더마다 `1`부터 시작한다.
- 계획 단계 문서에는 `상태: 제안`을 표시하고, 확정 전에는 기준 문서의 정책으로 취급하지 않는다.
- 확정된 보완안은 의사결정 로그와 관련 기획·MVP·시스템 문서에 반영한 뒤 검증보고서를 갱신한다.
- 검증보고서의 Pxx 또는 Rxx 해당 항목과 보완계획 문서는 서로 상대 링크로 연결한다.

## 작성 양식

각 보완계획은 아래 순서로 작성한다.

1. 목적과 범위
2. 현재 문제 분석
3. 보완 목표와 원칙
4. 권장 보완안
5. 대안과 권장 이유
6. 재검증 시나리오와 완료 기준
7. 후속 구현에서 정할 항목
8. 근거 문서

계획은 문제를 해결할 수 있는 권장 방향과 아직 결정하지 않은 항목을 구분해 쓴다. 확정 뒤에만 기준 문서와 의사결정 로그를 갱신한다.
