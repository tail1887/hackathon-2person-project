### 1. AI 심판 `restricted` 정책의 화면 설계 일치 확인

- 배경: `safety_guidance`와 별도 안전 안내 흐름은 폐기됐으며, 위험 입력에는 AI가 `restricted`만 반환하는 정책이 확정됐다. 페이즈 1 와이어프레임·MVP 명세·시스템 정의는 이 정책을 반영했지만, 페이즈 2 작업 안내에는 이전 표현이 남아 있었다.
- 논의할 질문: 현재 화면 흐름의 `restricted` 행동(전송·추천·협상 조건 생성 불가, 초안 수정 후 재확인)이 팀의 의도와 일치하는가?
- 현재 확인: 인터페이스 설계 README의 페이즈 2 안내를 `restricted` 기준으로 최신화했다. 옛 기획서와 초기 검증보고서의 이전 용어는 당시 이력으로 보존한다.
- 결정 시 반영 문서: 필요 시 `doc/1_MVP_명세.md`, `doc/3_시스템_데이터_정의.md`, `doc/5. 인터페이스 설계/01_화면_흐름과_와이어프레임.md`; 작업 안내는 `doc/5. 인터페이스 설계/README.md`
- 상태: 확인 필요

### 2. M1.2 페이즈 2·3과 인터랙티브 목업의 진행 순서

- 배경: 페이즈 1에서 화면 이동과 텍스트 와이어프레임을 작성했다. 페이즈 2는 화면별 정상·로딩·오류·재연결·복구 행동을, 페이즈 3은 요청·응답·공용·비공개 이벤트 계약을 정의한다.
- 논의할 질문: 목데이터 기반 인터랙티브 목업을 언제 만들고, 어느 화면·상태까지 검증 대상으로 둘 것인가?
- 현재 제안: 페이즈 1을 기준으로 정상 흐름과 핵심 분기만 가진 얇은 목업을 먼저 만들고, 이를 보며 페이즈 2의 화면 상태를 정의한다. 이어서 페이즈 3에서 명령·조회·이벤트 계약과 상태·시퀀스 다이어그램을 확정한다. 목업은 확정 정책을 검증하는 도구이며 새 정책을 임의로 정하지 않는다.
- 결정 시 반영 문서: `doc/5. 인터페이스 설계/01_화면_흐름과_와이어프레임.md`, 이후 `02_화면_상태_설계.md`, `03_요청_응답_실시간_이벤트_계약.md`, M1.3 기술 선택·프로젝트 뼈대 문서
- 상태: 논의 전

### 3. 페이즈 1의 결정 필요 항목 확인

- 배경: 조건 0개 무승부 제안은 선택 UI 없이 수락하고, 미션 없이 대국방으로 돌아가는 흐름으로 확정했다. 페이즈 1 문서에는 진행 중인 방 사용자의 로그인 직후 경로와 미션 보드의 진입 형태가 `결정 필요`로 남아 있다.
- 논의할 질문: 남은 두 항목은 이미 팀에서 결론을 냈는가? 결론이 있다면 어떤 사용자 경험으로 확정할 것인가?
- 현재 제안: 결론이 난 항목은 의사결정 로그와 상위 기준 문서부터 반영한 뒤 페이즈 1의 상태를 `확정`으로 갱신한다. 결론이 없는 항목은 목업의 명시적 가정으로만 표시하고 페이즈 2·3의 정책 근거로 사용하지 않는다.
- 결정 시 반영 문서: `doc/1. 의사결정 로그/`, `doc/0_커플들이_집착하는_AI_심판이_되었다_기획서.md`, `doc/1_MVP_명세.md`, `doc/3_시스템_데이터_정의.md`, `doc/5. 인터페이스 설계/01_화면_흐름과_와이어프레임.md`
- 상태: 일부 확인 완료 — 조건 0개 무승부 제안의 수락 화면은 확정했으며, 두 항목은 확인이 필요하다.
