# 커플들이 집착하는 AI 심판이 되었다 — MVP 명세

> 이 문서는 해커톤에서 실제로 구현·시연할 최소 경험의 기준이다. 서비스 전체 방향과 확장 기능은 [기획서](0_커플들이_집착하는_AI_심판이_되었다_기획서.md)를 따른다.
>
> **상태: 팀 확인 완료 · 2026-09-16**

---

## 1. MVP 목표

로그인한 두 사용자가 초대 링크 또는 코드로 하나의 대국방에 연결되어 갈등 메시지를 주고받고, AI 도움을 거쳐 조건부 무승부에 합의한 뒤, 각자에게 생성된 회복 미션을 상호 확인까지 완료한다.

### 데모 성공 조건

다음 흐름을 끊김 없이 시연할 수 있다.

```text
A가 대국방 생성
→ B가 초대 링크/코드로 입장
→ A가 날선 메시지 초안 작성
→ AI 훈수 확인 후 원문 또는 대안 문장 전송
→ A의 개인 형세 파악
→ A와 B의 AI 문철
→ A의 조건부 무승부 제안
→ B의 카운터오퍼, A의 수락
→ 개인/공동 미션 생성
→ 수행 완료 및 상대 확인
```

### 범위 원칙

- 한 대국방에는 사용자 두 명만 참여한다.
- 진행 중인 대국은 로그인 계정당 한 개만 지원한다.
- 기한은 오늘 또는 내일만 선택할 수 있다.
- AI는 조언·요약·문장 대안을 제공할 뿐, 누가 옳은지 판결하거나 관계를 대신 결정하지 않는다.

## 2. 사용자와 권한


| 역할       | 할 수 있는 일                          | 볼 수 있는 정보               |
| -------- | --------------------------------- | ----------------------- |
| 로그인 사용자 | 대국방 생성, 초대 수락, 본인 미션 재진입 | 본인이 속한 대국 메시지·합의·미션 |
| 방 생성자    | 대국방 생성, 초대 링크/코드 공유, 메시지·제안·미션 처리 | 본인과 상대의 대국 메시지·합의·미션    |
| 초대받은 사용자 | 초대 링크/코드로 입장, 메시지·제안·미션 처리        | 본인과 방 생성자의 대국 메시지·합의·미션 |
| AI       | 메시지 초안 분석, 대안 문장·형세·미션 문구 생성      | 해당 대국방의 필요한 대화 맥락       |


**권한 원칙:** 대국방 밖의 사용자는 메시지·미션·AI 분석 결과를 볼 수 없다. 합의된 개인 미션은 양쪽이 보며, 제안자가 조건별로 지정한 책임 주체만 수행 처리할 수 있다. 개인 미션 수행 사진은 수행자와 상대 확인자가, 공동 퀘스트 수행 사진은 두 참여자가 확인 근거로 볼 수 있다.

## 3. 화면별 명세



### 3.1 시작·대국방 연결


| 항목    | 명세                             |
| ----- | ------------------------------ |
| 목적    | 두 사용자가 같은 대국방에 입장한다.           |
| 진입    | 미로그인 앱 첫 화면 또는 초대 링크, 로그인 후 시작 화면             |
| 입력    | 로그인 뒤 메인의 `대국 시작하기`, 초대 코드, 대국·미션 카드      |
| 출력    | 미션 목록, 진행 중·지난 대국 목록, 대국방 진입 버튼  |
| 완료 조건 | 두 사람이 대국방에 입장하면 채팅 가능한 상태가 된다. |


**동작 규칙**

1. 대국방 생성과 초대 수락은 로그인한 사용자만 할 수 있다.
2. 인증 전 앱 첫 화면과 미로그인 초대 링크 진입 화면에는 로그인·회원가입만 둔다. 초대 코드 입력, 방 생성, 초대 정보 조회는 인증 전 제공하지 않는다.
3. 로그인 뒤 메인은 미션을 먼저, 대국 목록을 다음에 표시한다. 진행 중인 대국은 `진행 중` 라벨과 강조 색으로 최상단에, 지난 대국은 `종료됨` 라벨로 그 아래에 둔다.
4. 대국이 없을 때 `대국 시작하기`를 누르면 `대국방 만들기`와 `초대 코드로 입장`을 선택한다. 진행 중인 대국이 있으면 새 방 생성·코드 입장은 제공하지 않는다.
5. 미로그인 사용자가 초대 링크를 열면 초대 유효성·방·참가자·대화 정보를 확인하지 않고 로그인·회원가입 화면으로 이동한다. 인증 성공 뒤에는 원래 링크로 돌아가 서버가 초대 유효성·빈자리·사용자의 진행 중인 다른 방 여부를 확인한다.
6. 이메일·비밀번호 회원가입 성공 시에는 자동 로그인하고, 간편 로그인 성공 시에도 같은 인증 세션으로 이어진다.
7. 로그인한 사용자가 초대 코드로 입장하거나, 인증 뒤 초대 링크를 다시 열면 서버가 초대 유효성·빈자리·사용자의 진행 중인 다른 방 여부를 확인한다. 모두 통과하면 멤버 생성·초대 사용·방 활성화를 함께 확정하고 대국방으로 이동한다. 초대가 만료됐거나 방이 찼다면 입장하지 않고 안내를 표시한다.
8. 상대가 코드 또는 링크로 입장하면 양쪽에 `상대가 입장했습니다` 상태를 표시한다.
9. 이미 두 명이 입장한 방에는 추가 입장을 허용하지 않는다.



### 3.2 대국방


| 항목    | 명세                                            |
| ----- | --------------------------------------------- |
| 목적    | 갈등 대화를 주고받고, AI 개입과 무승부 협상으로 진입한다.            |
| 입력    | 메시지 초안, `확인`, `초안 수정`, `형세 파악`, `AI 문철`, `무승부 제안`                |
| 출력    | 시간순 메시지, 상대 입장 상태, 진행 중인 제안·미션 요약             |
| 완료 조건 | 메시지가 양쪽 화면에 같은 순서로 표시되고, AI·협상 기능으로 진입할 수 있다. |


**동작 규칙**

- 사용자는 메시지 초안을 작성한 뒤 `확인`을 누른다. 확인은 항상 AI 심판 시트를 연다.
- AI 심판 결과를 본 뒤에만 `원문 전송` 또는 `추천 메시지 전송`을 선택할 수 있다. 시트를 건너뛰어 바로 전송할 수 없다.
- 사용자는 AI 심판 시트에서 `초안 수정`을 선택해 작성창으로 돌아갈 수 있다. 수정한 초안은 다시 `확인`해 새 AI 심판 결과를 받아야 하며, 수정 전 분석 결과로는 전송할 수 없다.
- `형세 파악`은 대국방의 별도 버튼으로 언제든 요청할 수 있으며, 요청자만 결과를 본다.
- `AI 문철 신청하기`는 대국방의 별도 버튼으로 연다. 신청자는 자신의 동의를 표시하며, 상대에게 `AI 문철을 신청했습니다. 동의하시겠습니까?` 안내와 수락 버튼을 보여 준다. 상대가 수락하기 전에는 AI 문철을 생성하지 않는다.
- 상대가 수락하면 두 멤버에게 공용 로딩 상태를 보인다. 생성이 끝나면 결과는 두 멤버가 함께 확인한다.
- 문철이 준비된 뒤 대국방의 문철 버튼은 `AI 문철 확인하기`로 현재 결과를 연다. 새 문철은 현재 결과 하단의 `새 AI 문철 신청하기`에서만 시작하며, 이전 문철은 `문철 기록`에서 읽기 전용으로 확인한다.
- 새 문철이 로딩되는 동안에는 문철 확인·신청 버튼을 비활성화한다. 준비가 끝나면 두 멤버에게 완료 알림을 보여 주되, 결과는 자동으로 열지 않는다.
- 진행 중인 무승부 제안이 있을 때는 대국방 상단에 상태를 고정 표시한다.



### 3.3 AI 심판 시트


| 항목    | 명세                                            |
| ----- | --------------------------------------------- |
| 목적    | 날선 초안을 더 전달 가능한 문장으로 선택할 수 있게 한다.             |
| 입력    | 작성 중인 초안                |
| 출력    | 이 수의 위험, 숨은 감정(추정), 대안 문장 2~3개                |
| 완료 조건 | 사용자가 원문 또는 대안 문장을 고르거나, 초안을 수정한 뒤 다시 AI 심판을 거쳐 대국방에 전송한다. |


**출력 규칙**

- 모든 감정·의도 해석에는 `AI의 추정`을 붙인다.
- 대안 문장은 비난·단정 대신 관찰, 감정, 요청을 포함한다.
- 폭력·협박·통제·자해 위험 표현에는 AI 프롬프트가 `restricted` 결과만 반환하며, 추천·재작성·협상 조건을 만들지 않는다. 화면은 `이 문장에는 AI 심판을 제공할 수 없습니다. 문장을 수정해 다시 확인해 주세요.`만 표시한다.
- 작성 중인 초안은 작성자 계정에 비공개로 저장해 기기를 바꿔도 이어 쓸 수 있다.
- 같은 계정으로 두 기기에서 같은 초안을 수정하다 충돌하면, 최신 서버 초안을 보호하고 로컬 입력은 지우지 않는다. 사용자는 `최신 초안 사용`, `내 변경 적용`, `직접 편집` 중 하나로 해결한다. 입력 중 다른 기기의 변경이 도착해도 작성창을 자동으로 바꾸지 않는다.
- 메시지를 전송한 뒤에는 작성자만 해당 메시지의 `내 초안과 AI 심판 보기`를 펼쳐 원문 초안·AI 심판 결과를 확인할 수 있다. 상대에게는 전송된 메시지 본문만 보인다.
- 작성자는 전송 뒤 개인 기록을 삭제할 수 있다. 삭제하면 원문 초안·AI 심판 결과만 사라지고, 상대에게 전송된 메시지 본문은 유지된다.



### 3.4 형세 파악 — 개인 확인

| 항목    | 명세                                             |
| ----- | ---------------------------------------------- |
| 목적    | 요청자가 현재 형세와 다음 대화 판단을 혼자 정리한다.                |
| 입력    | 최근 대화 맥락, `형세 파악` 요청                           |
| 출력    | 현재 형세, 내가 확인할 쟁점, `AI의 추정`, 다음 판단 |
| 완료 조건 | 요청자만 결과를 확인하고 대국방으로 돌아간다.                |

**표현·공개 규칙**

- 형세는 `난타전`, `교착`, `회복 가능`처럼 대화 상태로 표현한다.
- 감정·의도 해석에는 `AI의 추정`을 붙인다.
- 결과와 요청 여부는 상대에게 표시하거나 알리지 않는다.

### 3.4.1 AI 문철 — 함께 읽는 대화 보드


| 항목    | 명세                                             |
| ----- | ---------------------------------------------- |
| 목적    | 두 사람이 같은 대화를 다시 읽고 서로 다른 지점과 다음 행동을 함께 고르게 한다.          |
| 입력    | 최근 대화 맥락, 한 멤버의 `AI 문철 신청하기`, 상대의 수락 |
| 출력    | 함께 확인할 대화 요약, 서로 다른 지점, `AI의 추정`인 바람과 걱정, 다음 수 제안 |
| 완료 조건 | 상대 수락 뒤 두 멤버가 공용 로딩을 거쳐 결과를 함께 확인하고, 대국방으로 돌아가거나 무승부 제안으로 이동한다.                |


**표현 규칙**

- 대화 요약은 확정 메시지에서 드러난 말과 사건만 정리한다.
- 서로 다른 지점은 각자가 중요하게 말한 기준이나 요청의 차이로 표현하며, 누가 잘못했는지 점수·승패·관계 상태로 판정하지 않는다.
- 바람과 걱정 같은 감정·의도 해석에는 `AI의 추정`을 붙인다.
- 다음 수는 먼저 확인할 질문, 작은 약속, 잠시 쉬고 다시 이야기하기처럼 선택 가능한 다음 행동으로 제안한다.
- 결과는 방 공용으로 두 멤버에게 함께 표시한다.
- 신청만으로는 문철 분석을 만들지 않는다. 상대 수락 뒤에만 공용 분석을 생성한다.
- 각 수락된 문철은 당시의 확정 메시지 순번에 연결된 읽기 전용 기록으로 남긴다. 현재 문철 결과 아래에서 새 신청을 시작하면 이후 대화 기준의 새 문철을 만들 수 있다.



### 3.5 무승부 협상


| 항목    | 명세                                     |
| ----- | -------------------------------------- |
| 목적    | 대화를 잠시 끝내는 대신, 실행할 회복 조건을 두 사람이 합의한다.  |
| 진입    | 대국방 또는 AI 문철의 `무승부 제안` 버튼              |
| 입력    | 제안자의 조건 선택지 0개 이상, 조건이 있을 때의 선택 방식(한 개/여러 개), 제안·수락·카운터오퍼 메시지·계속 대국 |
| 출력    | 현재 선택지, 상대의 선택 또는 카운터오퍼 메시지, 합의 여부                 |
| 완료 조건 | 양쪽이 같은 조건을 수락하면 합의가 성립하고, 선택한 조건이 있으면 미션을 생성한다. 조건이 없으면 미션 없이 대국방으로 돌아간다.     |


**상태 전이**

```text
초안 작성 → 제안됨 → 상대 선택 후 수락 → 합의됨 → 미션 생성
                    ├→ 카운터오퍼 메시지 → 제안자 수정 → 새 제안됨
                    └→ 계속 대국 → 종료

조건 0개 제안 → 상대 수락 → 합의됨 → 미션 생성 없음 → 대국방
```

**동작 규칙**

- 제안자는 AI 추천과 직접 입력으로 조건 선택지를 만들고, 각 조건의 책임 주체를 `나`·`상대`·`함께` 중에서 정한다. AI 추천 조건의 기본 책임 주체는 제안자(`나`)지만 수정할 수 있다. 조건이 없으면 선택 방식도 없다.
- 상대는 한 개 선택 제안에서 정확히 하나를, 여러 개 선택 제안에서 하나 이상을 선택한 뒤 수락한다. 선택한 조건만 미션으로 생성한다.
- 조건 0개 제안의 상대 화면에는 선택 UI 대신 `수락` 버튼을 보인다. 상대가 수락하면 합의만 기록하고 미션을 만들지 않으며 대국방으로 돌아간다.
- 제안자가 제안을 보낸 뒤 상대의 선택·수락·계속 대국·카운터오퍼 전까지는 해당 제안을 읽기 전용으로만 보며 수정·재발송할 수 없다. 상대는 제안의 조건·선택 방식을 직접 수정하지 않고, 일반 대화에는 남지 않는 카운터오퍼 요청 메시지만 보낸다. 카운터오퍼가 도착하면 기존 제안 아래에 메시지를 함께 표시하고, 제안자만 그 메시지를 보면서 자신의 제안을 수정해 새 버전으로 다시 제안한다.
- 대국방에는 최신 협상 상태와 필요한 행동만 요약한다. `무승부 협상 기록 보기`에서는 현재 진행 중이거나 가장 최근에 종료된 협상 1건의 제안 버전·카운터오퍼·수락·계속 대국·합의 결과를 시간순 읽기 전용으로 확인한다. 새 협상을 시작하면 이전 협상 기록은 이 진입점에서 교체한다.
- 무승부 제안에는 기한을 입력하거나 표시하지 않는다. 합의 뒤 생성되는 미션의 기한 정책은 제안과 별도로 적용한다.
- 개인 조건은 제안자가 지정한 `나` 또는 `상대`에게 생성한다. `함께`로 지정한 조건은 공동 퀘스트로 만든다. 상대는 카운터오퍼 메시지에서 책임 주체 변경을 요청할 수 있지만, 직접 수정하지는 않는다.
- 합의되기 전에는 어떤 미션도 생성하지 않는다.
- `계속 대국`을 선택하면 제안은 종료하고 메시지 대화로 돌아간다.



### 3.6 미션 보드와 상대 확인


| 항목    | 명세                                    |
| ----- | ------------------------------------- |
| 목적    | 합의 조건을 실행 가능한 개인 미션 또는 공동 퀘스트로 전환한다.  |
| 입력    | 완료 처리, 상대 확인, 다시 요청, 재수행 시작, 미션 포기, 수정 제안·수락·거절·취소 |
| 출력    | 미션 소유자/참여자, 기한, 진행 상태, 상대 확인 상태, 수정 제안과 변경 전·후 값 |
| 완료 조건 | 개인 미션은 상대가 확인하고, 공동 퀘스트는 양쪽이 완료 처리한다. 수정 제안은 양쪽 수락 전 적용되지 않는다. |


**생성 규칙**

- 상대가 선택한 조건은 제안자가 지정한 책임 주체의 개인 미션이다. 예를 들어 `오늘 밥은 내가 사기`는 `나`로 지정한 제안자의 개인 미션이다.
- `같이 산책하기`처럼 양쪽 참여가 필요한 조건은 공동 퀘스트다.
- MVP에서는 텍스트 완료 처리와 상대 확인을 기본으로 한다. 사진 인증은 있으면 데모에서 보여 주는 선택 기능이며, 개인 미션은 수행자와 상대 확인자가, 공동 퀘스트는 두 참여자가 수행 근거로 확인한다.

**상태 전이**

```text
합의됨 → 진행 중 → 완료 요청 → 상대 확인 대기 → 완료
                                  └→ 다시 요청 → 재수행 요청 → 재수행 시작 → 진행 중
진행 중/재수행 요청 → 수정 제안 → 상대 수락 → 수정된 미션으로 진행 중
                              └→ 거절/취소 → 기존 미션 유지
```

**동작 규칙**

- 개인 미션은 수행자만 완료 요청·재수행 시작·포기를 할 수 있고, 상대만 확인·다시 요청할 수 있다.
- 공동 퀘스트는 두 참여자가 각각 완료 처리하면 완료된다. 한 참여자가 포기하면 공동 퀘스트도 포기 상태가 된다.
- 진행 중 또는 재수행 요청 상태에서는 어느 방 멤버나 문구·기한·수행자·개인/공동 유형의 수정 제안을 만들 수 있다. 상대가 수락할 때만 새 미션 버전을 적용하며, 수락 전에는 기존 미션이 유지된다.
- 수정된 미션은 진행 중으로 돌아가며, 이전 완료 요청과 공동 완료 체크인은 새 버전에 적용하지 않는다. 완료 요청·완료·포기 상태에서는 새 수정 제안을 만들 수 없다.

## 7. 인수 기준 체크리스트

- [ ] 초대 링크 또는 코드로 두 사용자가 같은 대국방에 입장한다.
- [ ] 두 화면에서 메시지와 협상 상태가 일관되게 보인다.
- [ ] 초안 메시지에서 `확인`을 누르면 AI 심판이 반드시 열리고, 원문 또는 추천 메시지만 전송할 수 있다.
- [ ] AI 심판에서 초안을 수정하면 이전 분석 결과로 전송할 수 없고, 다시 `확인`해야 한다.
- [ ] 두 기기에서 같은 초안을 수정하면 먼저 저장된 최신 초안을 오래된 자동 저장이 덮어쓰지 않으며, 충돌한 기기의 로컬 입력은 유지된다.
- [ ] 전송된 메시지의 초안과 AI 심판 결과는 작성자만 펼쳐 볼 수 있고, 상대에게는 전송 본문만 보인다.
- [ ] 작성자가 개인 기록을 삭제하면 초안·AI 심판 결과만 사라지고 전송 메시지는 유지된다.
- [ ] 형세 파악이 요청자에게만 현재 형세·쟁점·다음 판단을 `추정`으로 안내한다.
- [ ] AI 문철 신청 뒤 상대가 수락하기 전에는 분석을 생성하지 않고, 수락 뒤 두 멤버에게 공용 로딩과 준비 완료 알림을 보인다. 사용자가 현재 문철을 직접 열고, 결과 하단에서 새 신청을 시작하거나 문철 기록에서 이전 결과를 읽을 수 있다.
- [ ] 한 사용자가 조건 선택지·단수/복수 선택 방식으로 무승부를 제안할 수 있다.
- [ ] 상대가 방식에 맞는 조건을 선택해 수락하거나, 조건을 직접 바꾸지 않는 카운터오퍼 메시지를 보낼 수 있다.
- [ ] 제안자는 상대 응답 전에는 보낸 제안을 수정·재발송할 수 없고, 카운터오퍼 메시지를 받은 뒤에만 새 버전을 만들 수 있으며, 상대의 유효한 선택·수락 전에는 미션이 생성되지 않는다.
- [ ] 현재 협상에는 최신 상태만 표시하고, 제안·카운터오퍼·수락·종료·합의의 전체 이력은 `무승부 협상 기록 보기`에서 읽기 전용으로 확인할 수 있다.
- [ ] 상대가 선택해 합의된 조건이 개인 미션 또는 공동 퀘스트로 생성된다.
- [ ] 완료 요청과 상대 확인을 거쳐 미션을 완료할 수 있다.
- [ ] 위험 표현에서는 프롬프트가 `restricted`를 반환하고, 일반 AI 추천·재작성·협상 조건이 생성되지 않는다.
