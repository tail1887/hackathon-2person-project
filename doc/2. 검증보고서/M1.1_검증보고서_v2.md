## 추가 확인 사항

### R01. 미로그인 초대 검증의 인증 경계

- **결과: 문서상 해소.** 시스템 §2.2·§5와 MVP §3.1이 미로그인 링크·코드 확인을 활성·만료 여부만 반환하는 단계로, 로그인 뒤 수락을 멤버 생성·초대 사용·방 활성화의 일괄 처리 단계로 분리했다. 미로그인 단계에서는 방·참가자·대화 정보를 읽지 못한다.

### R02. 여러 기기에서 초안을 수정할 때의 충돌 처리

- **결과: 문서상 해소.** [R02 보완계획](../3.%20보완%20계획/2026-09-18/4_R02_초안_동시_수정_충돌_보완계획.md)과 시스템 §3.1·§4.2·§6.2가 `expected_revision` 일치 저장, `draft_revision_conflict`, 로컬 미저장 입력 보존, 최신 초안 재조회·명시적 재저장 규칙을 정의한다. 오래된 자동 저장·오프라인 보류 저장·AI 심판 요청은 최신 초안을 바꾸거나 오래된 분석을 만들 수 없다.

## 미검증 항목과 남은 위험

- 실제 코드 실행, 두 브라우저 화면, 인증 제공자 연동, 권한 차단, 동시 입장·합의, AI 안전 분류는 검증하지 않았다. 이번 검토는 설계 문서에 한정한다.
- P07은 선택 사진 기능을 구현할 경우 실제 권한 차단을 재검증한다. R02는 문서상 해소됐지만, 실제 두 기기 충돌·오프라인 재접속 동작은 구현 뒤 재검증해야 한다.
- 초대 만료·재발급, 오늘/내일의 기준 시간대, 조건 0개 합의의 화면 처리는 후속 계약에서 확인해야 한다.
- 개인 기록 삭제의 기능 범위는 정의되어 있으나 실제 보관·완전 삭제 기간은 M1.3 결정 사항이다. 이번 문서 검토로 저장소에서의 삭제를 보장할 수 없다.
- 실제 코드 실행과 저장소별 조건부 갱신 방식은 M1.2·M1.3에서 정하고 검증한다.
